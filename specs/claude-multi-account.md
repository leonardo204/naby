# Claude 멀티 계정과 한도 표시

## 1. 문제

Claude 구독 계정을 여러 개 쓰는 사람이 있다. 개인과 회사, 또는 팀 좌석과 개인 좌석이다. 지금 naby에서 계정을 바꾸려면 브라우저 로그인을 다시 해야 하고, 바꾸고 나면 이전 계정으로 돌아올 때 또 로그인해야 한다.

그리고 지금 남은 사용량을 볼 방법이 없다. 한도에 걸리고 나서야 안다.

## 2. 원칙

1. **naby는 남의 자격증명을 읽지도 쓰지도 않는다.** Claude Code의 자격증명은 Claude Code가 소유한다. naby가 그 저장소에 쓰기 시작하면, 형식이 바뀌거나 쓰기가 중간에 실패했을 때 **사용자가 naby 밖에서도 로그아웃된다.** 우리 앱의 실수로 다른 도구를 망가뜨리지 않는다.
2. **전환은 naby 안에서만 유효하다.** 터미널에서 `claude`를 치면 원래 계정 그대로다. 기계 전체를 바꾸는 것은 이 스펙의 범위가 아니다.
3. **숫자가 없으면 아무것도 그리지 않는다.** 한도는 백엔드가 줄 때만 있다. 없는 것을 추정해서 채우지 않는다. 틀린 잔량은 없는 것보다 나쁘다.
4. **자동 전환은 하지 않는다.** 한도에 닿았을 때 다른 계정으로 자동 failover 하는 것은 한도의 취지를 거스르는 자동화다. 계정을 바꾸는 것은 언제나 사람이 누른다.

## 3. 무엇을 알아냈는가

설계가 이 사실들 위에 서 있으므로 근거를 남긴다. 전부 이 기계에서 실측했거나 CLI 번들에서 확인했다.

### 3.1 설정 디렉터리가 자격증명을 나눈다

Claude Code는 자격증명을 두 저장소에 둔다 — macOS Keychain(`security` 명령)과 평문 파일이다. 선택 규칙은 **Keychain 우선, 실패 시 평문**이고, 한쪽에 쓰기가 성공하면 **반대쪽을 지운다.**

여기서 결정적인 것은 **Keychain 서비스명이 설정 디렉터리에 따라 달라진다**는 점이다. `CLAUDE_CONFIG_DIR`이 설정되면 서비스명 뒤에 그 경로의 해시가 붙고, 평문 파일 경로와 계정 신원 파일(`.claude.json`)도 그 디렉터리 안으로 들어간다.

실측으로 확인했다. 로그인된 기계에서 다른 설정 디렉터리를 주고 `claude auth status`를 물으니 **완전한 로그아웃 상태**로 답했고, 그 디렉터리 안에 신원 파일이 새로 생겼다. 원래 로그인은 그대로였다.

**그래서 전환은 자격증명을 교체하는 일이 아니라 어느 네임스페이스를 볼지 고르는 일이 된다.** 백업도 교체도 롤백도 필요 없다.

### 3.2 설정 디렉터리를 나눠도 naby가 잃을 것이 없다

설정 디렉터리를 나누면 사용자 설정·`CLAUDE.md`·스킬·MCP 정의가 함께 갈린다. 보통은 큰 부작용이지만 naby에게는 아니다. naby는 이미 그 전부를 **의도적으로 차단**하고 자기 스킬을 텍스트로, 자기 커맨드를 엔진 이음매 위에서 펼쳐 넘긴다. MCP도 naby가 직접 관리한다. 격리 비용이 사실상 0인 드문 경우다.

### 3.3 한도는 스트림 이벤트로만 안정적으로 온다

SDK 응답(result) 메시지에는 한도가 **없다.** 한도를 한 번에 조회하는 컨트롤 요청이 따로 있지만, 그 접근 메서드의 이름이 `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`이다. 이름 자체가 계약이 없다는 뜻이므로 제품 경로에 넣지 않는다.

대신 `rate_limit_event`가 SDK 메시지 유니온의 정식 멤버라, naby가 이미 도는 루프에 **그냥 도착한다.** 별도 왕복도 프로세스도 지연도 없다.

### 3.4 한도 이벤트는 퍼센트를 주지 않는 경우가 많다

실제로 받아 본 이벤트다.

```json
{"status":"allowed","resetsAt":1786426200,"rateLimitType":"five_hour",
 "overageStatus":"rejected","overageDisabledReason":"org_level_disabled","isUsingOverage":false}
```

`utilization`이 **아예 없다.** 그래서 **퍼센트 게이지를 이 기능의 약속으로 삼지 않는다.** 확실히 오는 것은 어느 창인지, 언제 리셋되는지, 그리고 한계에 가까운지(`allowed` / `allowed_warning` / `rejected`)다.

이 편이 오히려 낫다. 평소에는 조용하고 **경고가 필요할 때만 말하는** 표시가 된다.

### 3.5 Windows는 모른다

CLI 번들에서 Windows 자격증명 저장소 구현을 찾지 못했다. 저장소는 macOS `security`를 쓰는 것과 평문 파일 둘뿐이므로, Windows에서는 평문 파일일 **가능성이 높다.** 실기로 확인하지 않았으므로 단정하지 않는다.

**이 설계는 그것을 알 필요가 없다.** naby는 설정 디렉터리만 정하고 쓰는 것은 CLI가 한다. 다만 그 플랫폼에서 격리가 성립하는지는 **실행 중에 확인**한다(§5.3).

## 4. 1단계 — 한도 표시

### 4.1 무엇을 보여주는가

- 지금 걸려 있는 창(5시간 / 7일 계열)과 **리셋까지 남은 시간**
- 상태가 경고나 거절이면 그것을 눈에 띄게
- `utilization`이 실제로 왔을 때만 퍼센트를 덧붙인다

값이 없으면 **아무것도 그리지 않는다.** API 키·Bedrock·Vertex에서는 이벤트 자체가 오지 않으므로 저절로 그렇게 된다. "한도 정보 없음" 같은 빈 칩을 만들지 않는다.

### 4.2 어디에 보여주는가

**채팅 헤더 한 곳.** 컨텍스트 게이지 옆이다. 두 지표는 짝이다 — 컨텍스트는 "이 대화가 얼마나 찼나", 한도는 "이 계정이 얼마나 남았나".

설정 화면에는 두지 않는다. 같은 사실을 두 곳에서 말하면 언젠가 둘이 어긋나고, 그때 사용자는 틀린 쪽을 믿는다. 설정 화면에는 계정 신원만 둔다.

### 4.3 배선

셸 클라이언트는 **이미 완성돼 있다.** 상태별 색과 리셋 카운트다운까지 구현돼 있고, 서버가 아무것도 보내지 않아 죽어 있을 뿐이다. 그래서 이 단계는 새 UI를 만드는 일이 아니라 **끊긴 배선을 잇는 일**이다.

- 런타임의 `EngineEvent`에 한도 이벤트를 `result`의 형제로 더한다. SDK 타입을 재수출하지 않고 **필요한 필드만 평면으로 다시 선언한다** — 이 계약은 프로바이더 독립이어야 한다.
- Agent SDK 엔진이 그 메시지를 1급으로 변환한다. 지금은 하네스 관찰 이벤트로 떨어져 **라벨만 남고 내용이 버려진다.**
- 변환은 **순수 함수로 뽑아 export 한다.** 라이브 SDK 없이 픽스처로 검증할 수 있어야 한다. 컨텍스트 창을 같은 이유로 그렇게 만든 선례가 있다.
- 런타임 턴 루프는 **통과만 시킨다.** 저장하지 않고 게이트에 영향을 주지 않는다. 관찰 이벤트와 같은 규칙이다.
- 셸 어댑터가 클라이언트가 기다리는 모양으로 그대로 흘린다.

### 4.4 퍼센트 산술은 한 곳에 둔다

지금 UI가 값에 100을 곱한다. SDK는 이 필드의 스케일을 문서화하지 않았고 실측에서는 값 자체가 오지 않았다. 그래서 **산술을 UI에서 걷어내 정규화 함수 한 곳으로 옮긴다.** 스케일이 확인되면 그 한 곳만 고치면 된다.

## 5. 2단계 — 계정 전환

### 5.1 모양

계정 하나당 설정 디렉터리 하나를 naby 홈 아래에 둔다. 그 안을 채우는 것은 **전부 CLI다.** naby는 디렉터리를 만들고 환경변수를 정할 뿐이다.

- **계정 추가** — 디렉터리를 만들고 그 환경으로 `claude auth login`을 돌린다. 브라우저 흐름은 기존과 같다.
- **계정 선택** — 설정에 계정 id 하나를 저장한다.
- **턴 실행** — SDK 옵션의 환경에 그 디렉터리를 넣는다. ⚠️ SDK 계약상 이 환경은 **병합이 아니라 치환**이다. 기존 환경을 펼쳐 넣지 않으면 `PATH`가 사라져 CLI가 뜨지 않는다.
- **계정 신원** — 그 환경으로 `claude auth status`를 물으면 이메일·조직·구독 종류가 온다. 기존 경로를 그대로 쓴다.
- **계정 삭제** — **먼저** 그 환경으로 `claude auth logout`을 돌리고 **그다음** 디렉터리를 지운다. 순서가 뒤집히면 Keychain 항목을 지울 근거(경로 해시)가 사라져 영원히 남는다.

### 5.2 함께 고쳐야 하는 것

로그인 상태 캐시가 **전역 슬롯 하나**다. 어느 계정을 물어도 같은 자리를 쓰므로, 계정 A를 조회한 직후 B를 물으면 **A의 답이 나온다.** 멀티 계정에서는 그냥 버그다. 캐시를 설정 디렉터리로 키잉한다.

### 5.3 성립하지 않는 플랫폼에서는 숨긴다

계정을 추가한 뒤 그 환경으로 로그인 상태를 물어 확인한다. 격리가 성립하지 않으면 **기능을 숨기고 단일 계정 동작으로 되돌린다.** 동작할 수 없는 선택지를 UI가 제시하지 않는다는 기존 규칙과 같다.

### 5.4 진행 중인 턴이 있으면 전환을 거절한다

이유는 안전이 아니라 **정직성**이다. 환경은 턴이 시작될 때 자식 프로세스에 고정되므로 이미 뜬 턴은 영향을 받지 않는다. 그런데 헤더는 새 계정을 말하는데 진행 중인 답변은 옛 계정의 한도를 쓴다. 그 어긋남을 만들지 않는다.

### 5.5 전환은 전역이고, 활동 로그에 남는다

계정 선택은 세션별이 아니라 **전역**이다. 모델 선택이 스코프별 전역인 것과 같은 자리에 둔다 — 같은 성질의 설정이 두 가지 규칙을 갖는 것이 사용자에게 더 나쁘다.

전환은 활동 로그에 남긴다. "이 대화가 어느 계정의 한도를 썼는가"를 나중에 되짚을 유일한 근거이기 때문이다. **계정 식별자와 이메일까지만 남기고 설정 디렉터리 경로는 남기지 않는다** — 로그는 사람이 읽고 공유하는 파일이다.

### 5.6 UI로 나가는 것

계정 id, 이메일, 조직명, 구독 종류, 상태, 확인 시각. **설정 디렉터리 경로는 절대 내보내지 않는다.** 경로가 화면에 있으면 그것을 되돌려 받는 API가 생기고, 그 순간 임의 경로 주입이 된다. 경로 해석은 런타임이 독점한다.

토큰은 어느 프로세스에서도 읽지 않으므로 "키는 렌더러로 나가지 않는다"는 불변식이 **저절로** 지켜진다.

## 6. 하지 않는 것

- **기계 전체 전환.** 터미널 `claude`는 영향을 받지 않는다. 원한다면 별도 결정이 필요하다.
- **한도 도달 시 자동 계정 전환.** §2-4.
- **ChatGPT 구독의 한도 표시.** 계정 관리는 별도 문서에서 다룬다. ChatGPT 자격증명은 naby가 이미 소유하므로 성격이 다르다.
- **비공식 사용량 API 호출.** 안정 경로가 있는데 문서화되지 않은 엔드포인트를 쓰지 않는다.

## 7. 검증

- 한도 변환은 순수 함수로 뽑아 픽스처로 검증한다. 실제로 관측한 이벤트를 픽스처로 쓴다.
- 전환은 전용 스파이크로 검증한다. 임시 설정 디렉터리 둘로 격리 성립, 캐시가 계정을 섞지 않음, 삭제 순서, 환경 치환 규칙을 어겼을 때 실패하는 것까지.
- **실 `~/.claude`를 절대 건드리지 않는 것이 그 스파이크의 첫 번째 요구사항이다.** 임시 DB 경로를 강제하는 기존 규율과 같은 이유다.
- 셸 배선은 vitest로 확인한다.

## 8. 미결

- `utilization`의 스케일. 값이 오는 상황을 관측하지 못했다. 정규화 함수 한 곳에 갇혀 있으므로 확인되면 그곳만 고친다.
- Windows 자격증명 저장 위치. §3.5. 설계는 알 필요가 없지만, 실기 확인이 되면 이 문서에 적는다.
- 계정별 한도를 나란히 보여줄지. 지금은 활성 계정 것만 보여준다.
