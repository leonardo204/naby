# 원격 MCP 브라우저 로그인 — 잘 알려진 서버 바로 연결과 URL 자동 감지

## 1. 결정 사항 (사용자 결정, 2026-10-13)

| 항목 | 결정 |
|---|---|
| 바로 연결 목록 | Notion, Linear, Asana, Sentry 네 개로 시작한다 |
| 목록에 없는 서버 | URL만 넣으면 OAuth가 필요한지 감지해 로그인 버튼을 보여 준다 |

## 2. 왜 지금 되는가

브라우저 OAuth 코드는 Atlassian 때 이미 만들었다(`src/runtime/mcp-oauth.ts`). 런타임 쪽은 서버 이름을 받아 동작하므로 일반화돼 있다.

- 토큰은 `mcp.oauth.<server>`에 서버별로 저장한다.
- 클라이언트는 동적 등록(RFC 7591)으로 만들고, 키 없는 공개 클라이언트에 PKCE S256을 쓴다.
- 갱신은 저장 먼저, 서버별로 한 번에 하나만 한다. 죽은 토큰은 `relogin` 상태가 된다.

셸 쪽은 Atlassian 전용이다. 로그인 액션(`atlassian.login`), 진행 중 로그인 상태(`orgHarness.ts`의 `pendingLogin` 하나), 로그인 버튼과 폴링이 모두 Atlassian에 묶여 있다. 이 문서의 일은 대부분 셸을 서버별로 바꾸는 것이다.

네 서버의 공개 메타데이터는 2026-10-13에 직접 조회했다. 모두 등록 엔드포인트가 있고, `token_endpoint_auth_methods_supported`에 `none`이, `code_challenge_methods_supported`에 `S256`이 있다. 지금 코드가 그대로 붙는 조건이다.

| 서버 | 이름 | 연결 주소 | 메모 |
|---|---|---|---|
| Notion | `notion` | `https://mcp.notion.com/mcp` | 보호 리소스 메타데이터 있음 |
| Linear | `linear` | `https://mcp.linear.app/mcp` | 같음 |
| Asana | `asana` | `https://mcp.asana.com/v2/mcp` | 예전 `/sse` 주소는 쓰지 않는다 |
| Sentry | `sentry` | `https://mcp.sentry.dev/mcp` | 메타데이터가 경로별(`/.well-known/oauth-protected-resource/mcp`)이고 401의 `resource_metadata`로 알려 준다 |

## 3. 화면

### 3.1 바로 연결

설정 → 연결 → 일반 MCP 목록 위에 "바로 연결" 줄을 둔다. 서버마다 이름, 한 줄 설명, 버튼 하나가 있다.

| 상태 | 버튼 | 누르면 |
|---|---|---|
| 연결 안 됨 | 연결 | 브라우저 로그인을 시작한다 |
| 로그인 진행 중 | 취소 | 진행 중인 로그인을 끝낸다 |
| 연결됨 | 연결 끊기 | MCP 행과 토큰을 지운다 |
| 다시 로그인 필요 | 다시 로그인 | 브라우저 로그인을 다시 시작한다 |

**로그인이 끝나야 행을 만든다.** 로그인에 성공하면 그때 `{name, transport: 'http', url, auth: 'oauth', status: 'enabled'}` 행을 만든다. 먼저 만들면 로그인하지 않은 서버가 매 턴 연결에 실패한다. Atlassian의 "로그인한 뒤에만 바꾼다"(org-harness-sync §4.4)와 같은 이유다.

바로 연결로 만든 행은 일반 MCP 목록에 다시 나오지 않는다. 같은 서버가 두 번 보이지 않게 하려는 것이다(System MCP 프리셋을 거르는 방식과 같다). 이름이 같은 일반 행이 이미 있으면 바로 연결 버튼 대신 "같은 이름의 서버가 이미 있습니다"를 보여 주고 덮어쓰지 않는다.

### 3.2 URL로 추가할 때 자동 감지

일반 MCP 추가 폼에서 `http`나 `sse`를 고르고 저장하면, 저장하기 전에 서버가 URL을 한 번 확인한다. 자격값 없이 요청을 하나 보내 응답을 본다. `http`는 MCP `initialize`를 POST로, `sse`는 스트림을 GET으로 연다. 10초 안에 답이 없으면 "확인 불가"로 본다.

| 응답 | 판정 | 폼이 하는 일 |
|---|---|---|
| 2xx | 인증 불필요 | 지금처럼 저장한다 |
| 401이고 OAuth 메타데이터에 등록 엔드포인트가 있음 | 브라우저 로그인 가능 | "이 서버는 브라우저 로그인으로 연결합니다"와 로그인 버튼을 보여 준다. 로그인에 성공하면 `auth: 'oauth'`로 저장한다 |
| 401인데 등록 엔드포인트가 없음 | 자동 로그인 불가 | "이 서버는 자동 로그인을 지원하지 않습니다. 헤더에 토큰을 넣어 주세요"를 보여 주고 헤더 칸을 연다 |
| 연결 실패·그 밖의 응답 | 확인 불가 | 오류를 보여 주되 "그래도 저장"을 허용한다(지금 동작) |

- 헤더를 직접 넣은 경우는 감지하지 않는다. 사용자가 이미 인증 방법을 정했기 때문이다.
- 메타데이터는 `@ai-sdk/mcp`가 로그인 때 쓰는 순서를 그대로 따른다. 401의 `resource_metadata`, 경로별 보호 리소스 메타데이터, 루트 메타데이터, 인가 서버 메타데이터 순서다. 감지와 로그인이 다른 결론을 내지 않게 하려는 것이다.
- 감지는 사용자가 저장을 누를 때만 한다. 목록을 열 때마다 원격 서버에 요청하지 않는다.
- 채팅에서 `naby_add_mcp`로 제안된 `http`·`sse` 행(`status: 'proposed'`)은 사용자가 승인할 때 같은 감지를 돌린다. 로그인이 필요하면 승인 버튼 대신 로그인 버튼을 보여 주고, 로그인에 성공하면 `auth: 'oauth'`와 `enabled`로 바꾼다.

### 3.3 일반 목록의 OAuth 행

`auth: 'oauth'` 행은 목록에서 상태 배지(연결됨·다시 로그인 필요)와 다시 로그인 버튼을 보여 준다. 헤더 칸은 보여 주지 않는다. 일반 삭제(`mcp.remove`)로 행을 지워도 그 서버의 토큰(`mcp.oauth.<server>`)을 함께 지운다. 이름을 바꾸는 편집은 받지 않는다. 토큰이 이름에 묶여 있어서다.

## 4. 런타임과 셸

### 4.1 액션

Atlassian 전용 액션을 서버 이름을 받는 액션으로 일반화한다.

| 액션 | 인자 | 하는 일 |
|---|---|---|
| `mcpOAuth.probe` | `url`, `transport` | §3.2 판정을 돌려준다. 저장하지 않는다 |
| `mcpOAuth.login` | `server`, `url` | 로그인을 시작하고 인가 URL을 돌려준다 |
| `mcpOAuth.cancel` | `server` | 그 서버의 진행 중 로그인을 끝낸다 |
| `mcpOAuth.disconnect` | `server` | 행과 토큰을 지운다 |

- `atlassian.login`·`atlassian.cancelLogin`은 남겨 두고 내부에서 새 액션을 부른다. 상태 줄(chat-connection-status)이 쓰고 있어서다. Atlassian만의 후처리(`applyAtlassianAtTurnBoundary`)는 Atlassian 로그인이 끝났을 때만 돈다.
- 진행 중 로그인은 서버별로 하나다. 서로 다른 서버의 로그인은 동시에 진행할 수 있다(루프백 포트가 로그인마다 다르다).
- 상태 조회는 OAuth 행마다 `{status: connected | relogin | none, pending, lastError}`를 준다. 로그인 버튼은 지금처럼 2초마다 이걸 읽어 끝났는지 본다.
- `mcpOAuth.*` 액션의 `server`는 바로 연결 목록의 이름이거나, URL 추가 폼에서 사용자가 정한 이름이다. System MCP 프리셋 이름(skill-hub·atlassian·cic)은 이 액션들이 거절한다. 프리셋은 자기 액션(`atlassian.*`, `systemMcp.*`)을 쓴다. 로그인 시작·취소·상태 관리는 서버별 내부 함수 하나로 구현하고, `mcpOAuth.*`와 `atlassian.*`가 모두 그 함수를 부른다. 거절은 액션 입구에서만 한다.

### 4.2 바로 연결 목록의 자리

목록(이름, URL, 설명 i18n 키)은 셸 서버 쪽 한 곳에 둔다. 클라이언트에는 System MCP 프리셋처럼 거울을 두고, 테스트로 두 쪽이 같은지 확인한다. 런타임은 목록을 모른다. 런타임에게는 OAuth 행 하나일 뿐이다.

### 4.3 엔진

새 행은 일반 OAuth 행이므로 두 엔진 모두 손댈 곳이 없다. 도구 이름은 `mcp__<server>__<tool>`이고, Claude 엔진에서는 `nabytools`를 거쳐 나온다. 도구 승인은 지금 정책 그대로다.

토큰이 죽어도 턴은 멈추지 않는다. 그 서버만 건너뛰고 `relogin` 배지가 붙는다(지금 동작). 채팅 입력창 아래 연결 상태 줄에는 이 서버들을 넣지 않는다. 그 줄은 조직 하네스가 필요로 하는 연결만 보여 준다(chat-connection-status).

### 4.4 Atlassian과 다른 점

`MCP_OAUTH_REQUIRED_TOOLS`는 Atlassian처럼 죽은 토큰에 401 대신 줄어든 도구 목록을 주는 서버를 위한 것이다. 네 서버에는 넣지 않는다. 실제 서버 확인(§5)에서 같은 증상이 보이면 그때 넣는다.

요청하는 scope는 없다. 각 서버의 기본 scope로 받는다. Sentry는 메타데이터에 쓰기 scope가 나열돼 있는데, 기본 scope로 도구가 충분히 나오는지는 실제 로그인으로 확인한다(§5).

## 5. 검증

- **스파이크(자동).** `spike:mcp-oauth`의 가짜 서버를 두 가지 모양으로 늘린다.
  - Notion형: 루트 보호 리소스 메타데이터가 있다.
  - Sentry형: 401에 `resource_metadata`를 싣고 경로별 메타데이터만 있다.

  각각 감지 판정, 로그인, 연결, 갱신, `invalid_grant`→relogin을 확인한다. 등록 엔드포인트가 없는 가짜 서버로 "자동 로그인 불가" 판정도 확인한다.
- **셸 테스트.** 바로 연결 상태 네 가지와 버튼, 로그인 성공 뒤에만 행이 생기는 것, 이름 충돌, 서버별로 진행 중 로그인이 따로 있는 것, 연결 끊기가 행과 토큰을 함께 지우는 것, 프리셋 이름 거부, 거울 일치, i18n.
- **실제 서버(수동, 사용자).** 네 서버에 각각 한 번 로그인해 도구 목록이 나오는지 본다. 테스트와 스파이크는 실제 서버에 붙지 않는다.

## 6. 남은 판단

- Figma, Canva, Vercel 같은 다음 후보는 이 문서가 끝난 뒤 실제 로그인을 해 보고 목록에 더한다. Figma는 등록된 클라이언트만 허용할 수 있어 확인이 필요하다.
- GitHub 원격 MCP는 동적 등록이 없다. 바로 연결에 넣으려면 토큰 칸이 있는 별도 방식이 필요하다. 이 문서에서는 다루지 않는다.

## 7. 구현 상태 (2026-10-13)

구현했고 커밋하지 않았다. 가짜 서버로는 확인했고, 실제 네 서버의 로그인은 아직 확인하지 않았다(§5 수동).

구현하면서 이 문서가 정하지 않은 부분을 이렇게 정했다.

1. **감지 결과를 로그인에 넘긴다.** 401이 메타데이터 주소를 알려 준 서버는 로그인 때도 그 주소로 찾는다(`resourceMetadataUrl`). `@ai-sdk/mcp` 2.0.15가 찾는 함수를 내보내지 않아서 감지는 같은 순서를 따로 구현했다. 스파이크가 두 쪽이 같은 주소를 같은 순서로 요청하는지 확인한다.
2. **OAuth 메타데이터가 전혀 없는 401은 "자동 로그인 불가"다.** 라이브러리처럼 `/register`를 어림으로 두드리지 않는다.
3. **로그인이 어차피 실패할 401은 "확인 불가"다.** 메타데이터가 다른 출처를 가리키거나, 리소스가 URL과 맞지 않거나, 라이브러리가 거절할 메타데이터(5xx, issuer 불일치)인 경우다.
4. **같은 이름에 행이 있으면 로그인을 거절한다.** URL이 같을 때(다시 로그인, 제안 승인)와 그 행을 고쳐 저장할 때(`replace`)만 받는다.
5. **바로 연결의 "연결됨"은 정확히 그 행일 때만이다.** 이름, 원격 전송, `auth: 'oauth'`, 목록의 URL이 모두 맞아야 한다. 이름만 같은 행은 사용자 것으로 보고 일반 목록에 두며, 이름 충돌 문구를 보여 준다.
6. **`mcp.upsert`는 OAuth 행을 만들지도 고치지도 않는다.** 화면에서 막을 뿐 아니라 서버도 거절한다.
7. **진행 중일 때는 "브라우저에서 기다리는 중" 문구와 취소 버튼 하나를 보여 준다.** Atlassian 버튼 모양은 그대로다.
8. **"다시 로그인" 안내 문구**는 Atlassian 밖의 서버에서 "설정 → 연결"을 가리킨다.

검증 결과는 다음과 같다.

- 스파이크: `spike:mcp-oauth-catalog` 24, `spike:mcp-oauth` 30, `spike:autonomy` 34, `spike:02` 5, `spike:org-harness-gate` 26, `spike:add-mcp` 5. 모두 통과했다.
- 셸 테스트: 223개 파일, 4264개 통과.
- 타입체크: 기존 오류만 있다.
- prod 서버: 가짜 서버로 감지, 로그인, 콜백, 행 생성, 도구 3개 조회, 연결 끊기까지 확인했다. 어떤 응답에도 토큰이 실리지 않았다.
