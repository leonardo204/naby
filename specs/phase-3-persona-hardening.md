# Phase 3 P3-M9 — 페르소나 하드닝 (위임 가능한 잠긴 에이전트)

> 상태: 설계 확정(2026-07-30). **G1~G4 구현 완료**(§6.1). 업계·연구 문헌 조사(벤더 4사 공식 문서, 논문 20여 편, 선두 제품 3사 + Lindy·OSS) 기반의 완비성 감사에서 나온 공백 G1~G4를 구현한다. M10(§7)은 후속이다.
> 한 줄 요약: 페르소나를 잠근 대신 시드와 배선을 단단하게 만든다 — 정체성은 시드가, 자율 수준은 사용자가, 위임 자격은 나비 게이트가 소유한다.

## 1. 배경 — 잠금이 만든 새 요구

페르소나는 편집·삭제가 불가능한 내장 에이전트다(persona-agent §4, 2026-07-30 사용자 결정). 잠근 순간 두 가지가 따라온다. 시드가 페르소나가 가질 유일한 지침이 되므로 **시드 자체가 완결적이어야 하고**, 사용자가 에이전트 행을 고칠 수 없으므로 **사용자 몫의 설정은 다른 자리로 옮겨야 한다.**

완비성 감사는 이 지점에서 공백 4개를 찾았다.

| # | 공백 | 근거 |
|---|---|---|
| G1 | 시드에 `maxSteps`가 없고 `escalation: 'inline'` 고정 — 잠긴 행으로는 "테스트 90%까지 알아서, 텔레그램 알림" 비전(persona-agent §1)이 실행 불가 | Lindy graduated autonomy, OpenAI 위험 등급 HITL |
| G2 | `@` 팔레트는 나비만 허용하지만 엔진 라우팅은 단계 검사 없이 통과 — 직접 타이핑하면 알 단계도 위임된다 | "두 표면이 한 함수를 공유한다"(checkin-contracts §5) |
| G3 | 시드 프롬프트에 메모리 프로토콜·물음 시점·검증 규칙·보고 형식이 없다 | Anthropic memory tool·harness 가이드, Ask Early(목표 확인은 초반 10% 안에), Knowing but Not Showing(물음은 명시 정책이어야 한다) |
| G4 | 자율 루프 종료 조건에 검증이 없다 — no-tool-use/`[[DONE]]`/상한뿐 | Anthropic 루프 정의(gather→act→verify), "검증 전 완료 선언 금지" |

감사에서 확인한 강점(신뢰 지표, 오염 방어, 학습 신호 다중화, 이식성)은 건드리지 않는다.

## 2. G1 — 자율 설정의 소유권을 사용자에게 옮긴다

### 2.1 원칙

에이전트 정의에는 **정체성**(이름·지시·종류)이 들어가고, **얼마나 맡길지는 위임하는 사람의 것**이다. 업계 실무도 같다 — Lindy는 액션별 확인 토글을 사용자가 조절하고, OpenAI는 "신뢰가 쌓일 때까지" 승인을 걸라고 말한다. 지금까지는 두 가지가 `autonomy` 필드에 섞여 있었고, 잠금이 그 혼재를 드러냈다.

### 2.2 설계

- 새 사용자 설정 두 개(settings 테이블): `persona.autonomy.escalation`('inline'|'telegram'|'both', 기본 'inline'), `persona.autonomy.maxSteps`(기본 1=끔, `AUTONOMY_STEP_CAP`(20) 상한, 저장 시에도 자른다 — agent.put과 같은 규칙).
- 엔진은 라우팅된 에이전트가 페르소나(kind='persona')면 **행의 `autonomy`를 읽지 않고 이 설정을 읽는다.** 커스텀 에이전트는 지금처럼 자기 행을 읽는다(행이 편집 가능하므로 소유권 문제가 없다).
- 시드는 바꾸지 않는다. `autonomy: {escalation:'inline'}`은 형태 호환으로 남고 엔진이 페르소나에 대해서만 무시한다.
- UI: 페르소나 카드에 "위임 설정" 섹션을 둔다. 정체성(이름·지시)은 읽기 전용 그대로, 에스컬레이션 채널과 자율 단계 상한만 편집할 수 있다. 문구가 소유권을 말한다 — 페르소나가 아니라 **위임 방식**을 설정하는 것이다.

## 3. G2 — `@` 게이트를 하나로 만든다

- 엔진 라우팅(`parseAgentAddress` → `getAgentByName`)에 팔레트와 **같은 읽기 함수**(growthRead 계열)로 `canBeAddressed(stage)` 검사를 추가한다. 나비가 아니면 정체성을 채택하지 않는다.
- 거부된 턴은 죽지 않는다 — **일반 턴으로 진행**하고(관측은 평소처럼 페르소나에 귀속), muted harness 필로 "아직 나비 단계가 아니라 @위임을 받을 수 없어 일반 턴으로 처리했다"를 알린다(i18n en/ko).
- 읽기 실패는 알로 취급한다(fail-closed) — 팔레트와 같은 동작이다.
- 커스텀 에이전트에도 같은 규칙이 적용된다. 팔레트가 이미 그렇게 보여주고 있었고, 엔진이 이제 그 말을 지킨다.

## 4. G3 — 시드 프롬프트에 운영 프로토콜을 넣는다

시드 `systemPrompt`(영어, 코드 리터럴)를 다음 프로토콜이 담기게 강화한다. 기존 계약(대리 수행, 중대사만 에스컬레이션, 간결 보고)은 유지하고 넷을 더한다.

1. **메모리 우선** — 주입된 기억을 먼저 반영하고, `confirmed` 절차(procedural) 기억은 상시 운영 규칙으로 따른다. 잠긴 지침과 충돌하지 않는 자기 개선 통로가 이것이다 — 지침은 불변, 배운 규칙은 기억으로 쌓인다.
2. **목표 확인은 초반에** — 목표나 완료 기준이 불명확하면 **첫 몇 스텝 안에** 물어라. 실행이 진행된 뒤의 목표 질문은 가치가 급락한다. 루틴한 저위험 스텝은 묻지 말라(기존 원칙 유지).
3. **검증 후 완료** — 완료 기준과 대조해 확인하기 전에는 끝났다고 선언하지 말라. 무엇을 어떻게 확인했는지가 보고의 일부다.
4. **보고 형식** — 한 일, 내린 판단, 확인한 것, 의도적으로 남긴 것.
5. **어투**(2026-08-04 추가) — 사용자의 언어를 따르고, 한국어로는 자연스러운 존댓말(해요체/합니다체)로 쓰며 거친 관용구나 직역투를 쓰지 않는다. 페르소나가 한국어 답변에서 거친 관용구를 쓴 사례에서 나왔고, 행이 잠겨 있으므로 고칠 통로는 이 시드뿐이다.

시드 변경은 `seedBuiltinPersona`의 강제 복원을 타고 기존 설치에도 다음 부팅에 배포된다 — 잠금 메커니즘이 곧 프롬프트 업그레이드 채널이다.

## 5. G4 — 자율 루프에 검증 스텝을 넣는다

- `decideAutonomyStep`의 종료 직전에 검증 단계를 끼운다. 자율 런(maxSteps>1)에서 모델이 `[[DONE]]` 또는 no-tool-use로 멈추려 할 때, 그 스텝에 검증 근거가 없으면 **검증 촉구 continuation을 정확히 한 번** 보낸다: "목표와 완료 기준에 대조해 결과를 확인하라. 미비하면 계속하고, 확인되면 무엇을 확인했는지와 함께 끝내라."
- 촉구는 런당 1회다. 두 번째 멈춤은 그대로 종료한다 — 검증을 무한 루프의 핑계로 만들지 않는다.
- 단일 턴(maxSteps 없음/1)은 건드리지 않는다. byte-for-byte no-op 불변은 자율 루프의 기존 계약이다.
- 검증 근거 판정은 결정론적 마커로 한다(`[[VERIFIED: ...]]` — autonomyInstruction 프로토콜에 추가). 마커가 있으면 촉구 없이 종료한다.

## 6. 검증 계획

- `spike:autonomy` 확장 — 검증 마커 없이 멈추면 촉구 1회 후 종료, 마커가 있으면 촉구 없음, 촉구는 런당 1회, 단일 턴 no-op 불변, maxSteps 상한 불변.
- `spike:agents` — 시드 프롬프트 강제 복원이 새 프로토콜 텍스트를 배포함.
- 셸 vitest — 페르소나 자율 설정 읽기/저장(상한 절단), 라우팅 게이트(알 단계 → 일반 턴 + 필, 나비 → 채택), 커스텀 에이전트 경로 불변, UI 위임 설정 섹션 배선.
- 회귀 — 전체 스파이크 세트 + 셸 전체 + 타입체크 양 트리 + `build:app`.
- 미검증으로 남는 것 — 라이브 모델이 새 프로토콜(초반 목표 확인, 검증 마커)을 실제로 얼마나 따르는지. mock으로는 배선만 증명된다.

### 6.1 구현 상태 — ✅ 완료(2026-07-30)

`npm run spike:autonomy` **22/22 PASS**(기존 10개 유지 + G4 4개 + G2 4개 + G1 4개), `spike:agents` 양 드라이버 PASS(시드 프로토콜 4종 강제 복원 확인), 회귀 스파이크 전부 PASS(reflection 51/51, checkin 12/12, growth 27/27, spike:02 5/5, learn 10/10, rank 13/13), 셸 테스트 **704/704**(54개 파일), 타입체크 clean(양 트리, 기존 베이스라인 4건 제외 — 전부 손대지 않은 테스트 파일), `build:app` exit 0. 구현하며 확정된 설계가 일곱 있다.

- **게이트는 규칙이 아니라 함수 하나로 만든다.** 팔레트와 엔진이 각자 `canBeAddressed(readGrowth(...).stage)`를 쓰면 규칙이 둘이 되고, 갈라지는 순간이 바로 이 공백(G2)이 생긴 방식이다. `growthRead.isAddressable(store, agentId)` 하나를 두 표면이 **호출**한다. 실패는 닫는다 — 원장을 못 읽으면 알이고, 알은 위임받지 못한다.
- **거부된 주소도 `@name`은 떼고 작업 텍스트로 돈다.** 판단 기준을 `routedAgent`가 아니라 `addressedAgent`에 둔다. `@`를 남겨두면 모델이 알 이유가 없는 핸들을 받고, 줄 전체를 버리면 사용자의 요청 자체가 사라진다. 정체성 채택만 거부한다.
- **필은 서버가 코드로, 클라이언트가 문장으로 만든다.** Next 서버에는 로케일이 없다(`growthReport.change`가 코드인 것과 같은 이유). 엔진은 `routing-gate` / `not-butterfly:<name>`을 보내고 `client/harnessPill.ts`가 en/ko로 렌더한다. 나머지 필(자율 스텝 바 등)은 종전대로 그대로 통과시킨다. 리듀서의 행 식별자는 **코드**로 잡는다 — 번역문으로 잡으면 언어를 바꾸는 순간 같은 필이 다시 쌓인다.
- **`decideAutonomyStep`의 검증 게이트는 모양으로 opt-in한다.** `verification` 필드가 없으면 M9 이전 동작 그대로다. 기본값을 켜두면 기존 호출자 전부의 동작이 조용히 바뀌므로, 규칙이 기본값을 타고 새는 길을 막는다. 게이트가 놓이는 자리는 "멈추고 싶다"와 "멈춘다" **사이**다 — 완료 주장이 만들어지고 아직 검사되지 않은 바로 그 순간이기 때문이다.
- **촉구는 두 겹으로 막힌다.** 런당 1회(`nudgeSent`)이고 예산을 넘지 않는다(`step < maxSteps`). 촉구 continuation도 평범한 스텝이라 똑같이 세며, 상한이 프로토콜보다 위다. abort·error는 종전대로 게이트보다 위다.
- **클램프는 쓸 때도 돈다.** 저장값이 곧 실행값이다. 읽을 때만 자르면 Settings는 50을 보여주고 엔진은 20을 돌려, 화면의 숫자가 제품이 지키지 않는 숫자가 된다. 필드별로 따로 쓰므로 컨트롤 하나를 저장해도 다른 하나가 초기화되지 않는다.
- **스파이크의 에이전트는 나비를 벌어야 한다.** 게이트가 켜지자 `spike-autonomy`·`spike-learn`이 만든 갓 생성 에이전트는 전부 알이 됐다. 두 스파이크는 원장에 연속 8히트를 넣어 나비를 **번다**(Wilson 하한 ~0.68 > 0.60). 특히 `spike-learn`은 게이트를 우회하지 않으면 검사가 통과는 하되 라우팅을 더 이상 시험하지 않는 상태가 된다 — 페르소나가 턴을 받아가기 때문이다.

검증이 커버하는 범위와 남는 것.

- G1은 스파이크 (i)~(i4)가 엔진까지 몬다: 페르소나 턴이 설정에서 예산을 읽고, **잠긴 행은 손대지 않으며**(autonomy·systemPrompt·updatedAt 불변), 설정을 1로 되돌리면 즉시 단일 턴으로 돌아가고, 커스텀 에이전트는 여전히 자기 행을 읽는다. 규칙 자체(기본값·클램프·부분 저장)는 `lib/personaAutonomy.test.ts`, API 배선은 `api/naby.test.ts`가 잡는다.
- G2는 스파이크 (h)~(h4)가 실제 엔진으로 몬다(알 → 정체성 미채택·필 1개·`@` 제거된 작업 텍스트로 실행, 같은 에이전트가 나비가 되면 그대로 라우팅). 게이트 함수 자체는 `growthRead.test.ts`가 알/유충/번데기/나비/읽기 실패로 나눠 검사하고, 팔레트가 렌더하는 값과 **같은지**를 등식으로 확인한다.
- G3은 `spike-agents`가 **치유된 행**에서 프로토콜 마커 5종과 기존 계약 2줄을 확인한다. 2026-08-04부터는 직전 릴리스의 시드(현재 시드에서 `LANGUAGE` 항목만 뺀 것)를 넣어 두고 부팅 치유가 새 프롬프트로 올려놓는지도 함께 본다 — 프롬프트만 달라도 드리프트로 잡히는지가 이 채널이 성립하는 조건이다. 시드 상수가 아니라 치유 결과를 보는 이유는, 상수만 보면 낡은 시드에서도 통과하기 때문이다.
- G4는 스파이크 (g)~(g4)와 `autonomy.test.ts`가 나눠 맡는다. 단일 턴 no-op 불변은 양쪽에 다 있다.
- **미검증** — 라이브 모델이 실제로 초반에 목표를 묻는지, `[[VERIFIED:]]`를 성실히 채우는지(빈 검증 주장을 쓰지 않는지), 촉구 1회가 충분한지. mock은 배선만 증명한다(§8 미결정과 같은 항목).

## 7. M10 개요 — 메모리 위생·주권 (후속)

- **감쇠(G5)** — 접근 빈도·최신성 기반으로 장기 미사용 기억의 주입 우선순위를 낮추고, 임계 초과 시 검토 큐로 올린다. 연구는 망각을 청소가 아니라 기능 요구로 본다(신호대잡음 개선, 오래된 고관련 사실의 오답 유발 방지).
- **주권 컨트롤(G6)** — 기억 항목 편집, 학습 전체 끄기 스위치, 임시(비학습) 세션 모드. 선두 3사가 공통으로 제공하는 기준선이다.
- 사전 행동성(G7, scheduledTasks 페르소나 통합 + 필요성 검사)과 편집비용 곡선(G8, M8e 골든셋)은 별도 트랙으로 남긴다.

## 8. 미결정

- `persona.autonomy.maxSteps`의 기본값. 1(끔)로 시작하되, 나비 도달 시 기본을 올릴지("신뢰가 자율을 산다"의 연장)는 실사용을 보고 정한다.
- 검증 촉구 1회가 충분한지. 촉구 후에도 미검증 종료가 잦으면 보고에 "미검증 종료" 표기를 추가하는 안이 후보다.
- 커스텀 에이전트의 autonomy도 설정으로 승격할지. 지금은 행이 편집 가능하므로 두지 않는다.
