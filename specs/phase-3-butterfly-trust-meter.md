# Phase 3 P3-M5 — 나비 신뢰 지표 (알고리즘 설계)

> 상태: 설계 확정(2026-07-25). 알고리즘 코어는 `src/runtime/growth.ts`에 구현하고 `npm run spike:growth`로 검증한다.
> 한 줄 요약: 페르소나 에이전트가 **얼마나 쌓았는지**가 아니라 **얼마나 검증됐는지**를 재서 알 → 애벌레 → 번데기 → 나비로 표시하고, 나비만 `@`로 부를 수 있게 한다.

## 1. 이 문서가 답하는 질문

> **"이 에이전트에게 일을 맡겨도 되는가를, 사용자가 믿을 수 있는 방식으로 어떻게 숫자로 만드는가?"**

제품의 성패는 나비 에이전트를 빨리 쓰게 되는 데 있지 않다. **믿고 맡길 수 있을 만큼 잘 처리하는지**에 있다. 그래서 지표가 관대하면 기능이 아니라 거짓말이 된다.

## 2. 개수를 세지 않는 이유

가장 쉬운 "학습률"은 누적이다. 저장한 기억 수, 대화 턴 수. 이것은 신뢰 신호로 쓸 수 없다. **틀린 사실 50개를 저장한 에이전트가 만개한 것으로 표시된다.** 개인화 전략 문서가 이미 같은 결론에 도달해 있다(`personalization-strategy` §2.2). 북극성 지표는 편집률 감소 곡선이고, 편집거리는 "대시보드 숫자가 아니라 깎아 내려야 할 대상"이다.

## 3. 신호 — 앱의 대화가 라벨을 만든다

에이전트가 작업 도중 **자기 추천안을 명시해** 묻는다. 사용자의 응답이 곧 라벨이 된다.

```
naby: 이 파일들을 정리하려고 합니다. 이렇게 할까요?
      ▸ (추천) 날짜별 폴더로 나눈다
        유형별 폴더로 나눈다
        그냥 이름만 바꾼다
사용자: [추천 선택]  → hit   (naby가 이미 알고 있었다)
        [다른 선택]  → miss  (아직 모른다)
```

이것은 PRELUDE/CIPHER(Gao et al., NeurIPS 2024)의 **zero-edit rate**를 문서가 아니라 **제안**에 적용한 것이다. 논문은 사용자 편집에서 잠재 선호를 학습하며 편집거리 총합과 무편집 비율로 성능을 재고, CIPHER가 60%, oracle이 76.7%를 기록했다. 같은 지표 계열이면서 **홀드아웃 코퍼스도, 동의 절차도, 별도 채점 모델도 필요 없다.** 앱을 쓰는 행위 자체가 라벨을 생산한다. 전략 문서의 "승인 버튼이 그대로 학습 신호"(§3.1)를 도구 승인에서 작업 판단으로 넓힌 것이다.

원장에 남기는 사건은 세 종류다.

| 사건 | 언제 | 무엇을 기록하는가 |
|---|---|---|
| `checkin` | 되돌릴 수 없는 행동 전에 물었다 | 추천안, 사용자 선택, hit 여부, 자기 확신도, 작업 유형 |
| `autonomous` | 묻지 않고 처리했다 | 되돌릴 수 있었는지, 사후에 사용자가 고쳤는지 |
| `tripwire` | 안전 관련 위반이 게이트에서 걸렸다 | 도구, 사유 |

## 4. 알고리즘

### 4.1 적중률의 신뢰 하한 (Wilson)

관측된 비율을 그대로 쓰면 **3번 맞힌 것이 100%가 된다.** 그래서 모든 단계는 Wilson score interval의 **하한**을 본다. 증거가 적으면 하한이 관측값보다 크게 낮고, 표본이 늘어야 올라간다. 결과적으로 성장은 **두 번 벌어야** 한다 — 맞히는 것, 그리고 맞혔다고 증명할 만큼 자주 맞히는 것.

```
p̂ = s/n
lower = ( p̂ + z²/2n − z·√( p̂(1−p̂)/n + z²/4n² ) ) / ( 1 + z²/n )     z = 1.96 (95%)
```

Wald 구간과 달리 [0,1]을 벗어나지 않고, 양 끝(0/0, n/n)에서 점추정으로 붕괴하지 않는다. 바로 그 지점이 순진한 비율이 거짓 확신을 보고하는 곳이다.

### 4.2 단계 문턱 (실측 검증값)

| 기록 | 하한 | 단계 | 뜻 |
|---|---|---|---|
| 2/2 | — | 🥚 알 | 표본 미달(최소 5) |
| 3/3 완벽 | 0.438 | 🥚 알 **0%** | 표본이 아니다 |
| 4/5 | 0.376 | 🐛 애벌레 | 5번에 1번 놓치면 실적이 아니다 |
| 5/5 완벽 | 0.566 | 🛡 번데기 | 완벽하지만 5건은 작다 |
| 8/8 완벽 | 0.676 | 🦋 나비 | 운으로 보기 어려운 연속 적중 |
| 17/20 | 0.640 | 🦋 나비 | 현실적 경로 |

상수: `GROWTH_MIN_SAMPLE=5`, `PUPA_THRESHOLD=0.45`, `BUTTERFLY_THRESHOLD=0.6`. 나비 문턱은 PRELUDE에서 CIPHER가 도달한 무편집 비율(약 60%)에 맞췄다. 추천이 5번에 3번 채택된다는 것이 **증명된** 수준이면, 문헌이 작동하는 개인화로 취급하는 지점이다.

### 4.3 게이지와 라벨은 서로 다른 말을 하지 않는다

퍼센티지는 `하한 / 0.6`의 진척도다. 단 **알 단계는 0%로 고정한다.** 완벽한 3/3의 하한은 0.438이라 그대로 두면 "알 — 아직 측정 못 함" 라벨 옆에 73% 게이지가 붙는다. 숫자와 단어가 다른 말을 하면 **사용자는 숫자를 믿는다.** 알 단계에서는 대신 "측정까지 N회 남음"을 보여준다.

### 4.4 커버리지 — 물어본 것만 채점하면 부풀릴 수 있다

적중률만 재면 에이전트가 **확신할 때만, 또는 사소한 것만 물어서** 100%를 만들 수 있다. 교과서적인 Goodhart다.

표준 해법은 selective classification의 **risk at coverage**(Geifman–El-Yaniv)다. LLM 에이전트에 적용한 최신 사례는 정확도를 **항상 커버리지와 함께** 보고한다(87~88% 정확도를 54~62% 커버리지에서). naby에 대응시키면 묻는 것이 판단 보류(abstention)이고, 묻지 않고 처리한 비율이 커버리지다.

```
coverage = autonomous / (autonomous + checkin)
```

그래서 나비 조건에 **커버리지 하한**이 들어간다. "잘 맞힌다"로는 부족하고 "모든 걸 묻지 않으면서 잘 맞힌다"여야 한다. 묻지 않고 처리한 구간의 오류(사후 수정, 게이트 거부)도 같은 원장에 남겨 커버리지가 공짜로 늘지 않게 한다.

### 4.5 물음의 트리거는 에이전트가 아니라 행동이 정한다

커버리지 하한만으로는 부족하다. **언제 물을지를 에이전트가 고르면** 여전히 유리한 것만 고를 수 있다. 업계 실무가 이 구멍을 원천에서 막는다.

- LangChain의 interrupt 실무 규칙: **"되돌릴 수 없고 파급이 큰 행동에만 끼어들어라 — 매 단계가 아니다."**
- OpenAI Agents SDK: 가드레일을 에이전트가 아니라 **도구에** 붙인다. 도구 수준 가드레일은 "에이전트가 어떤 경로로 그 호출에 도달했든 모든 호출을 잡는다."

따라서 체크인 의무는 **행동 부류의 성질**이다. naby에는 이 분류가 이미 있다 — `phase1HarnessFloor`의 `OBSERVATION_BUILTINS`(읽기 전용) 대 `DANGEROUS_BUILTINS`(변형·실행). 새로 만들지 않고 재사용한다.

여기에 LangSmith가 하는 채점을 하나 더 가져온다. 정답 여부만이 아니라 **"승인을 위해 멈췄는지 자체를 채점"** 한다. 즉 물음 판단에도 재현율(위험한 행동에서 물었는가)과 정밀도(사소한 것에 묻지 않았는가)가 있다.

### 4.6 창 관리 — 고정 20에서 변화 감지로

사용자 패턴이 실제로 바뀌면 옛 데이터가 추정치를 **오염시킨다.** 고정 창 20은 다 밀려나가는 데 체크인 20번이 걸리고, 앞/뒤 절반 비교는 통계적 검정이 아니라 어림이다.

**ADWIN**을 쓴다. 파라미터 없이 창을 유지하며 인접 부분창들의 통계를 비교하고, 유의한 차이가 감지되면 **창을 즉시 줄여 최근 데이터만 남긴다.** 감지 시점은 후퇴 설명의 근거가 된다 — "여기서 패턴 변화를 감지해 그 이후만 세고 있다"가 어림이 아니라 사실이 된다.

### 4.7 보정 — 정확도와 다른 축

ConfidenceBench(2026)의 결론: **가장 정확한 모델이 가장 잘 보정된 모델이 아니며**, 말로 표현한 확신도의 보정은 정확도와 별개의 실용 축이다. 선택적 자동화가 성립하려면 "확신도 0.8이면 실제로 80% 맞아야" 한다.

체크인에 자기 확신도를 담고 **Brier score**로 보정을 잰다. "잘 맞힌다"와 "자기가 언제 틀릴지 안다"는 다르고, 혼자 처리하게 맡길 근거는 뒤쪽이다.

단, 같은 계열 연구가 **말로 한 확신도는 행동 일관성(여러 번 실행해 일치도 측정)보다 약한 실패 탐지기**라고 보고한다. 일관성 측정은 모델 호출이 배로 드니 지금은 확신도를 **믿지 않고 보정만 측정**하고, 일관성 방식은 후보로 남긴다.

### 4.8 트립와이어는 평균에 섞지 않는다

OpenAI의 tripwire는 규칙 위반 시 실행을 즉시 중단시킨다. 신뢰 지표로 옮기면 **안전 관련 위반은 평균으로 희석되면 안 된다.** 파괴적 행동이 게이트에서 거부된 사건이 창 안에 있으면 적중률이 아무리 높아도 그 창에서는 나비가 될 수 없다. 하드 게이트다.

### 4.9 신뢰는 전역이 아니라 작업 유형별이다

Claude Code 권한 모델의 핵심은 **graduated trust**다. 이진 허용이 아니라 allow/deny/ask를 순서대로 평가하고(deny 우선), 매칭이 없으면 묻고(fail-closed), 신뢰를 **도구별·디렉터리별로** 넓힌다. 되돌릴 수 없는 것만 deny에 둔다.

성장 지표도 같아야 한다. 글쓰기에서 나비여도 SQL 리뷰에서는 알일 수 있다. 이것이 드리프트 문제도 상당 부분 녹인다 — 새 작업 유형은 전역 점수를 끌어내리는 대신 **자기 알 단계에서 시작한다.**

**대가**: 범위를 쪼개면 범위당 표본이 줄어 하한이 넓어지고 성장이 느려진다. 빠른 도달이 목표가 아니므로 감수한다.

멘션 게이트는 **전역(모든 범위 합산)** 단계를 쓰고, 패널이 작업 유형별로 분해해 보여준다. 게이트가 하나여야 UI와 라우팅이 어긋나지 않는다.

### 4.10 결과 수용과 접근 일치를 분리한다

Google ADK/Vertex 에이전트 평가는 **trajectory 평가와 final response 평가를 따로** 낸다(`trajectory_exact_match`, `in_order_match`, `any_order_match`, `precision`, `recall`). 우연히 결과만 맞은 것과 접근까지 맞은 것을 구분하려는 설계다. 체크인에서 사용자가 **어느 선택지를 골랐는지**까지 기록해 "결과는 받아들였지만 접근은 달랐다"를 구분한다.

## 5. 나비 게이트 (다섯 축 동시 성립)

| 축 | 조건 |
|---|---|
| 적중 정확도 | Wilson 하한 ≥ 0.6 |
| 커버리지 | 스스로 처리한 비율 ≥ 하한 |
| 물음 판단 | 위험 행동에서 물었고 사소한 것엔 안 물었다 |

| 트립와이어 | 창 안에 안전 위반 0건 (하드) |

## 6. 후퇴와 그 설명

게이지는 **내려간다.** 최근 창 기준이라 옛 연속 적중이 현재를 떠받치지 못한다. 검증: 나비(100%)에서 최근 8건을 놓치자 애벌레(64%)로 떨어졌다. 오르기만 하는 지표는 장식이다.

내려갈 때 사용자에게 갚아야 할 것은 **정직한 이유**다. 진단은 결정론적이다 — 모델을 부르지 않으므로 재현되고, 공짜이고, **이유를 지어낼 수 없다.**

| 사유 코드 | 언제 | 설명 예시 |
|---|---|---|
| `not-measured` | 표본 미달 | "아직 5회를 모으지 못해 측정을 시작하지 않았습니다." |
| `new-pattern` | 처음 보는 작업 유형에서 놓쳤다 | "SQL 리뷰는 지금까지 없던 종류의 일입니다. 최근 8번 중 6번을 다르게 고르셨고, 이 유형을 더 배워야 합니다." |
| `accuracy-drop` | 익숙한 작업에서 놓쳤다 | "익숙한 작업인데 최근 8번 중 6번이 어긋났습니다." |
| `accuracy-gain` | 실제로 더 맞히고 있다 | "추천이 더 자주 채택되고 있습니다." |
| `evidence-grew` | 비율은 같고 표본이 늘었다 | "적중률은 같지만 사례가 늘어 확신이 높아졌습니다." |
| `steady` | 변화 없음 | — |

**핑계를 대지 않는다**: 같은 하락이라도 이미 익숙한 유형에서 발생했으면 `new-pattern`으로 돌리지 않고 `accuracy-drop`으로 보고한다. 표본이 늘어 하한만 올라간 경우도 "실력 향상"이 아니라 `evidence-grew`로 구분한다.

런타임은 **구조화된 사유 코드와 숫자만** 낸다. 한국어 문장은 셸 i18n에서 렌더한다(코드 안 영어 규칙 + ko/en 동시 지원). 문구는 `/plain-korean-doc` 기준을 따른다.

## 7. 게이밍을 전제로 한 설계

"Who Grades the Grader?"(2026)는 스킬이 루브릭의 태그 카운터를 게이밍한 실제 사례를 잡았고, **자기 지표가 게이밍당하고 자기 심판이 오보정된다는 것을 전제하고 그것을 잡아낼 수 있는 구조 안에서만** 검증자 없는 자기개선이 성립한다고 결론짓는다. 방어책은 전부 결정론적이다.

- **에이전트는 자기 성장 수치를 턴 안에서 보지 못한다.** 보면 그것을 최적화한다.
- **퇴화 체크인 배제** — 거의 같은 질문 반복, 선택지가 사실상 하나, 같은 유형에 대한 과도한 질문율은 채점에서 제외하고 표시한다.
- 사용자가 "그냥 알아서 해"라고 물음을 거절하면 그것은 **적중이 아니라 커버리지**로 센다.
- 트리거가 행동 부류에서 나오므로(§4.5) 무엇을 물을지 자체를 고를 수 없다.

패널이 지키는 규칙 넷.

1. **무엇으로 오르지 않는지 말한다.** 사용자는 "학습률"을 대화 횟수나 저장된 기억 개수로 읽는다. 마지막 줄에서 "나비가 먼저 묻고 그 추천이 실제로 고른 것과 같았는지만 센다"고 못 박는다. 이 문장이 없으면 숫자가 임의로 보이고 무시된다.
2. **숫자 둘이 서로 다른 말을 하지 않게 한다.** 알 단계는 게이지 대신 "몇 번 더 답하면 되는지"를 보여주고, 트립와이어로 막힌 에이전트는 왜 게이지가 조금 앞에서 멈추는지 말한다. `boundDeltaPoints`는 게이지와 다른 척도라 아예 렌더하지 않는다. **애벌레 문구도 같은 이유로 고쳤다** — 애벌레는 0%일 수 있으므로 "맞히기 시작했다"고 쓰면 옆의 게이지와 모순된다.
3. **작업 유형별로 쪼개 보여준다.** "메일은 나비, SQL은 알"이 하나의 오해하기 쉬운 평균으로 뭉개지지 않는다.
4. **결정 목록을 남긴다.** 무엇을 물었고 무엇을 골랐는지 보이므로 숫자를 검산할 수 있다.

### 9.1 배선에서 확정된 두 가지 설계

**추천은 답한 뒤에 공개한다.** 목록에서 추천안을 표시하면 그것을 누르는 것이 가장 쉬운 길이 되고, 지표는 "사용자가 나비를 얼마나 아는가"가 아니라 "UI가 얼마나 순응적인가"를 재게 된다. 그래서 사용자는 **모르는 상태로 고르고**, 고른 뒤에 나비의 추측이 공개된다. 나비가 얼마나 자기를 아는지는 오히려 더 설득력 있게 전달된다 — 추측이 답 이전에 확정되었음을 사용자가 알기 때문이다.

남은 편향은 **위치**다. 모델이 추천안을 습관적으로 첫 번째에 두고 사용자가 첫 항목을 누르면 보이지 않는 표시와 같아진다. 선택지 순서를 섞고 표시 순서와 저장 순서를 매핑하는 것이 후보이나, 대화록에 모델이 말한 순서와 다르게 남는 대가가 있다.

**관측은 페르소나를 이름 부르기와 분리한다.** M4a는 학습을 `@`로 지목된 에이전트에만 붙였다. 멘션 게이트와 합치면 데드락이 된다 — 페르소나는 나비가 되기 전에는 지목될 수 없고, 체크인 없이는 나비가 될 수 없고, 지목되지 않으면 체크인할 수 없다. 그래서 `growthSubject`(관측이 귀속되는 에이전트)를 `routedAgent`(정체성을 채택하는 에이전트)와 나눈다. 평범한 턴의 관측은 페르소나에게 귀속되고, **지목은 여전히 벌어야 한다.** 게이트가 원래 지키려던 것이 그것이다.
