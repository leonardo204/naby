# 기억 바로 쓰기와 백그라운드 정리

> 이 문서가 답하는 질문 — **"사용자가 '이건 기억해'라고 말했는데 왜 또 확인을 눌러야 하는가? 그리고 쌓인 기억이 서로 어긋날 때 누가 정리하는가?"**

## 0. 배경

2026-11-09 사용자 리뷰. 요지는 두 가지다.

- 기억하라고 시킨 것까지 "기억할까요?" 버튼을 눌러야 한다. 누르지 않으면 그 기억은 쓰이지 않는다.
- 기억 안에 서로 어긋나거나 합쳐야 할 것이 보이는데 정리되지 않는다.

코드로 확인한 원인은 이렇다.

- `naby_remember`와 세션 회고가 쓰는 기억은 전부 `proposed`다. 주입은 `confirmed`만 고른다(기억 계약 §5). 그래서 확인 전의 기억은 한 턴에도 영향을 주지 못한다.
- 자동 승인(`memory.autoConfirmCorroborated`)은 기본이 꺼져 있고, 켜도 서로 다른 세션 3곳에서 같은 내용이 나와야 승인된다.
- 중복·상충 판정(4연산, hardening §3.1)은 **회고가 새 후보를 낼 때만** 돈다. 이미 쌓인 기억끼리는 비교하지 않는다. `naby_remember`로 들어온 기억도 이 비교를 거치지 않는다.
- 상충이 발견돼도 새 기억이 확정돼야 옛 기억을 대체한다. 결국 다시 확인 버튼이다.

전부 확인을 받게 한 이유는 기억 오염 방어다(전략 §7.1). 그런데 전략이 금지한 것은 "외부 콘텐츠에서 온 것의 자동 저장"과 "사용자가 열어 보고 고치고 지울 수 없는 기억"이다. 사용자가 직접 한 말까지 확인을 받게 한 것은 그 원칙보다 넓게 막은 것이다. 이 문서는 방어선을 원칙이 그어 둔 자리로 되돌린다.

## 1. 결정 사항 (사용자 결정, 2026-11-09)

1. **사용자가 직접 말한 것은 바로 저장하고 바로 쓴다.** 확인 버튼을 띄우지 않는다.
2. **나비가 추론한 것도 바로 쓴다.** 틀리면 사용자가 취소한다.
3. **외부 콘텐츠에서 온 것은 지금처럼 확인을 받는다.**
4. **기억의 중복과 상충은 백그라운드에서 정리한다.** 사용자에게는 정말 애매한 것만 묻는다.
5. **모든 기억은 적용 전에 모델 검수를 거친다.** 검수는 사용자가 그 세션에서 쓰는 모델이 한다. 뜻이 같은지도 이 모델이 판단한다. 임베딩은 쓰지 않는다.
6. **되묻기는 대화와 분리된 팝업으로 한다.** 자주 뜨면 안 된다.
7. **기다리던 제안은 한 번에 올린다**(§7). 끄는 스위치를 둔다(R8).

## 2. 근거 규칙 — 무엇이 바로 쓰이는가

바로 쓰여도 되는 **자격**은 모델이 아니라 코드가 정한다. 그 뒤 모델 검수(§2a)가 내용을 본다. 순수 함수 하나(`decideMemoryActivation`, `src/runtime/memory-gate.ts`)가 쓰기 요청마다 상태와 신뢰 등급을 정한다. `naby_remember`와 세션 회고가 같은 함수를 쓴다.

- **R1 근거 인용.** `naby_remember`에 선택 입력 `evidenceQuote`(사용자가 한 말 그대로)와 `basis`(`stated` | `inferred`)를 더한다. 회고 후보는 이미 `evidenceQuote`를 낸다.
- **R2a 하네스가 쓴 사용자 메시지 표시.** 하네스가 쓰는 사용자 역할 메시지(자율 실행의 이어 가기, 예약 작업, 작업 보고, 시작 메시지)에 `harness` 필드를 붙여 사용자 입력과 구분한다.
- **R2 인용 검사.** `evidenceQuote`는 **이 세션에서 사용자가 직접 입력한 메시지**에 부분 문자열로 있어야 한다. 회고가 쓰는 검사를 그대로 쓴다. 하네스가 넣은 사용자 역할 메시지(다른 세션의 요청, 예약 작업, 자율 실행의 이어 가기)는 사용자 입력으로 치지 않는다. 텔레그램으로 온 사용자 메시지는 사용자 입력이다.
- **R3 판정 표.** 표의 `confirmed`는 "검수를 통과하면 `confirmed`가 된다"는 뜻이다(§2a).

| 조건 | 상태 | 신뢰 등급 |
|---|---|---|
| 인용 검사 통과, `basis: stated` | `confirmed` | `user` |
| 인용 검사 통과, `basis: inferred` | `confirmed` | `artifact` |
| 인용 없음, 범위가 `project`·`session`, 외부 내용이 들어오지 않은 턴 | `confirmed` | `artifact` |
| 인용 없음, 범위가 `user` | `proposed` | `artifact` |
| 인용 없음, 외부 내용이 들어온 턴 | `proposed` | `external` |
| 인용이 사용자 메시지에 없음(지어낸 인용) | `proposed` | `artifact`. 외부 내용이 들어온 턴이면 `external` |

- **R4 외부 내용이 들어온 턴.** 그 턴에서 `naby_remember`가 불리기 전에 외부 유래 결과가 하나라도 들어왔으면 외부 내용이 들어온 턴이다. 외부 유래 결과는 웹 검색·웹 페이지·브라우저 도구, MCP 도구, 다른 프로젝트 읽기(cross-project-context), 다른 세션의 답, 참가자·서브에이전트의 출력이다. 지금 프로젝트 폴더의 파일을 읽은 것은 외부가 아니다. 판정 함수는 하나만 둔다(엔진이 턴마다 플래그를 들고 다닌다).
- **R5 사용자에 대한 사실은 사용자의 말에서 나와야 한다.** 범위 `user`의 기억은 인용 검사를 통과해야 바로 쓰인다(R3 넷째 줄). 프로젝트 파일에서 읽어 낸 관례가 사용자 전체의 선호로 굳는 것을 막는다.
- **R6 기억 계약 §4의 불변식 네 개는 그대로다.** 외부 유래는 자동 확정되지 않고, 신뢰 순서는 `user > artifact > external`이며, 외부 유래는 `user`·`org` 범위에 쓰지 못한다. `decideMemoryWrite`는 바꾸지 않는다. 바뀌는 것은 호출하는 쪽이 `confirmed`를 요청하는 조건뿐이다.
- **R7 `basis`는 순위에만 쓴다.** `stated`와 `inferred`는 모델이 고른다. 모델이 잘못 골라도 둘 다 쓰이는 기억이라, 영향은 주입 순위와 상충 정리의 우선순위에 그친다. 근거 인용은 기억 화면에 그대로 보여서 사용자가 확인할 수 있다.
- **R8 끄기.** 설정 `memory.autoApply`(기본 켬)를 끄면 모든 쓰기가 예전처럼 `proposed`로 들어가고 확인 버튼이 뜬다. 검수(§2a)와 밀린 정리(§4)도 돌지 않는다. `memory.autoConfirmCorroborated`는 없앤다. 값이 남아 있어도 읽지 않는다.
- **R9 남는 위험.** 사용자가 외부 글을 메시지에 붙여 넣으면 그 안의 문장도 인용 검사를 통과한다. 사용자가 직접 넣은 글이라 막지 않는다. 방어는 채팅의 표시(§3)와 기억 화면의 기록(§6)이다.

## 2a. 모델 검수 — 모든 기억이 거친다

근거 규칙(§2)은 "이 기억이 사용자의 말에서 왔는가"만 본다. 뜻이 맞는지, 이미 아는 것과 겹치거나 어긋나는지는 보지 못한다. 그 일을 모델이 한다.

- **R36 검수 대기.** 바로 쓰일 자격이 있는 쓰기(R3의 `confirmed` 줄)는 먼저 검수 대기로 들어간다(`status: proposed`, `review_state: pending`). 대기 중인 기억은 주입되지 않는다. R3이 `proposed`로 정한 쓰기는 검수 없이 사용자 확인을 기다린다(검수가 올릴 수 없으므로, R40).
- **R36a 같은 키, 다른 값.** 쓰이고 있는 기억과 같은 키로 다른 값이 들어오면 옛 행을 덮어쓰지 않고 옆에 둔다(키 `‹key›-2`). 검수가 끝날 때까지 옛 기억이 계속 쓰인다. 값까지 같으면 새 행을 만들지 않고 확증 관측만 더한다("이미 알고 있어요").
- **R37 언제.** 턴이 끝난 직후 백그라운드로 돈다. 그 턴에서 쓴 기억을 모아 호출 한 번으로 본다. 턴을 늦추지 않는다. 회고 후보는 회고 호출 뒤 같은 스윕에서 본다. 보통 다음 턴이 시작되기 전에 끝난다.
- **R38 어느 모델.** 그 세션의 턴이 실제로 돈 프로바이더와 모델이 검수한다. 구독으로 돌았으면 구독으로, 키로 돌았으면 그 키로 부른다. 회고와 밀린 정리(§4)처럼 세션 밖에서 도는 검수는 스윕을 깨운 턴의 모델을 쓴다. 다른 프로바이더의 키로도, 구독으로도 넘어가지 않는다. 그 턴의 백엔드를 쓸 수 없으면 검수하지 않고 대기로 둔다(`resolveJudgeBackend`보다 엄격하다).
- **R39 무엇을 묻나.** 두 가지만 묻는다.
  - **근거가 내용을 뒷받침하는가**(`supported: yes | no`). 인용이 있는 기억에만 묻는다. 인용은 "한국어로 답해 줘"인데 값이 "영어 선호"면 `no`다.
  - **이미 쓰이는 기억과의 관계.** 같은 범위에서 쓰이는 기억 목록을 주고, 새 기억과 관계가 있는 것마다 `equivalent | refines | contradicts`를 받는다. **뜻으로 판단한다.** 단어가 달라도 같은 말이면 `equivalent`다. 목록은 같은 범위 전체를 주되 200줄까지다. 넘으면 어휘 유사도 상위 60줄과 최근 60줄을 준다.
- **R39a 상충은 드물다.** `contradicts`는 한쪽을 따르면 같은 상황에서 다른 쪽을 따를 수 없을 때만 답한다. 전체 규칙과 특정 화면·대상에 대한 지시(앱 전체 팔레트와 '월간' 뱃지 색)는 상충이 아니다. 특정 지시는 예외이고 둘 다 유효하므로 관계 없음으로 답한다. `refines`도 아니다. `refines`는 새 기억이 옛 기억을 잃는 것 없이 대신할 수 있을 때만 쓴다. 애매하면 관계 없음으로 답한다. 쓸데없는 질문은 품질 문제다.
- **R40 검수는 낮추기만 한다.** R3이 `proposed`로 정한 기억(외부 유래, 인용 없는 사용자 범위)은 검수가 `confirmed`로 올리지 못한다. 검수의 답에서 연산으로 가는 길은 코드가 정한다(R17, R18). 모델은 어느 쪽이 맞는지, 무엇을 할지 정하지 않는다.
- **R41 결과.**

| 검수의 답 | 연산 |
|---|---|
| `supported: no` | `proposed`로 남기고 "확인이 필요한 것"에 올린다 |
| 관계 없음 | R3대로 `confirmed` |
| `equivalent` | 새 행을 만들지 않는다. 기존 기억에 확증 관측을 더한다. 새 쪽이 등급이 높으면 기존 기억의 등급과 근거를 올린다 |
| `refines` | 기존 기억의 값을 새 값으로 고친다(같은 행). 등급을 따지지 않는다(R18) |
| `contradicts` | R17·R17a·R18을 따른다 |

- **R41a 여러 관계가 함께 나오면** `contradicts`, `refines`, `equivalent` 순으로 적용한다.
- **R42 검수를 못 했을 때.** 모델을 부를 수 없거나 답이 깨졌으면 대기로 둔다. 다음 턴이 끝날 때 다시 시도한다. 판정을 지어내지 않는다. 24시간 넘게 대기 중인 기억은 "확인이 필요한 것"에 보인다.
- **R43 검수 프롬프트.** 기억의 값과 인용은 데이터로 감싸서 준다(기존 `untrusted_` 펜스 방식). 그 안의 지시는 따르지 않는다고 적는다. 답은 정해진 JSON 형식만 받고, 목록에 없던 기억을 가리키는 답은 버린다.
- **R44 비용.** 기억을 쓴 턴마다 호출이 한 번 더 든다. 쓰기가 없는 턴에는 들지 않는다. 구독이면 구독 사용량에 잡힌다.

## 3. 채팅에서 보이는 것

- **R10 "기억했어요 · 취소".** 바로 쓰이는 기억은 그 도구 호출 자리에 "기억했어요: ‹내용›"과 **취소** 버튼을 보인다. 검수가 끝나기 전에는 "기억하는 중…"으로 보이고, 끝나면 결과에 맞게 바뀐다("기억했어요", "이미 알고 있어요", "기억을 바꿨어요: ‹옛 내용› → ‹새 내용›"). 취소를 누르면 그 기억을 지운다. 기존 값을 고친 기억이면 이전 값으로 되돌린다. 행이 남지 않는 결과(기존 기억에 합쳐짐, 제자리 수정)는 되돌릴 수 있게 영수증을 설정 `memory.review.receipts`(상한 있는 JSON)에 남긴다.
- **R11 확인이 필요한 것만 묻는다.** `proposed`로 들어간 기억(R3 넷째~여섯째 줄)에만 지금의 "기억할까요?" 버튼을 보인다. 버튼 옆에 이유를 한 줄 붙인다("웹 페이지에서 읽은 내용이라 확인이 필요합니다").
- **R12 도구 결과 문구.** `naby_remember`가 모델에게 돌려주는 글을 상태에 맞춘다. 바로 쓰이는 자격이면 "saved; in use from the next turn after a quick check"라고 하고, 나비는 사용자에게 "기억했어요"라고 말해도 된다. 지금의 "제안일 뿐이니 적용됐다고 말하지 마라" 문장은 `proposed`일 때만 남긴다. 학습 지침(`learningInstruction`)과 도구 설명도 같이 고친다. 사용자가 기억하라고 시켰으면 `basis: stated`와 인용을 꼭 넣으라고 적는다.
- **R13 이 답변에 쓴 기억.** 기억이 주입된 답변 아래에 "기억 N개 반영"을 작게 보인다. 누르면 그 턴에 들어간 기억 목록이 뜬다. 주입 결과는 이미 턴마다 나오므로(`onMemoryInjection`) 그것을 스트림에 싣는다. 사용자가 "쓸수록 나를 안다"를 눈으로 보는 자리다.

## 4. 기억 정리 — 백그라운드

세션 회고 스윕(continuous-learning §4.3) 끝에 정리 패스를 붙인다. 타이머를 따로 만들지 않는다. 앱을 쓰는 동안에만 돌고, 지금 입력 중인 턴을 늦추지 않는다.

- **R14 밀린 기억.** 검수를 거친 적 없는 기억(`reviewed_at`이 빈 행 — 이 기능 전에 쌓인 기억과 사용자가 설정에서 고친 기억)이 대상이다. 새로 들어오는 기억은 §2a에서 이미 기존 기억 전체와 비교되므로, 밀린 것만 따라잡으면 모든 짝을 본 셈이 된다.
- **R15 검수(모델).** 스윕 한 번에 호출 한 번, 기억은 최대 30개다. 범위 키별로 묶어, 각 기억을 같은 범위의 쓰이는 기억 목록과 R39의 둘째 질문으로 비교한다. 뜻으로 판단한다. 범위가 다르면 비교하지 않는다(hardening §3.1과 같은 이유). 문체 기억(`style/` 키)은 대상에서 뺀다. 본 기억에는 `reviewed_at`을 찍는다. 대상은 `confirmed` 기억뿐이다. 학습이 꺼져 있으면(`memory.learningEnabled`) 돌지 않는다.
- **R16 한 번 본 짝은 다시 묻지 않는다.** 새 테이블 `memory_pair_verdicts(a_id, b_id, a_updated_at, b_updated_at, relation, judged_at)`에 판정을 남긴다. 어느 한쪽의 값이 바뀌면 다시 본다. 사용자가 "둘 다 유지"라고 답한 짝(R26)도 여기 남는다.
- **R17 연산(코드).** 이미 쌓인 기억 둘 사이의 판정에서 연산으로 가는 길은 정해져 있다. 새로 들어오는 기억은 R41 표를 따른다.

| 판정 | 연산 |
|---|---|
| `equivalent` | 한쪽을 남기고 다른 쪽을 대체 처리한다. 등급이 높은 쪽, 같으면 최근에 쓰인 쪽이 남는다. 확증 관측과 강도는 남는 쪽으로 합친다 |
| `refines` | 더 구체적인 쪽이 남고 다른 쪽을 대체 처리한다 |
| `contradicts` | 최신 쪽이 남고 옛 쪽을 대체 처리한다. 일시적 사실은 안정적 사실을 대체하지 못한다(hardening §3.1 그대로) |
| `unrelated` | 아무것도 하지 않는다 |

- **R17a 방금 한 말을 바꾸면 채팅에 보인다.** 사용자가 지금 대화에서 말한 기억이 옛 기억을 대체하면 채팅에 "기억을 바꿨어요: ‹옛 내용› → ‹새 내용› · 취소"가 보인다(R10).
- **R18 새 기억이 옛 기억을 덮는다.** 상충과 보완은 등급을 따지지 않고 묻지 않는다. 옛 기억이 `user` 등급이고 새 기억이 추론이어도 새 기억이 남는다. 사용자는 정리 내역과 기억 화면에서 되돌린다(R19). 일시적 사실이 안정적 사실을 대체하지 못하는 규칙(R17)과, 외부 유래 기억이 사용자 승인 없이 쓰이지 못하는 규칙(R40)은 그대로다. 사용자가 전에 "둘 다 유지"로 답한 짝은 다시 판정하지 않는다(R16).
- **R19 대체는 삭제가 아니다.** 밀려난 기억은 지금처럼 `superseded_at`·`superseded_by`가 찍혀 주입에서 빠질 뿐 남는다. 기억 화면에서 되돌릴 수 있다. 정리 패스가 한 대체에는 누가 했는지 표시한다(`superseded_reason: tidy-equivalent | tidy-refines | tidy-contradicts`).
- **R20 새 글을 쓰지 않는다.** 정리 패스는 두 기억을 합친 새 문장을 만들지 않는다. 남는 쪽의 값을 그대로 둔다. 모델이 쓴 문장이 근거 검사 없이 기억으로 들어가는 길을 만들지 않는다.
- **R21 회고의 새 후보도 같은 규칙을 따른다.** 회고 후보도 §2a 검수를 거친다. 기존 기억과 `contradicts`면, 후보가 `confirmed`가 되는 순간 대체가 바로 일어난다. "대체는 확정이 조건"(hardening §3.1)은 그대로고, 확정이 빨라졌을 뿐이다. R18은 여기에도 적용한다.
- **R22 모델이 없으면 건너뛴다.** 모델을 부를 수 없으면 정리 패스를 돌지 않는다. `reviewed_at`도 찍지 않는다. 판정을 지어내지 않는다(continuous-learning §4.9와 같은 원칙).
- **R23 기록.** 활동 로그에 `memory_review`(본 기억 수, 연산별 건수, 만든 질문 수, 쓴 모델)를 남긴다. 기억의 내용은 남기지 않는다.

## 5. 되묻기 — 대화와 분리된 팝업, 드물게

- **R24 새로 묻지 않는다.** 0.3.0부터 나비는 기억 상충을 사용자에게 묻지 않는다(R18). 근거 없이 `user` 등급 기억과 같은 키에 쓰려던 후보는 게이트가 거절하고 버린다. 이전 버전이 만든 열린 질문은 기억 화면을 열 때 R18대로 정리하고 닫는다. 질문이 쌓여 사용자가 처리해야 했던 것이 이 변경의 이유다. 아래 R25~R28은 이전 질문의 저장과 표시 규칙으로 남긴다.
- **R25 저장.** 새 테이블 `memory_questions(id, kind, a_id, b_id, candidate_json, created_at, status, answer, answered_at, shown_count, snoozed_until)`. `kind`는 `conflict`(기억 둘) 또는 `overwrite`(기억 하나와 후보 값)다. 같은 짝의 열린 질문은 하나만 둔다. 한쪽 기억이 지워지거나 대체되면 질문을 닫는다.
- **R26 팝업.** 채팅 기록에 넣지 않는다. 화면 오른쪽 아래에 뜨는 작은 패널이다. 모달이 아니다. 입력을 막지 않고, 포커스를 가져가지 않고, 턴을 멈추지 않는다.
  - ko: "기억 두 개가 서로 달라요. 어느 쪽이 맞나요?" 아래에 두 기억의 내용과 배운 날짜를 나란히 보인다.
  - 두 기억은 각각 카드 하나다. 카드 안에 내용, 배운 날짜, **이 기억 남기기** 버튼이 같이 있어 어느 버튼이 어느 기억인지 헷갈리지 않는다. 내용이 길면 네 줄로 자르고 "더 보기"를 둔다. 카드 밖에 **둘 다 유지** · 나중에를 둔다.
  - 고른 쪽이 남고 다른 쪽은 대체 처리된다. 고른 기억은 `user` 등급이 된다(사용자가 정했다). "둘 다 유지"는 그 짝의 판정을 `both-valid`로 남겨 다시 묻지 않는다.
  - 열린 질문이 더 있으면 "1/3"처럼 보인다. 하나에 답하면 다음 질문이 이어서 나온다. 사용자가 이미 답하고 있는 동안에만 몰아서 묻는다.
- **R27 드물게 뜬다.** 팝업이 스스로 뜨는 조건은 모두 맞아야 한다.
  - 보이는 탭에 돌고 있는 턴이 없고, 사용자가 입력 중이 아니다.
  - 오늘 스스로 뜬 적이 없다(하루 한 번).
  - 앱을 켠 지 5분이 지났다. 켜자마자 묻지 않는다.
  - 20초 동안 답이 없으면 스스로 접혀 설정 진입점의 작은 점으로 남는다. 점을 누르면 다시 열린다.
  - "나중에"를 누르거나 두 번 연달아 답 없이 접힌 질문은 7일 동안 스스로 뜨지 않는다(`snoozed_until`). 그동안에도 기억 화면에는 있다.
  - 임시 세션(`noLearn`)만 열려 있을 때와 빠른 진화 세션 중에는 뜨지 않는다. 텔레그램으로는 묻지 않는다.
  - 구현의 정의: "하루"는 기기의 달력 날짜다. "돌고 있는 턴"은 지금 프로젝트에 진행 중인 세션이 있는 것이다. "입력 중"은 포커스가 있는 입력 칸에 글이 있는 것이다. 임시·빠른 진화 여부는 지금 보이는 탭의 세션으로 본다. "나중에"를 누르면 이어지던 질문도 거기서 멈춘다.
- **R27a 답하지 않아도 일은 계속된다.** 열린 질문의 두 기억은 지금 상태 그대로 쓰인다(둘 다 쓰이던 것이면 둘 다, 후보는 쓰이지 않는다). 주입 순위가 사용자가 말한 것과 최근 것을 앞에 둔다.
- **R28 신뢰 지표와 섞지 않는다.** 이 팝업은 `naby_checkin`이 아니다. 답이 신뢰 원장에 들어가지 않는다(`pendingMemory.ts`가 체크인을 재사용하지 않는 것과 같은 이유).

## 5a. 3줄을 넘는 기억은 요약으로 보여 준다

- **R45 요약 한 줄.** 3줄을 넘는 기억은 어느 화면에서든 한 줄 요약을 먼저 보여 준다. 요약은 `memory_items.summary`에 저장하고 화면 표시에만 쓴다. 턴에 주입하지 않고 검수·정리 비교에도 쓰지 않는다. 스키마 버전은 17이 된다.
- **R46 대상.** 값이 120자를 넘거나 4줄 이상인 기억이다. 대체된 기억도 "바뀌었어요" 표시에 쓰이므로 포함한다. 확인 대기, 쓰이는 기억, 대체된 기억 순으로 만든다. 검수 대기 중인 기억은 검수가 끝난 뒤 만든다. 외부 유래(`external`)는 요약하지 않는다. 외부 글이 요약을 조작하면 사용자가 다른 내용을 보고 승인하게 되기 때문이다.
- **R47 표시.** 대상 화면은 채팅의 기억 표시("기억할까요?", "기억했어요", "기억을 바꿨어요"), "기억 N개 반영" 목록, 설정의 "확인이 필요한 것"과 "최근 배운 것", 기억 탐색 화면이다. 요약이 없으면(아직 안 만들었거나 외부 유래) 원문을 3줄로 자른다. 카드 화면에는 "원문 보기"를 두고, 채팅에서는 툴팁으로 전체를 본다. 기억 수정은 언제나 원문으로 한다.
- **R48 생성.** 턴 뒤 검수와 회고 때 세션 모델이 80자 이내로 만든다(R38). 대상이 없으면 호출하지 않고, 한 번에 20개까지 만든다. 쌓여 있던 긴 기억도 이 호출로 차례대로 만든다. 값은 데이터로 감싸서 준다(R43). 모델을 못 부르거나 답이 깨지면 원문을 보이고 다음에 다시 시도한다. 값이 바뀌면 요약을 지운다. `memory.autoApply`가 꺼져 있으면 턴 뒤 검수가 돌지 않으므로 요약도 만들지 않는다.

## 6. 설정의 기억 화면

승인함에서 기록으로 바꾼다. 기존 브라우저(검색, 범위·상태 필터, 편집, 삭제, 대체 되돌리기)는 그대로 둔다.

- **R29 맨 위에 두 묶음을 둔다.**
  - **확인이 필요한 것** — 열린 질문(§5)과 `proposed` 기억. 검수를 기다리는 중인 기억은 넣지 않는다(24시간이 넘으면 넣는다, R42). 없으면 묶음을 숨긴다.
  - **최근 배운 것** — 최근 7일에 바로 쓰이기 시작한 기억과 정리 패스가 한 일("‹A›와 ‹B›를 합쳤습니다", "‹A›를 ‹B›로 바꿨습니다"). 줄마다 취소·되돌리기 버튼이 있다.
- **R30 근거를 보인다.** 기억 줄을 펴면 근거 인용, 배운 세션, `stated`·`inferred` 구분이 보인다.
- **R31 설정 줄.** "반복 확인된 기억 자동 승인" 토글을 없애고 "배운 것을 바로 쓰기"(`memory.autoApply`) 토글을 둔다. 설명: "끄면 나비가 배운 것을 내가 확인한 뒤에만 씁니다. 웹 페이지 같은 외부 내용에서 배운 것은 켜져 있어도 항상 확인을 받습니다."
- **R32 받은편지함.** 지금의 "기억 제안" 항목은 "확인이 필요한 것"이 있을 때만 나타난다.
- **R29a 최근 배운 것은 팝업으로 연다.** 나비가 알아서 한 일이라 사용자가 볼 필요가 없다. 기억 화면에 목록을 두지 않고 "전체 보기", "문체 기억 보기"와 나란한 버튼에서 팝업으로 연다. 항목이 없으면 버튼을 숨긴다. 줄마다 되돌리기는 그대로다.

## 7. 기존 기억의 이전

- **R33 기다리던 제안.** 업그레이드 뒤 첫 실행에 한 번, `artifact` 등급의 `proposed` 기억 중 만든 지 90일이 안 된 것을 검수 대기(R36)로 넣는다. 검수를 통과하면 `confirmed`가 된다. 근거 규칙(§2)은 적용하지 않는다(그때는 인용을 받지 않았다). 사용자가 기억하라고 시키고 버튼을 지나친 것들이 여기 있다. 올린 기억은 "최근 배운 것"에 한 묶음으로 나타나 한 번에 훑고 지울 수 있다. 90일이 넘은 것과 `external` 등급은 그대로 "확인이 필요한 것"에 남는다.
- **R34 이전 표시.** 이전을 한 번 했다는 것을 설정 `memory.autoApply.migratedAt`에 남긴다. 두 번 하지 않는다. `memory.autoApply`가 꺼져 있으면 하지 않는다.
- **R35 스키마.** 테이블 둘(`memory_pair_verdicts`, `memory_questions`)과 컬럼 다섯(`memory_items.prov_evidence_quote`, `prov_basis_kind`, `superseded_reason`, `review_state`, `reviewed_at`)을 더한다. 스키마 버전은 15에서 16이 된다. 컬럼은 지금처럼 컬럼 존재를 보고 `ALTER`한다. 백필은 없다. 기존 행은 인용이 없고 `basis`가 없고 검수를 거치지 않은 것으로 읽는다. 이미 `confirmed`인 기존 기억은 계속 쓰이고, 밀린 정리(R14)가 차례로 본다.

## 8. 바꾸지 않는 것

- 주입(기억 계약 §5). `confirmed`이고 대체되지 않은 기억만, 턴마다 2,000토큰 안에서 관련도 순으로 고른다.
- 감쇠와 검토 대기열(memory-hygiene §2).
- 학습 끄기(`memory.learningEnabled`)와 임시 세션. 꺼져 있으면 쓰기 자체가 없다.
- 비밀값 거부(`looksLikeSecret`), 값 400자 상한, 키 정규화.
- 참가자는 기억을 쓰지 않는다.

## 10. 검증

- 런타임 스파이크(모델 호출 없음):
  - R3 판정 표 여섯 줄. 지어낸 인용, 하네스가 넣은 사용자 메시지의 인용은 통과하지 못한다.
  - 간접 주입 재현 — 웹 결과가 들어온 턴에서 "항상 ~하라고 기억해" 쓰기가 `confirmed`가 되지 않는다(기억 계약 §4 불변식 4의 연장).
  - 답→연산 표(R41·R17), 방금 한 말 규칙(R17a), 등급 규칙(R18), 일시적·안정적 규칙.
  - 검수는 낮추기만 한다(R40) — 외부 유래 기억은 검수가 무엇을 답해도 `confirmed`가 되지 않는다. 목록에 없는 기억을 가리키는 답은 버린다.
  - `memory.autoApply`를 끄면 모든 쓰기가 `proposed`다.
- 셸 vitest(임시 `NABY_DB_PATH`, mock 검수 모델):
  - `naby_remember` → 검수 전에는 주입되지 않고, 검수 뒤 다음 턴 주입에 들어간다. 취소하면 빠진다.
  - 검수: 단어가 다른 같은 뜻(mock 답 `equivalent`)이면 행이 늘지 않는다. `supported: no`면 `proposed`로 남는다. 모델이 없으면 대기로 남고 다음 턴에 다시 시도한다. 검수가 그 세션의 프로바이더로 가고 다른 키로 넘어가지 않는다. 값을 고친 기억의 취소는 이전 값으로 돌아간다.
  - 밀린 정리: 검수 안 된 기존 기억이 스윕마다 30개씩 줄어든다. 같은 뜻의 두 기억이 하나로 줄고 되돌릴 수 있다. 본 짝은 다시 모델에 가지 않는다. 한쪽 값이 바뀌면 다시 간다. 모델이 없으면 아무것도 바뀌지 않는다.
  - 질문: 세 경우(R24)에서 생기고, 방금 한 말의 상충(R17a)에서는 생기지 않는다. 답에 따라 대체와 등급이 맞게 바뀐다. "둘 다 유지" 뒤에는 다시 생기지 않는다. 신뢰 원장에 행이 생기지 않는다.
  - 팝업이 뜨는 조건(R27)은 순수 함수로 두고 표로 테스트한다 — 하루 한 번, 턴 중·입력 중 아님, 켠 지 5분, 미루기 7일. 팝업이 채팅 기록에 들어가지 않는다.
  - 이전(R33): 한 번만 돈다. 90일 넘은 것과 `external`은 남는다.
- 앱에서 직접: "앞으로 커밋 메시지는 영어로 써 줘, 기억해"라고 말하고, 버튼을 누르지 않은 채 새 대화에서 커밋 메시지를 시켜 본다. 그다음 "아니다, 한국어로 써 줘"라고 말하면 팝업 없이 "기억을 바꿨어요"가 보이는지, 기억 화면에서 영어 쪽이 대체됐는지 본다.

## 11. 범위 밖과 미결정

- **검수 모델을 따로 고르기.** 검수는 세션 모델로 고정한다(R38). 큰 모델을 쓰는 세션에서는 검수도 그 모델로 돈다. 비용이 문제가 되면 작은 모델로 내리는 설정을 나중에 둔다.
- **범위가 200줄을 넘는 경우.** 목록을 줄여서 주므로(R39) 줄 밖의 중복은 놓칠 수 있다. 임베딩은 쓰지 않는다.
- **오래된 기억 되묻기.** 90일 검토 대기열을 질문 팝업으로 올리는 일은 하지 않는다. 팝업이 잦아지는지 먼저 본다.
- **숫자들.** 밀린 정리 30개, 목록 200줄, 팝업 하루 한 번·20초·미루기 7일, 최근 배운 것 7일, 이전 90일은 쓰면서 조정한다.
