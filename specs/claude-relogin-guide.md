# Claude 로그인 만료 안내

> 이 문서가 답하는 질문 — **"Claude 로그인이 만료돼 턴이 실패하면, 사용자는 어디를 눌러 무엇을 하면 되는가?"**

## 0. 지금 무엇이 문제인가

2026-11-03 사용자 제보. Claude 턴이 다음 오류로 실패했다.

```
Claude Code returned an error result: Failed to authenticate: OAuth session expired and could not be refreshed
```

화면에서 세 가지가 어긋났다.

1. **분류가 틀렸다.** `claudeSdkFailureCode`(src/engines/error-codes.ts)는 `not logged in`, `please run /login`, `invalid api key`, `oauth token has expired`만 로그인 문제로 본다. 이 문구는 어디에도 걸리지 않아 `ENGINE_THREW`가 되고, 알림은 "AI 응답 중 오류: …" 영어 원문을 그대로 보여 줬다.
2. **안내가 실제 화면과 다르다.** 로그인 문제로 분류됐더라도 지금 문구는 "Claude 칩에서 '로그인'을 누르라"고 한다. 그런데 토큰 갱신만 실패한 경우 `claude auth status`는 여전히 로그인됨으로 답한다. 칩 메뉴에는 "로그아웃"만 있고 "로그인"이 없다. 사용자는 로그아웃 → 로그인 순서를 스스로 알아내야 한다.
3. **"자세히"가 없는데 "자세히"를 보라고 한다.** 실패 알림의 아래 줄 "자세히에서 전체 내용을 볼 수 있습니다"는 "자세히" 버튼이 없을 때(제목 줄이 전문일 때)도 나온다.

말풍선에도 같은 영어 원문("Failed to authenticate: …")이 답처럼 남았다. CLI가 오류를 assistant 메시지(model `<synthetic>`)로도 보내기 때문이다.

## 1. 요구사항

### 1.1 분류

- **R1.** 다음 문구도 `authentication_failed`로 분류한다. 대소문자는 가리지 않는다.
  - `failed to authenticate`
  - `oauth session expired`
  - `could not be refreshed`(oauth나 token과 함께 나올 때)
  - `oauth token (has )?expired`(기존), `token expired`
- **R2.** 같은 문구가 SDK의 assistant 메시지로 올 때(`message.model === '<synthetic>'`이고 텍스트가 R1에 걸릴 때)는 말풍선 텍스트로 내보내지 않는다. 대신 `authentication_failed` 코드의 error 이벤트 하나로 바꾼다. 같은 턴에 뒤이어 throw가 와도 알림은 하나만 보인다(마지막 error가 이긴다는 기존 규칙 그대로).

### 1.2 실패 알림 안의 로그아웃 → 로그인 안내

`authentication_failed` 코드로 실패한 턴의 알림(RunFailureNotice)은 일반 오류 대신 **안내 카드**를 보여 준다. 카드는 사용자가 직접 할 일을 순서대로 알려 준다. **naby가 대신 로그아웃하거나 로그인하지 않는다.** 로그아웃과 로그인은 사용자가 Claude 칩에서 직접 누른다.

카드 내용(ko):

> **Claude 로그인이 만료되었습니다.** 아래 순서대로 다시 로그인하면 이어서 쓸 수 있습니다.
>
> 1. 채팅 위의 **Claude 칩**(계정 이메일)을 누릅니다.
> 2. 메뉴에서 **로그아웃**을 누릅니다.
> 3. 칩에 나타나는 **로그인**을 누르고, 열리는 브라우저에서 로그인을 마칩니다.
> 4. 돌아와서 아래 **다시 보내기**를 누릅니다.
>
> 브라우저가 열리지 않으면 터미널에서 다음 명령을 실행하세요: `claude auth login` (복사)

- **R3. 진행 표시.** 카드는 Claude 로그인 상태를 지켜보며 단계마다 표시만 바꾼다. 사용자 대신 어떤 액션도 부르지 않는다.
  - 상태가 `signed-out`이 되면 2단계에 완료 표시(✓)를 한다.
  - 그 뒤 `signed-in`이 되면 3단계에 완료 표시를 하고, 4단계의 "다시 보내기"를 강조한다.
  - 상태는 Claude 칩이 읽는 것과 같은 값을 쓴다. 칩이 로그아웃·로그인 후 다시 읽은 결과를 카드도 받는다. 카드가 따로 폴링하지 않는다.
  - 지금 답하는 계정 기준이다. 따로 둔 계정이면 1단계 문구의 칩이 그 계정을 보여 준다.
- **R3a. 칩 강조.** "Claude 칩"이라는 말만으로는 어디인지 모를 수 있다. 안내 카드가 떠 있는 동안 Claude 칩을 눈에 띄게 한다.
  - 칩 둘레에 브랜드 색 링이 천천히 깜빡인다(펄스, 약 1.5초 주기). 칩 자리나 크기는 바뀌지 않는다.
  - 3단계까지 끝나(`signed-in`으로 돌아오면) 강조를 멈춘다. 카드를 닫거나 다음 메시지를 보내도 멈춘다.
  - 칩 메뉴를 연 동안은 링을 멈추고, 메뉴 안에서 지금 눌러야 할 항목(로그아웃, 그다음 로그인)에 같은 색 테두리를 준다.
  - 카드 1단계의 "Claude 칩" 글자를 누르면 칩 메뉴가 열린다. 마우스를 올리면 칩 링이 한 번 더 진하게 반짝인다.
  - `prefers-reduced-motion`이면 깜빡이지 않고 링을 고정해서 보인다.
- **R4. 같은 판정을 한 곳에.** 칩과 카드는 로그인 상태를 같은 출처에서 읽는다. 사본을 두지 않는다(CLAUDE.md "판정 함수 사본 금지").
- **R5. 다시 보내기.** "다시 보내기"는 실패한 턴의 사용자 메시지를 그대로 다시 보낸다. 기존 `handleResendMessage`를 쓴다. 상태가 아직 `signed-in`으로 바뀌지 않았어도 누를 수 있다(상태 읽기가 늦을 수 있다). 보낼 메시지를 찾지 못하면 버튼 대신 "메시지를 다시 보내 주세요."를 보인다.
- **R6.** (삭제) 칩 갱신은 칩 자신의 로그아웃·로그인 동작이 이미 한다.
- **R7. 닫기.** 카드의 ✕와 "다음 메시지를 보내면 사라진다"는 기존 규칙은 그대로다.
- **R8. 원문 보존.** SDK 원문은 카드 아래 "자세히"로 접어 둔다(기본 접힘).

### 1.3 "자세히" 안내 문구

- **R9.** 실패 알림 아래 줄은 "자세히" 버튼이 있을 때만 "자세히에서 전체 내용을 볼 수 있습니다."를 붙인다. 없으면 "다음 메시지를 보내면 사라집니다."만 보인다. 키를 둘로 나눈다.

### 1.4 문구

- `chat.runError.claudeSignIn`(코드 문구)은 "Claude 로그인이 만료되었습니다. Claude 칩에서 로그아웃한 뒤 다시 로그인해 주세요."로 바꾼다. 안내 카드가 그려지지 않는 곳(텔레그램 등 텍스트만 가는 곳)에서도 뜻이 통하도록 "Claude 칩 → 로그아웃 → 로그인" 경로를 덧붙인 텍스트 문구를 따로 둔다.
- UI 한국어는 `~합니다` 체를 쓴다.

## 3. 검증

- 런타임: `claudeSdkFailureCode`가 제보 문구와 R1 문구를 `authentication_failed`로, 무관한 문구는 `ENGINE_THREW`로 둔다. synthetic 메시지 변환은 mock SDK 메시지로 확인한다(실제 모델 호출 금지).
- 셸: 카드 단계별 정적 렌더(ko/en), 진행 표시 순수 함수(signed-in → signed-out → signed-in 순서로 단계 표시, 처음부터 signed-out인 경우, 카드가 로그아웃·로그인 액션을 부르지 않음을 소스 단언으로), R9 문구 분기, 소스 단언으로 다시 보내기 연결.
- 앱에서 직접: 실제 만료 상태를 만들기 어렵다. 칩에서 로그아웃한 뒤 보내 보고, 카드 안내대로 로그인해 단계 표시와 다시 보내기가 이어지는지 확인한다.

## 4. 범위 밖

- 토큰 자동 갱신. 갱신은 Claude Code가 하고, naby는 로그인 정보를 읽거나 저장하지 않는다(claude-multi-account §2).
- 보내기 전에 만료를 미리 막는 점검. 칩이 이미 상태를 보여 준다.
