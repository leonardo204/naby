# 단기·장기·고정 기억

> 이 문서가 답하는 질문 — **"나비는 무엇을 얼마나 오래 기억하고, 무엇을 절대 잊지 않는가?"**

## 0. 배경

2026-11-10 사용자 결정. 요지는 세 가지다.

- 기억을 사람처럼 단기와 장기로 나눈다. 둘을 가르는 기준과 장기 기억의 보존 기간을 둔다.
- 기억을 무한정 갖고 있지 않는다.
- 사용자가 여러 번 강조한 기억은 늘 참조하는 기억으로 두고 바뀌지 않게 한다.

지금 나비에는 수명이 없다. 강도 기반 감쇠(MemoryBank 곡선, `R = exp(-t / (S × 30일))`)가 있지만 동점 순서만 바꾼다. 90일 넘게 안 쓰인 기억도 "오래됨" 필터에 올라갈 뿐 지워지지 않는다. memory-hygiene §2.2는 자동 삭제를 일부러 거절했다. 이 문서는 그 결정을 사용자 결정에 따라 뒤집는다(§4).

## 1. 조사 요약

학술 자료, 업계 제품, 오픈소스에서 확인한 것이다. 출처는 §10에 있다.

- **승격은 반복과 간격이 정한다.** 간격을 두고 반복된 것이 오래 남는다(간격 효과, Cepeda 2006). Claude Code도 같은 정정이 두 번 나오면 그때 규칙 파일에 적으라고 안내한다. 같은 자리에서 다섯 번보다 다른 날 두 번이 강한 신호다.
- **감쇠는 사용 이력의 함수다.** ACT-R의 기저 활성도와 MemoryBank의 망각 곡선 모두 쓰일수록 천천히 잊는다. 나비는 이미 MemoryBank 곡선을 쓰고 있다.
- **업계는 저장소를 나누지 않고 상태로 다룬다.** 단기·장기 이분법만으로는 에이전트 기억을 다 담지 못한다는 비판도 있다(2025 서베이). 그래서 테이블은 하나로 두고 단계 컬럼을 더한다.
- **망각은 숨김 다음에 삭제다.** Mem0은 만료된 기억을 숨기고, Zep/Graphiti는 모순된 사실을 무효화할 뿐 지우지 않는다. 나비도 보관 기간을 거쳐 지운다.
- **늘 주입되는 층을 두는 쪽과 두지 않는 쪽이 갈린다.** Letta(코어 블록)와 Claude Code(CLAUDE.md, 자동 메모리 앞 200줄)는 두고, Mem0과 Zep은 검색만 한다. 두는 쪽은 모두 상한이 있다. 지시가 길수록 준수율이 떨어진다는 공식 안내도 있다.
- **불변은 "에이전트가 못 바꾼다"는 뜻이다.** Letta의 `read_only`는 에이전트의 편집만 막고 사람은 고칠 수 있다.
- **보존 기간 수치는 공개된 것이 없다.** Mem0만 감쇠 배율 구간을 공개한다. 아래 기간은 모두 나비가 정한 설정값이다.

## 2. 세 단계

| 단계 | 코드 | 무엇인가 | 주입 | 수명 |
|---|---|---|---|---|
| 단기 | `short` | 막 배워서 아직 한 번만 확인된 기억 | 관련 있으면 주입 | 14일 안에 장기로 오르지 못하면 보관 |
| 장기 | `long` | 다시 확인됐거나 사용자가 직접 말한 기억 | 관련 있으면 주입 | 마지막으로 쓰인 뒤 90일, 자주 쓰인 기억은 최대 1년 |
| 고정 | `anchored` | 사용자가 여러 번 강조한 기억 | **매 턴 항상 주입** | 없음. 나비가 바꾸지 않는다 |

- **R1 단계는 쓰이는 기억에만 붙는다.** `memory_items.memory_tier`(v18)로 둔다. 사용자 확인을 기다리는 기억(`proposed`)과 검수 대기 기억은 단계가 없다. 쓰이기 시작하는 순간 단기로 들어간다(§3의 조건을 이미 채웠으면 바로 그 단계다).
- **R2 단기 기억도 바로 쓰인다.** 단기와 장기의 차이는 수명이지 주입 여부가 아니다. "말하면 바로 쓴다"(memory-auto-apply)를 지킨다.
- **R3 세션 범위 기억과 일시적 사실은 늘 단기다.** `scope: session`은 세션과 함께 끝나는 기억이고, `volatility: transient`("이번 주는 휴가")는 오래 가지 않을 사실이다. 둘은 장기로 오르지 않는다.
- **UI 이름.** 단기는 "최근 기억", 장기는 "기억", 고정은 "고정 기억"이다. `core`는 Letta에서 에이전트가 고칠 수 있는 블록을 뜻해 피했다. `pinned`는 사용자가 직접 누른 것처럼 읽혀 자동 승격과 맞지 않는다.

## 3. 승격 — 코드가 정한다

승격은 모델 판단이 아니라 관측으로 정한다. 같은 입력이면 같은 결과가 나오고 스파이크로 검증할 수 있다. 판정은 턴 뒤 검수와 회고 때 백그라운드에서 한다.

- **R4 단기 → 장기.** 하나라도 맞으면 오른다.
  - 사용자가 직접 말했다(`basisKind: stated`, 인용 검사 통과). "기억해"라고 말한 것을 단기로 두지 않는다.
  - **서로 다른 날, 서로 다른 세션 2곳 이상**에서 같은 기억이 확인됐다. 확증 관측(corroboration)과 검수의 `equivalent` 병합이 이 수를 센다. 같은 세션 안의 반복은 한 번으로 센다.
  - **서로 다른 날, 서로 다른 세션 2곳 이상**에서 주입됐고 그 사이에 취소·대체되지 않았다.
- **R5 장기 → 고정.** 하나라도 맞으면 오른다.
  - **사용자가 서로 다른 세션 3곳 이상에서 같은 내용을 직접 말했다.** 세는 것은 R4의 확증 중 `stated`이고 인용 검사를 통과한 것뿐이다. 나비의 추론은 세지 않는다.
  - 사용자가 "항상 기억해", "이건 고정해"처럼 **명시적으로 요청했다.** `naby_remember`에 `pin: true`와 사용자의 말(인용)을 함께 넘기고, 인용 검사를 통과해야 한다. 인용이 없거나 검사에 실패하면 장기 기억으로만 남는다.
  - 사용자가 기억 화면에서 "고정"을 눌렀다.
- **R6 고정 알림.** 명시적 요청으로 고정되면 "고정했어요: ‹요약› · 취소"가 보인다. 자동으로 고정되면 채팅에 "자주 말씀하신 걸 고정했어요: ‹요약› · 취소"가 보인다. 묻지 않고 알린다(memory-auto-apply와 같은 방식). 취소하면 장기로 돌아가고, 같은 기억은 다시 자동 고정하지 않는다.
- **R7 외부 유래는 오르지 않는다.** `external` 등급 기억은 사용자가 승인해도 고정되지 않는다. 사용자가 직접 "고정"을 누른 경우만 예외다.

## 4. 보존 기간과 망각

- **R8 단기 보존.** 단기 기억은 쓰이기 시작한 지 **14일** 안에 장기로 오르지 못하면 보관된다. 세션 범위 기억은 세션이 끝나고 7일 뒤 보관된다. 일시적 사실은 마지막으로 쓰인 뒤 14일이 지나면 보관된다.
- **R9 장기 보존.** 장기 기억은 마지막으로 쓰인 뒤 **`min(90일 × S, 365일)`** 이 지나면 보관된다. `S`는 지금의 강도(1~12)다. 한 번 쓰인 기억은 90일, 자주 쓰인 기억은 길게 가지만 1년을 넘지 않는다.
- **R10 강도는 하루에 한 번만 오른다.** 지금은 주입될 때마다 강도가 1씩 오른다. 이러면 한 대화에서 열 번 쓰인 기억이 열 달을 번다. 간격 효과에 맞춰 같은 날의 여러 번은 한 번으로 센다.
- **R11 보관은 삭제가 아니다.** 보관된 기억(`archived_at`)은 주입되지 않고, 검수·정리 비교에도 쓰이지 않는다. 기억 화면의 "보관됨"에서 30일 동안 되살릴 수 있다. 되살리면 장기 기억으로 돌아가고 시계가 다시 시작된다.
- **R12 보관 30일 뒤 지운다.** 행을 지우고 확증 관측, 짝 판정, 요약도 함께 지운다. 사용자가 "기억을 무한정 가지고 있을 필요는 없다"고 정했다. memory-hygiene §2.2의 "자동 삭제 거절"을 이 규칙으로 대신한다.
- **R13 조용히 정리한다.** 보관과 삭제는 묻지 않고 알리지도 않는다. 기억 화면의 "최근 배운 것" 팝업에 하루치를 "기억 N개를 보관했어요"로 한 줄 남긴다.
- **R14 대체된 기억도 같다.** 새 기억에 밀려난 기억(`superseded_at`)은 30일 동안 되돌릴 수 있고, 그 뒤 지운다.

## 5. 고정 기억

- **R15 매 턴 주입.** 고정 기억은 관련도와 상관없이 매 턴 맨 앞에 주입된다. 사용자 범위 고정 기억은 나비를 거치는 모든 프로젝트에, 프로젝트 범위 고정 기억은 그 프로젝트에만 들어간다. 주입은 런타임(`session.ts`)에서 하므로 엔진과 상관없이 같다.
- **R16 예산.** 고정 기억은 기억 주입 예산(2,000토큰) 안에서 **최대 500토큰, 20개**까지 쓴다. 남는 예산은 지금처럼 관련도 순으로 채운다. 3줄을 넘는 고정 기억은 요약(memory-auto-apply §5a)이 아니라 원문을 넣는다. 요약은 표시용이다.
- **R17 가득 차면 오르지 않는다.** 자리가 없으면 R5를 채운 기억도 장기로 남고 "고정 후보"로 표시된다. 기억 화면 "확인이 필요한 것"에 "고정 기억이 가득 찼어요"가 보인다. 기존 고정 기억을 자동으로 내리지 않는다.
- **R18 나비는 고정 기억을 바꾸지 않는다.** 검수, 정리 패스, "새 기억이 옛 기억을 덮는다"(memory-auto-apply R18) 어느 것도 고정 기억을 대체·보완·병합하지 못한다. 감쇠와 보관도 적용하지 않는다.
- **R19 고정 기억과 어긋나는 새 기억.** 새 기억은 따로 저장되지만 주입에서는 고정 기억이 이긴다. 채팅에 "고정 기억 ‹요약›과 달라서 고정 기억대로 할게요 · 새 내용으로 바꾸기"가 보인다. 버튼을 누르면 고정 기억의 값을 새 내용으로 바꾼다. 묻는 팝업은 띄우지 않는다.
- **R20 사람은 언제든 고친다.** 기억 화면에서 고정 기억을 편집하거나 고정을 풀 수 있다. 고정을 풀면 장기 기억이 되고 시계가 다시 시작된다.

## 6. 기억 화면

- 요약 줄에 단계별 개수를 보인다: 고정 N · 기억 N · 최근 N.
- 고정 기억은 맨 위 별도 묶음이다. 줄마다 편집과 고정 풀기가 있다.
- 기억 탐색에 단계 필터와 "보관됨" 필터를 더한다. 보관된 기억에는 "되살리기"와 남은 날짜가 있다.
- 장기 기억 줄에 "고정" 버튼을 둔다.

## 7. 기존 기억의 이전 (v18)

- **R21 단계 부여.** 쓰이는 기억마다 §3 조건으로 단계를 정한다. 사용자 등급이고 `stated`인 기억, 서로 다른 세션 2곳 이상에서 확증된 기억은 장기다. 나머지는 단기다. 이전으로는 고정 기억이 생기지 않는다. 과거 기록에는 강조 횟수가 없기 때문이다.
- **R22 첫 보관은 30일 유예.** 업데이트 당일에 오래된 기억이 한꺼번에 사라지지 않도록, 이전 뒤 30일 동안은 보관하지 않는다. 기억 화면에 "30일 뒤부터 오래 안 쓴 기억을 보관해요"를 한 번 보인다.
- **R23 강도는 그대로 둔다.** 지금까지 쌓인 강도는 유지한다. R10은 이후부터 적용한다.

## 8. 바꾸지 않는 것

- 쓰기 게이트와 신뢰 등급(user > artifact > external), 외부 유래 기억은 사용자 승인 없이 쓰이지 않는 규칙.
- 모델 검수, "새 기억이 옛 기억을 덮는다"(고정 기억 제외), 요약.
- 관련도 순위 계산. 단계는 순위에 쓰지 않는다. 고정 기억만 순위 밖에서 먼저 들어간다.

## 9. 미결정

- **보존 기간 수치.** 단기 14일, 장기 90일·최대 1년, 보관 30일로 확정했다. 공개된 업계 수치가 없어 정한 값이므로 설정값으로 두고 실사용으로 조정한다.
- **보관 기억의 내보내기.** 지우기 전에 파일로 남길지 정하지 않았다.

## 9a. 구현에서 정한 것 (0.3.0)

스펙의 규칙은 모두 구현했다. 아래는 스펙이 열어 둔 부분을 어떻게 정했는지와, 스펙 문장과 다르게 간 곳이다.

### 스키마 v18

`memory_items`에 컬럼 8개를 더했다: `memory_tier`, `tier_since`(그 단계에 들어온 시각, 보존 기간의 기준), `archived_at`, `anchor_origin`(auto · explicit · user), `anchor_blocked`(R6 취소 뒤 자동 고정 금지), `anchor_candidate`(R17 고정 후보), `pin_requested`(R5 명시적 요청이 검수를 기다리는 중), `injection_log`. `memory_observations`에는 `stated`를 더했다. 모두 v10~v17과 같이 컬럼이 없을 때만 `ALTER`한다.

- **주입 기록은 테이블이 아니라 컬럼이다.** R4의 "서로 다른 날, 서로 다른 세션 2곳에서 주입"은 단기 기억에만 필요하다. 그래서 세션마다 첫 주입 시각 하나씩, 최대 8개를 JSON으로 `injection_log`에 둔다. 값이 실질적으로 바뀌면 확증 관측과 함께 지운다.
- **`stated`는 확증 관측에 붙는다.** 쓰기에 `basisKind: stated`와 인용(`evidenceQuote`)이 함께 있으면 그 세션의 관측을 `stated`로 표시한다. 인용은 검사를 통과해야만 저장되므로(memory-auto-apply R30) 인용이 있다는 것 자체가 검증이다. 한 세션에서 한 번이라도 그랬으면 그 세션은 끝까지 `stated`로 센다.
- **"날"은 이 컴퓨터의 달력 날짜다.** R4와 R10 모두 `startOfLocalDay`로 하루를 자른다. SQLite 쪽도 경계 시각을 JS에서 계산해 넘기므로 두 드라이버가 같은 답을 낸다. 확증 관측은 세션당 한 행이고 시각은 그 세션의 마지막 동의 시각이다.

### 단계에 들어가는 순간 (R1~R3)

행이 `confirmed`가 되는 모든 길(쓰기, 사람의 확인, 검수 통과)에서 스토어가 `initialMemoryTier`로 단계를 붙인다. 사용자 등급이면서 `stated`면 장기, 나머지는 단기다. 세션 범위와 일시적 사실은 늘 단기다. 고정은 이 순간에 붙이지 않는다. 고정은 예산을 확인해야 하고(R16) 알림이 따라가야 해서(R6) `anchorMemory`가 따로 한다.

### 승격 (R4~R7)

순수 함수 `decideTierPromotion`이 판정하고, 기억 작업의 `promote` 작업이 실행한다. 검수와 회고가 끝날 때마다 뒤따라 대기열에 들어가고, 기억 프로세스가 시작될 때도 한 번 돈다.

- 단기 기억이 이미 R5를 채웠으면 한 번에 장기를 거쳐 고정까지 오른다.
- 명시적 요청(`naby_remember`의 `pin: true`)은 인용 검사를 통과한 `stated` 쓰기에서만 받는다. 그 밖의 경우 도구 결과에 `pin: "unverified"`를 돌려주고 장기 기억으로만 남는다. 검수를 기다리는 행이면 `pin_requested`를 켜 두었다가 검수가 확인하는 순간 고정한다. 검수가 같은 내용의 기존 행에 합치거나 기존 행을 고치면 요청도 그 행으로 옮긴다.
- 예산이 차 있으면 나비의 고정(auto · explicit)은 장기로 두고 `anchor_candidate`를 켠다. 사용자가 누른 고정은 `anchored-full` 오류로 거절하고 화면에 "고정 기억이 가득 찼어요"를 보인다.
- 예산은 그 기억과 한 턴에 같이 들어갈 고정 기억만 센다. 사용자 범위 고정 기억 전부와 같은 범위 키의 고정 기억이다.
- 고정을 취소하거나(R6) 사용자가 풀면(R20) 장기로 돌아가고 `anchor_blocked`가 켜진다. 같은 기억을 사용자가 다시 고정하면 이 표시는 꺼진다.

### 고정 알림 (R6) — 스펙과 다른 곳

스펙은 자동 고정 알림을 "채팅에" 보인다고 했다. 별도 채팅 줄은 만들지 않았다. 대신 그 기억을 다룬 `naby_remember` 칩이, 칩을 쓴 뒤에 고정이 일어났으면 "자주 말씀하신 걸 고정했어요: ‹요약› · 취소"로 바뀐다. 자동 고정은 대화가 끝난 뒤 백그라운드에서 일어나서 붙일 자리가 없고, 칩은 이미 그 기억의 자리이기 때문이다. 칩은 화면을 다시 그릴 때 상태를 한 번 읽으므로, 열려 있는 대화에서는 다음에 그릴 때 바뀐다. 명시적 고정은 검수와 같은 작업 안에서 일어나서 기다리던 칩에 바로 보인다.

### 보존과 망각 (R8~R14, R22)

`archive` 작업이 `decideRetention`으로 보관하고 `shouldPurgeMemory`로 지운다. 기억 프로세스가 시작될 때 한 번, 그 뒤로는 날짜가 바뀐 뒤 처음 끝나는 작업이 하루 한 번 넣는다. 둘 다 모델을 부르지 않으므로 사용량 한도로 멈춘 동안에도 돈다.

- 보존 기간의 시계는 마지막 사용과 그 단계에 들어온 시각 중 나중 것이다. 되살리기(R11)와 고정 풀기(R20)가 시계를 다시 시작하는 방법이 이것이다.
- 세션이 끝난 시각은 세션의 마지막 사용 시각(`last_used_at`)으로 본다.
- 보관된 행은 일반 조회, 주입, 검수와 정리의 비교 대상, 오래됨 목록에서 모두 빠진다. 보관된 키에 다시 쓰면 기억이 돌아오고 단계를 새로 받는다.
- 지울 때는 `deleteMemory`를 쓴다. 확증 관측과 짝 판정이 같이 지워지고, 요약은 행의 컬럼이라 행과 함께 사라진다.
- 이전 뒤 30일 유예(R22)는 보관에만 건다. 삭제는 보관을 거친 행과 대체된 행만 대상이라 유예가 필요 없다.
- "최근 배운 것"에는 하루 한 줄 "기억 N개를 보관했어요"가 보이고 되돌리기 버튼은 없다. 되살리기는 기억 탐색의 "보관됨"에서 한다.
- 고정 기억은 오래됨 목록에도 오르지 않는다(R18의 "감쇠를 적용하지 않는다").

### 강도 (R10)

주입될 때 강도는 그 날의 첫 주입에만 오른다. 이 때문에 같은 시각에 여러 번 주입해 강도를 올리던 스파이크 두 곳(`spike:hygiene` (l), `spike:reflection` (t3))을 날짜를 나눠 주입하도록 고쳤다.

### 주입 (R15, R16)

`selectMemoryForInjection`이 고정 기억을 고정된 순서대로 먼저 넣는다(500토큰, 20개, 턴 예산 중 작은 쪽). 원문을 넣고 요약은 쓰지 않는다. 몫에 들지 못한 고정 기억은 버리지 않고 아래 관련도 순위에서 다른 기억과 겨룬다. 고정 기억이 있으면 블록 안에 "Always apply — the user anchored these; they win over anything else here that disagrees:" 줄을 두고 그 아래에 넣는다. 고정 기억이 없으면 블록은 이전과 바이트 단위로 같다.

### 나비는 고정 기억을 바꾸지 않는다 (R18~R20)

규칙을 판정 함수와 스토어 두 곳에 둔다.

- 검수(`decideReviewOutcome`): 같은 뜻이면 고정 기억에 합치되 등급과 문구는 바꾸지 않는다. 보완이면 새 기억을 옆에 둔다. 상충이면 새 기억을 확정하되 고정 기억이 이기도록 새 행을 대체 처리한다(`superseded_reason = anchored-wins`).
- 정리(`decideTidyOperation`): 고정 기억은 절대 물러나지 않는다. 고정 기억끼리는 건드리지 않는다.
- 스토어: 고정 행 위에 다른 값을 덮어쓰는 `putMemory`는 거절하고, 같은 값이면 확증 관측만 남긴다. `supersedeMemory`는 고정 행을 거절한다. 사람이 질문에 답한 경우(`question`)만 예외다.
- 사람의 편집(`updateMemoryValue`)은 그대로 통과하고 고정도 유지한다.
- "새 내용으로 바꾸기"를 누르면 고정 행의 값이 새 내용으로 바뀌고 사용자 등급이 된다. 옆에 두었던 새 행은 지운다.

### 기존 기억의 이전 (R21~R23)

`memory_tier` 컬럼을 기존 테이블에 더하는 그 순간에 한 트랜잭션으로 단계를 붙이고, 이전 시각을 설정 `memory.tiers.migratedAt`에 남긴다. 기억 화면은 유예 안에서 안내문을 한 번 보이고 `memory.tiers.graceNoticeShownAt`을 남긴다.

### 기억 화면 (§6)

요약 줄은 범위마다 "고정 N · 기억 N · 최근 N"이다. 고정 기억 묶음은 "확인이 필요한 것" 다음, 요약 줄 위에 있다. "확인이 필요한 것"이 사용자의 결정을 기다리는 유일한 묶음이라 맨 위 자리는 그대로 두었다. 기억 탐색에는 단계 필터, "보관됨" 필터(남은 날짜와 되살리기), 장기 기억의 "고정", 고정 기억의 "고정 풀기"가 있다.

### 함께 고친 것

기억 작업 대기열에서 턴의 모델이 정해졌다는 알림(`turnModel`)이 대기열을 다시 보지 않았다. 다시 채운 작업은 우연히 남아 있던 실행 예약 덕에 돌고 있었다. 이제 알림이 대기열을 다시 확인한다. 아무 일도 하지 않은 승격·보관 작업은 설정의 "최근 완료"를 덮어쓰지 않는다. `spike:memory-worker` (d)는 DB 쓰기와 상태 메시지 사이의 경합으로 가끔 실패했다. 상태 메시지가 도착할 때까지 기다리도록 고쳤다.

### 검증

- `npm run spike:memory-tiers`(신규) 60/60 — 두 드라이버에서 R1~R20, 실제 파일로 v17→v18 이전(R21~R23), `naby_remember`의 `pin`, 대기열의 승격·보관 작업.
- 셸 테스트 286파일 5263개 전부 통과. 신규는 `memoryTiers.test.ts`(검수·칩·작업·API)와 `memoryTiersUi.test.ts`(문구·필터·배치).
- 회귀 스파이크 autonomy, 02, memory-auto-apply, model-router, memory-worker, hygiene, reflection, store-projects 모두 통과.

### 검증하지 않은 것

- 화면이 실제로 그려지는 모습. 소스 단언으로 대신했다.
- 패키징된 앱에서의 승격·보관 작업.
- 몇 달에 걸친 실제 보존 기간의 적정성(§9).
- 지운 세션의 주입 기록은 `injection_log`에 남는다. 장기로 오른 뒤에는 읽지 않는 값이라 그대로 두었다.
