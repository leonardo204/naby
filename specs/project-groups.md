# 프로젝트 그룹 — 사이드바에서 프로젝트를 묶는다

> 이 문서가 답하는 질문 — **"프로젝트가 많아졌을 때 사이드바에서 어떻게 묶어 보고, 묶음은 어디에 저장되며, 기존 드래그 정렬과는 어떻게 함께 동작하는가?"**
>
> 상태: 구현 완료(2026-10-22). 구현 내용은 §7에 적는다.

## 1. 요구사항

- **R1 그룹 만들기.** 사이드바 "프로젝트" 제목 줄의 `+` 버튼으로 그룹을 만든다. 누르면 이름 입력 칸이 그 자리에 열리고, Enter로 확정, Esc나 빈 이름으로 취소한다.
- **R2 이름 바꾸기.** 그룹 머리줄을 더블클릭하거나 머리줄 메뉴의 "이름 변경"으로 바꾼다. 입력 방식은 R1과 같다.
- **R3 삭제.** 머리줄 메뉴의 "그룹 삭제"로 지운다. 그룹 안의 프로젝트는 지우지 않고 "그룹 없음" 쪽으로 돌려보낸다. 데이터가 사라지지 않으므로 확인 창을 띄우지 않는다.
- **R4 드래그로 옮기기.** 프로젝트 줄을 그룹 머리줄이나 그룹 안의 프로젝트 위에 놓으면 그 그룹으로 들어간다. "그룹 없음" 영역(그룹 아래의 프로젝트 줄이나 목록 끝 빈 영역)에 놓으면 그룹에서 빠진다. 놓을 수 있는 곳은 드래그 중에 강조한다.
- **R5 접고 펴기.** 그룹 머리줄의 화살표로 그룹을 접는다. 접힘 상태도 저장한다. 접힌 그룹 안에 읽지 않은 세션이 있으면 머리줄에 점을 표시한다.
- **R6 기존 동작 유지.** 프로젝트 클릭·제거·노트·세션 트리 펼치기, 같은 영역 안에서의 드래그 정렬은 지금과 같이 동작한다. 그룹이 하나도 없으면 사이드바는 지금과 똑같아 보인다.
- **R7 그룹 순서 바꾸기.** 그룹 머리줄을 다른 그룹 머리줄 위로 끌어 놓으면 그 앞이나 뒤로 옮긴다. 머리줄의 위쪽 절반에 놓으면 앞, 아래쪽 절반에 놓으면 뒤다. 놓을 자리는 기존 프로젝트 정렬처럼 굵은 강조선(`border-t-2 border-brand`, 뒤쪽은 `border-b-2`)으로 보인다. 순서는 `groups` 배열 순서로 저장한다. 프로젝트 드래그와는 섞이지 않는다. 프로젝트를 끌 때는 그룹 순서가 바뀌지 않고, 그룹을 끌 때는 프로젝트가 그룹에 들어가지 않는다.

## 2. 화면 배치

```
프로젝트                         [+]
▾ 고객사 A                    (3)  ⋯
    naby
    cockpit
    ass-portal
▸ 개인                        (2)  ⋯
  scratch            ← 그룹 없음 프로젝트
  dotfiles
```

- 그룹이 위, "그룹 없음" 프로젝트가 아래다. 그룹 없음 영역에는 따로 제목을 달지 않는다.
- 그룹 순서는 처음에는 만든 순서이고, 그룹 머리줄을 드래그해 바꿀 수 있다(R7). 새 그룹은 맨 뒤에 붙는다.
- 그룹 안 프로젝트는 들여쓴다. 머리줄 오른쪽에 프로젝트 수와 `⋯` 메뉴(이름 변경·그룹 삭제)를 둔다. 메뉴는 사이드바 밖으로 빠져나갈 수 있으므로 셸 CLAUDE.md의 `overflow-hidden` 규칙을 지킨다.
- **접힌 레일(48px)** 에서는 그룹을 표시하지 않고 프로젝트 아이콘을 그룹 순서대로 평평하게 늘어놓는다. 그룹 사이에는 얇은 구분선만 둔다.
- 빈 그룹도 머리줄을 그대로 보인다. 펼치면 "프로젝트를 여기로 끌어 놓으세요" 안내를 보인다.

## 3. 저장

- 그룹은 UI 정리 수단이라 사이드바 너비·접힘처럼 **스토어 설정(settings)** 에 JSON으로 저장한다. 스키마는 바꾸지 않는다.
- 키는 `sidebar.projectGroups`, 값은 이렇다.

```json
{ "groups": [ { "id": "g_ab12", "name": "고객사 A", "collapsed": false, "cwds": ["/path/naby", "/path/cockpit"] } ] }
```

- `/api/projects`의 GET 응답과 POST 본문에 선택 필드 `groups`를 더한다. POST에서 `groups`가 없으면 건드리지 않는다(기존 PATCH 규칙과 같다).
- 한 프로젝트는 많아야 한 그룹에 속한다. 서버는 저장할 때와 읽을 때 정규화한다.
  - 목록에 없는 cwd는 뺀다(프로젝트를 지우면 그룹에서도 빠진다).
  - 두 그룹에 같은 cwd가 있으면 앞 그룹만 남긴다.
  - 이름은 앞뒤 공백을 자르고 60자로 자른다. 빈 이름은 저장하지 않는다(클라이언트가 막지만 서버도 막는다).
  - 값이 깨졌으면 그룹 없음으로 읽는다. 시작 경로에서 예외를 던지지 않는다.
- 그룹 안 프로젝트의 **표시 순서는 전체 프로젝트 순서를 따른다.** `cwds` 배열은 소속만 뜻한다. 그래서 같은 그룹 안에서 드래그 정렬하면 기존 `onReorderProjects`가 그대로 순서를 바꾼다. 프로젝트를 다른 그룹에 놓으면, 놓은 줄 바로 앞으로 전체 순서도 함께 옮긴다.
- 활성 프로젝트는 지금처럼 전체 목록의 index(`activeIndex`)로 가리킨다. 그룹 때문에 index 의미가 바뀌지 않는다.

## 4. 구현 위치

- 셸만 바꾼다. 런타임(`src/`) 변경은 없다.
- 순수 로직은 `workspace/src/client/projectGroups.ts`(또는 같은 패키지의 ops 파일)로 뺀다. 정규화, 그룹 만들기·이름 변경·삭제, 프로젝트 옮기기, 화면용 목록(그룹별 프로젝트와 원래 index) 만들기를 순수 함수로 두고 단위 테스트한다.
- 서버 정규화는 `src/app/api/projects/route.ts`가 같은 순수 함수를 쓴다.
- UI는 `ProjectSidebar.tsx`. 행 컴포넌트는 `memo`하고 콜백 식별자를 고정한다(셸 CLAUDE.md의 성능 규칙).
- i18n 키는 en·ko 양쪽에 추가한다. ko UI 문구는 `~합니다`/명사형이다.

## 5. 검증

- 순수 함수 단위 테스트: 정규화(없는 cwd, 중복 소속, 깨진 JSON, 긴 이름), 만들기·이름 변경·삭제, 옮기기(그룹으로·그룹 밖으로·같은 그룹 안 정렬), 화면용 목록의 index가 원래 `projects` index와 맞는지.
- 라우트 테스트: `groups` 없는 POST는 기존 그룹을 지우지 않는다. 프로젝트를 지우면 그룹에서 빠진다.
- 컴포넌트 테스트: 그룹이 없으면 기존 DOM과 같다. 머리줄 메뉴로 이름 변경·삭제가 된다. 삭제 후 프로젝트가 그룹 없음에 남는다.
- 테스트는 `NABY_DB_PATH` 임시 경로에서 돈다. 실제 `~/.naby`를 건드리지 않는다.

## 6. 범위 밖

- 중첩 그룹, 그룹 색·아이콘.
- 모바일 화면(`mobile/MobileSessionList.tsx`)의 그룹 표시. 모바일은 지금처럼 평평한 목록을 보인다.
- 홈 화면 최근 목록의 그룹 표시.

## 7. 구현 상태 (2026-10-22)

셸만 바꿨다. 런타임(`src/`) 변경은 없다.

| 파일 | 내용 |
|------|------|
| `shell/packages/feature/workspace/src/client/projectGroups.ts` | 순수 함수. 정규화(`normalizeGroups`·`parseStoredGroups`·`serializeGroups`), 만들기·이름 변경·삭제·접기, `reorderGroups`(R7), `assignProject`, `moveProject`(드롭 한 번 적용), `buildSidebarModel`(그룹별 프로젝트와 원래 index) |
| `shell/packages/feature/workspace/src/client/ProjectGroupHeader.tsx` | `memo`한 그룹 머리줄, 이름 입력 칸, `⋯` 메뉴. 메뉴는 `<body>`로 포털을 띄워 `fixed`로 놓는다 |
| `shell/packages/feature/workspace/src/client/ProjectSidebar.tsx` | 선택 prop `groups`·`onChangeGroups`. 그룹 화면, 두 종류 드래그, 접힌 레일 구분선 |
| `shell/packages/feature/workspace/src/client/Workspace.tsx`, `effect/projectClient.ts` | GET의 `groups`를 읽고, 바뀌면 `groups`만 담은 POST(`saveProjectGroups`)로 따로 저장한다 |
| `shell/src/app/api/projects/route.ts`, `server/effect/project.ts`, `server/index.ts` | `groups` 필드, 설정 키 `sidebar.projectGroups`. 서버가 같은 순수 함수로 정규화한다 |
| `shell/packages/shared/i18n/locales/{en,ko}.json` | `workspace.newGroup` 등 키 9개 |
| 테스트 | `projectGroups.test.ts`(순수 함수), `projectGroupsSidebar.test.tsx`(컴포넌트), `src/app/api/projects/route.test.ts`(라우트) |

설계와 다르거나 설계가 정하지 않은 부분은 이렇다.

- **저장 경로.** 그룹은 너비와 같이 `groups`만 담은 POST로 따로 저장한다. 기존 `saveProjects` 호출부 어디에도 그룹을 싣지 않는다. 다른 그룹으로 옮기는 드롭은 순서 저장과 그룹 저장, 두 번의 POST를 보낸다. 두 필드는 서로 독립이라 도착 순서는 상관없다.
- **서버 정리 시점.** GET은 읽을 때 정규화한다. `projects`를 담은 POST가 `groups` 없이 오면 저장된 그룹에서 지운 프로젝트를 빼고 다시 저장한다. 그래서 같은 프로젝트를 다시 열어도 옛 그룹으로 돌아가지 않는다. GET 응답에는 `groups`가 항상 있다(없으면 `[]`).
- **그룹 머리줄에 놓을 때의 순서.** 프로젝트를 그룹 머리줄에 놓으면 그 그룹의 마지막 프로젝트 바로 뒤로 전체 순서를 옮긴다. 빈 그룹이면 순서는 그대로 둔다. "목록 끝 빈 영역"에 놓으면 그룹에서 빠지고 전체 목록 맨 끝으로 간다. 그룹이 하나라도 있을 때만 이 영역을 그린다.
- **이름 입력 칸.** Enter는 확정, Esc와 빈 이름은 취소다. 입력 칸 밖을 누르면(blur) 입력한 이름을 확정한다.
- **그룹이 없을 때의 화면.** 프로젝트 줄과 접힌 레일은 이전과 똑같다. 다만 R1의 `+` 버튼 때문에 "프로젝트" 제목 줄은 버튼이 하나 늘었다.
- **접힌 레일 안 드래그.** 레일에서도 드래그 정렬은 그대로 되고, 다른 묶음의 아이콘 위에 놓으면 그 묶음으로 옮겨진다. 그룹 머리줄이 없으므로 그룹 순서는 레일에서 바꿀 수 없다.
- **컴포넌트 테스트의 범위.** 셸에는 DOM 테스트 환경(jsdom)이 없다. 그래서 상태별 화면은 정적 렌더로, 상태 변화는 순수 함수 테스트로, 메뉴 항목과 드롭이 어느 콜백을 부르는지는 소스 단언으로 나눠 확인한다. 실제 드래그 동작은 앱에서 직접 확인해야 한다.
