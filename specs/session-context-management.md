# 세션 컨텍스트 관리

## 1. 문제

- 상태 바의 "컨텍스트" 숫자는 마지막 턴이 소비한 입력 토큰 총량(스텝 합산)이라, **창이 얼마나 찼는지**를 말해주지 않는다. 748k처럼 창보다 큰 숫자가 떠서 오히려 헷갈린다.
- Claude Code는 `/clear`·`/compact`로 창을 비우지만, naby의 연속성은 트랜스크립트가 아니라 기억·성장 원장에 있다. 세션이 끝나면 회고가 배울 것을 뽑아가고 확정 기억은 자동 주입된다. 그래서 naby의 답은 커맨드가 아니라 **새 탭**이어야 한다 — 단, 인계가 자연스러워야 한다.
- ai-sdk 엔진은 페이로드를 우리가 만드는데 창 관리가 없다. 대화가 길어지면 창 초과로 실패하는 잠복 결함이다. Agent SDK 엔진은 SDK가 자체 컴팩션을 수행하므로 우리 관리 대상이 아니다.

## 2. 설계

### 2.1 창 사용률 게이지

- **측정** — 턴의 마지막 스텝이 보고한 입력 토큰(캐시 리드 포함)이 곧 현재 창 점유량이다. 모델이 실제로 받은 양이므로 추정이 아니라 실측이다. 스텝별 usage가 없으면 게이지를 **숨긴다** — 측정하지 않은 것을 지어내지는 않는다. 이 규칙은 그대로다.
- **모델 식별** — 분모를 정하는 것은 **실행이 실제로 보고한 구체적 모델 id**이지, 우리가 요청한 문자열이 아니다. 둘은 분모가 중요해지는 바로 그 지점에서 갈라진다. Claude 경로의 기본값은 `default`(Agent SDK의 "알아서 고르기" 행)라 어떤 창도 이름 대지 못하고, `opus` 같은 별칭도 마찬가지다. 실행 쪽은 언제나 답을 안다 — Agent SDK는 `system`/`init`의 `model`과 매 assistant 메시지의 `message.model`로, ai-sdk는 스텝 응답의 `response.modelId`로 알려준다. 엔진은 이것을 `contextModel`로, 협상된 베타 목록을 `contextBetas`로 result 이벤트에 실어 보낸다.
- **분모** — 엔진·모델별 창 크기 레지스트리(`contextWindowFor(engine, model, { betas })`). Claude 계열 200k이며, **장문 컨텍스트 티어는 1M**으로 답한다. 티어를 알아내는 신호는 둘이고 각각 단독으로 충분하다: 구체적 id에 붙는 `[1m]` 표식(실측 예: `claude-opus-5[1m]`)과 init이 보고하는 베타 `context-1m-2025-08-07`. 신호가 없으면 1M을 적용하지 않는다 — 기본으로 1M을 쓰면 평범한 턴의 점유율을 다섯 배로 줄여 말하게 된다.
- **모르는 분모** — *(v0.3.0에서 개정)* 이전 규칙은 "모르면 비율 없이 토큰 수만"이었으나, 사용자 보고로 뒤집혔다. `293k`라는 숫자만으로는 읽는 사람이 아무것도 판단하지 못하고, 게다가 이 경우가 예외가 아니라 **가장 흔한 경로**였다. 그래서 이제는 **언제나 비율을 보여주되 근사치임을 표시한다**(`~29%`). 규칙은 세 가지다.
  - 정확한 창을 알고 측정값이 그 안이면 → 그대로 `66%`.
  - 측정값이 알고 있던 창을 **넘으면** → 그 계열의 다음 티어로 올린다(Claude 200k → 1M). 측정값은 이 실행에 대한 사실이고 창은 id에서 끌어낸 추론이므로, 측정값을 믿는다. 올릴 티어가 없으면 그대로 두어 100%가 넘게 표시한다 — "우리가 아는 모든 창보다 크다"의 정직한 표현이다.
  - 정확한 창이 없으면 → 계열 기본값(claude 200k · openai 128k · gemini 1,048,576 · 알 수 없음 128k). 알 수 없는 계열에 가장 작은 창을 쓰는 이유는 컴팩션 폴백과 같다 — 실제보다 "더 찬 쪽"으로 틀려야 사용자가 늦게가 아니라 일찍 움직인다.
- **표시** — 상태 바에 `컨텍스트 66% (132k/200k)` 형태, 근사치일 때는 `컨텍스트 ~29% (293k/1000k)`. 70% 미만 무채색, 70~85% 주의색, 85% 이상 경고색. 라벨은 "창"에서 **"컨텍스트"**로 바꾼다 — "창"은 읽는 사람이 지켜보는 대상이 아니라 그 대상을 담는 기계 장치의 이름이다. 기존 "컨텍스트"(턴 소비량) 라벨이 "턴 입력"으로 옮겨가면서 이 이름이 비었다.
- **캐시 적중** — `Cache: 7%`는 무엇의 7%인지 말하지 않았다. 라벨을 "캐시 적중"으로 바꾸고 한 줄 설명을 툴팁(`title`)으로 붙인다: "이번 턴 입력 중 프롬프트 캐시에서 재사용된 비율입니다. 높을수록 빠르고 저렴합니다." 이 행의 다른 힌트(레이트 리밋, 게이지)가 이미 쓰는 방식이라 새 컴포넌트가 필요 없고, 세 패널 레이아웃에 잘릴 일도 없다.
- **임계 안내** — 85%를 넘으면 입력창 위에 한 줄 배너: "이 대화가 길어졌습니다 — 새 탭에서 이어가기". 강제하지 않고, 닫으면 그 세션에서 다시 뜨지 않는다. **근사 분모에서는 배너를 띄우지 않는다.** 비율을 보여주는 것은 정보 제공이지만 "대화가 거의 찼으니 나누라"고 말하는 것은 주장이고, 추측한 분모로는 그 주장을 할 수 없다. 색은 그대로 올린다 — 색은 힌트지 방해가 아니다.

### 2.2 새 탭에서 이어가기 (요약 인계)

- 배너 또는 탭 컨텍스트 메뉴에서 실행한다. 흐름: 현재 세션의 대화를 짧은 인계 요약(합의된 결정·진행 중인 일·미해결 질문)으로 압축하는 턴을 헤드리스로 돌리고 → 새 세션을 만들어 요약을 첫 시스템 컨텍스트로 심고 → 탭을 연다(빠른 성장 세션과 같은 OpenProject 경로).
- 요약은 세션 행에 저장되어 새 세션의 모든 턴에 주입된다(시스템 프롬프트의 한 블록, "이전 세션 인계" 라벨). 기억 주입은 어차피 자동이므로 인계는 **그 세션에서만 유효했던 맥락**에 집중한다.
- 인계 요약 생성이 실패해도 새 탭은 열린다 — 인계 없이. 실패가 이어가기를 막으면 안 된다.

### 2.3 ai-sdk 엔진 롤링 컴팩션

- 페이로드를 만들 때 추정 토큰(문자 기반 근사)이 창의 70%를 넘으면, 오래된 턴들을 요약 한 블록으로 접고 [요약 + 최근 꼬리]만 보낸다. 요약은 세션에 저장해 다음 턴에 재사용하고, 접힌 범위가 늘 때만 갱신한다.
- 트랜스크립트(저장된 메시지)는 절대 건드리지 않는다 — 접는 것은 **보내는 페이로드**뿐이다. UI에는 컴팩션이 일어났음을 시스템 필 한 줄로 표시한다.
- 수동 `/compact` 커맨드는 두지 않는다. 자동이 기본이고, 수동 개입은 "새 탭에서 이어가기" 하나다.

## 3. 거절한 대안

- **`/clear`·`/compact` 커맨드 추가** — 탭이 곧 clear다. 같은 일을 하는 문이 둘이면 사용자가 어느 쪽이 맞는지 고민하게 된다.
- **문자 수 기반 게이지** — 실측(스텝 usage)이 있는데 근사를 보여줄 이유가 없다. 근사는 ai-sdk 컴팩션의 내부 판단에만 쓴다.
- **Agent SDK 컴팩션 개입** — SDK가 이미 Claude Code와 같은 관리를 한다. 이중 관리는 충돌만 만든다.

## 4. 구현 상태

세 항목 모두 구현하고 검증했다. 검증은 셸 vitest 전량(1673 → **1718 통과**, 신규 45건)과 런타임 스파이크로 한다.

### ✅ CM-1 창 사용률 게이지 + 임계 배너

- **측정** — 두 엔진 모두 마지막 스텝의 입력 토큰을 `EngineEvent.result.contextTokens`로 올린다. Agent SDK는 `result` 메시지가 스텝을 합산하므로 쓰지 않고 **assistant 메시지마다 실리는 usage**를 읽는다(`src/engines/claude-agent-sdk-engine.ts:1424` 부근, `parent_tool_use_id == null`인 본 스레드만 — 서브에이전트는 자기 창을 쓴다). ai-sdk는 스텝마다 `result.usage.inputTokens`를 덮어쓴다(`src/engines/ai-sdk-engine.ts`). 턴 합계(`usage`)와 **별도 필드**이며, 스텝 usage가 없으면 undefined로 남아 게이지가 숨는다.
- **레지스트리** — `src/runtime/context-window.ts`의 `contextWindowFor(engine, model)`. Claude 계열 200k, Gemini 1,048,576, gpt-4.1 1,047,576, gpt-4o 128k, gpt-5 계열 272k(입력 기준), o 시리즈 200k, **모르는 모델은 undefined**. 셸 테스트 `contextWindow.test.ts` 8건이 이 표를 고정한다.
- **표시** — 상태 바에 `창 66% (132k/200k)`. 70% 미만 무채색, 70~85% 주의색, 85% 이상 경고색. 판정은 순수 함수 `contextGauge.ts`에 두고 `contextGauge.test.ts` 8건으로 고정한다(측정 없으면 숨김, 창을 모르면 비율 없이 토큰만). 기존 "컨텍스트" 라벨은 **"턴 입력"**(en: turn input)으로 고쳤다.
- **임계 배너** — 85%에서 입력창 위 한 줄(`ContextLimitBanner.tsx`). 닫으면 그 세션에서 다시 뜨지 않는다. 규칙은 `contextBannerReveal.ts`에 두고 `contextBannerReveal.test.ts` 6건으로 고정한다 — 특히 **dismiss는 세션 id로 기억한다**(불리언이면 다음 대화까지 따라간다).
- 엔진 끝단 증거: `handoffInjection.test.ts`가 실제 `createNabySpec`을 돌려 `result` 이벤트에 `context_tokens=1234`, `context_window=200000`이 실리는 것을 확인한다.

### ✅ CM-2 새 탭에서 이어가기(요약 인계)

- **저장** — 스키마 v13, `sessions.handoff TEXT`(컬럼 존재 여부로 게이트한 ALTER, 두 드라이버, 백필 없음). 세팅이 아니라 **컬럼**인 이유는 엔진이 매 턴 시스템 프롬프트를 만들 때 읽는 값이기 때문이다 — `fast_growth`와 같은 자리, 같은 읽기(`getSession` 한 번). v12 DB를 열어 기존 행 보존·재오픈 무해를 확인했다.
- **액션** — `session.continueInNewTab { sessionId, cwd, title }`. 원본 대화의 최근 구간(메시지 60개/24,000자 상한)을 헤드리스 요약 턴으로 압축하고, 새 세션을 만들어 인계를 그 행에 심고, `sessionId`를 돌려준다. 요약은 `runTurn`이 아니라 **엔진을 직접 구동한다** — 반영 판정기(`lib/reflection.ts`)와 같은 이유로, 사용자가 떠나는 대화에 "요약해줘"라는 턴을 남기지 않기 위해서다. 백엔드 선택은 `resolveJudgeBackend`를 재사용한다(사본을 두면 한쪽만 로그인을 못 본다).
- **실패가 막지 않는다** — 요약이 던지든, 비어 돌아오든, 엔진이 아예 없든 **세션은 만들어지고 탭은 열린다**. `sessionHandoff.test.ts` 13건과 `continueInNewTab.test.ts` 3건이 두 경로를 모두 고정한다.
- **주입** — `engines/naby.ts`의 `turnSystem`에서 페르소나 다음, 단계·체크인 지시 **앞**에 `PREVIOUS SESSION HANDOFF` 블록 하나로 넣는다(정책이 아니라 맥락이므로). 그 세션의 **모든 턴**에 넣는다 — 새 세션은 트랜스크립트가 비어 있어 첫 턴만 넣으면 두 번째 메시지에서 잊는다.
- **클라이언트** — 배너 버튼과 탭 컨텍스트 메뉴("새 탭에서 이어가기")가 같은 액션을 부르고 `Topics.OpenProject`로 이동한다(빠른 성장 세션과 같은 경로). 요약이 도는 동안 버튼은 대기 상태를 보인다.

### ✅ CM-3 ai-sdk 롤링 컴팩션

- **알고리즘**(`src/runtime/compaction.ts`, 순수) — 나가는 페이로드를 문자/3.5로 추정해 창의 **70%**를 넘으면, 남는 꼬리가 **45%**에 들어올 때까지 앞에서부터 접는다. 경계는 도구 결과 위에 놓지 않고(모든 프로바이더가 짝 없는 tool_result를 거부한다), 꼬리는 최소 6개를 남긴다. 보내는 것은 [요약 블록 + 최근 꼬리]뿐이다.
- **요약 재사용** — 접힌 범위가 그대로면 저장분을 그대로 쓰고, 범위가 늘면 **이전 요약 + 새로 접힌 구간**만 모델 한 번에 넘겨 확장한다. 요약은 세션 컬럼 `rolling_summary` + `rolling_summary_upto`에 둔다(항목 6과 같은 결정, 같은 자리). 범위 없는 요약은 재사용하지 않는다 — 어느 앞부분을 설명하는지 모르는 요약은 요약이 아니다.
- **실패는 정직하게** — 요약 생성이 실패하면 오래된 턴을 잘라내되 모델에게 "일부가 없으니 추측하지 말고 물어보라"고 적어 보내고, 절반짜리 요약은 저장하지 않는다. 두 경우 모두 시스템 필 한 줄을 낸다(`context-compaction` / `folded:n` · `truncated:n` → `harnessPill.ts`에서 한국어 문장으로 바뀐다).
- **트랜스크립트는 건드리지 않는다** — 접는 것은 페이로드뿐이다. `npm run spike:compaction` **10/10**이 저장된 240개 메시지가 턴 전후로 바이트 단위 동일함을 확인한다.
