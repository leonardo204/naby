# 하네스 단독 소유 — 가져오면 naby 것이 된다

> 상태: 구현 완료(2026-08-03) — §2.1~§2.5 반영, 상태는 §6. 한 줄 요약: 벤더 하네스(`~/.claude`, `~/.codex` 등)를 **가져오는 것은 허용**하되, 가져오는 순간 파일이 `~/.naby`로 **복사되어 naby 소유**가 되고, 이후 벤더 디렉터리와의 상시 연결은 없다.

## 1. 기준 (사용자 선언)

- naby는 **단독 앱**이다. 다른 하네스와 연관을 갖지 않는다.
- 기존 `~/.claude`·`~/.codex` 등의 하네스를 **불러오는 것은 OK**다. 단, 불러올 때 **이미 `~/.naby`로 가져와서** naby 레이어에서 관리한다.
- 설정의 스킬/커맨드/에이전트/MCP는 전부 naby 레이어에 위치하고 naby 레이어에서 관리된다.
- 자격증명은 하네스가 아니다 — Claude 구독 로그인·ChatGPT OAuth 등 **인증**과 엔진 내부 저장(세션 트랜스크립트 등)은 이 기준의 대상이 아니다. 하네스 콘텐츠(스킬·커맨드·서브에이전트·CLAUDE.md·훅·MCP 설정)가 대상이다.

## 2. 해소 계획 (감사 위반 → 조치)

### 2.1 가져오기의 실체화 (V2, CRITICAL)

- 명시적 가져오기 액션이 벤더 트리를 읽을 때, 아티팩트를 **`~/.naby/{skills,commands,agents}`(또는 `<cwd>/.naby/...`)로 복사**한 뒤 그 naby 경로를 `provenance.origin`으로 기록한다. 벤더 경로는 감사용 `importedFrom` 필드로만 남는다(불활성).
- 스킬 디렉터리(`skills/<name>/` + references 등)는 통째로 복사한다. 이름 충돌 시 기존 naby 파일을 덮어쓰지 않고 가져오기를 건너뛰며 요약에 보고한다(naby 소유가 이긴다 — 기존 섀도잉 규칙과 동일한 방향).
- 복사 실패(권한 등)는 해당 항목만 건너뛰고 보고한다. DB 행만 만들고 파일을 안 만드는 상태는 만들지 않는다.
- 기존 설치의 `.claude` origin 행: 다음 명시적 가져오기 때 같은 이름이 발견되면 실체화 경로로 승격된다. 별도 마이그레이션은 하지 않는다(묘비 체계가 하위호환을 지킨다).

### 2.2 스캔은 naby 전용 (V1, CRITICAL)

- `resolveBaseDirs`가 **naby 베이스만** 반환한다. `.claude`는 목록 스캔에서 제거된다.
- `.claude` 읽기는 **명시적 가져오기 버튼 안에서만** 일어난다(§2.1의 복사 포함). 스캔-온-리스트는 naby 홈만 본다 — skill-hub가 naby 홈에 설치한 스킬의 자동 표시는 그대로 동작한다.
- skill-hub-builtin §2.5의 "이중 스캔·벤더 브리지" 규칙은 이 문서로 대체된다(0.4.0에서 개정).

### 2.3 Agent SDK 격리 기본화 (V3, CRITICAL)

- `settingSources: []`를 **무조건** 적용한다(isolated 구분 삭제). `~/.claude`·`<cwd>/.claude`의 settings·훅·CLAUDE.md가 naby 턴에 로드되지 않는다.
- SDK 네이티브 스킬/서브에이전트/커맨드 로드도 막는다(SDK 옵션으로 명시적으로 끄거나, 끄는 옵션이 없으면 가능한 수단을 조사해 적용하고 한계를 기록한다).
- 자격증명 읽기(`~/.claude/.credentials.json`)와 SDK 내부 세션 저장은 유지된다 — §1의 인증/엔진 내부 예외.
- 결과: 스킬·기억·지침의 유일한 전달 경로가 naby 주입이 된다. dev-claude 이중 전달 비대칭(V9)이 뿌리에서 해소된다.

### 2.4 예약 작업은 naby 엔진 (V4·V5, HIGH)

- 예약 작업 디스패치가 벤더 cockpit 엔진(claude/codex/deepseek 등)으로 가지 않고 **naby 단일 엔진**을 쓴다. 엔진 선택지는 제거하거나 'naby'만 허용한다.
- 이로써 cockpit 엔진 스펙들(V5의 MCP 상속 구멍 포함)은 도달 불가가 된다. 코드 삭제는 후속 정리로 남긴다(도달 불가 확인 테스트만 둔다).

### 2.5 잔재 제거 (V7·V8)

- 벤더 디렉터리를 읽거나 쓰는 부수 경로 제거: `claude-stats` 엔드포인트(미사용), 세션 클린업의 `~/.claude`·`~/.codex` 스윕(naby가 벤더 디렉터리에 쓰는 유일한 경로).
- 사용자 문구(i18n·UI 주석)에서 "~/.claude를 계속 스캔한다"는 약속을 제거하고, 가져오기 버튼 문구를 "…에서 naby로 복사해 가져오기" 의미로 바꾼다(en/ko).

### 2.6 묘비 체계의 위상 (V6)

- `.claude`가 라이브 베이스에서 빠지면 부활 루프의 원인이 사라지므로 묘비는 **하위호환 장치**로 축소된다(기존 `.claude` origin 행의 삭제 처리). 신규 가져오기는 전부 naby 소유(tier 1 파일 삭제)다. 묘비 코드는 유지하되, 존재 이유를 주석으로 재기술한다.

## 4. 검증 계획

- 임포터 — 가져오기가 파일을 naby 홈에 복사하고 origin이 naby 경로로 기록됨, 이름 충돌 시 naby 기존 파일 보존, 스킬 디렉터리 통째 복사, 복사 실패 건너뜀 보고, 스캔-온-리스트가 `.claude`를 읽지 않음(벤더 트리에 파일을 두고 목록 반복 → 절대 등장하지 않음), 명시 가져오기 후에만 등장(naby 경로로).
- 엔진 — buildQueryOptions가 항상 `settingSources: []`(스파이크 단언 반전), `~/.claude` 스킬이 dev-claude 턴에 네이티브로 안 뜸(가능한 범위에서 옵션 단언).
- 예약 작업 — naby 엔진으로만 디스패치, 벤더 엔진 지정 거부.
- 잔재 — claude-stats 라우트 부재, 클린업이 벤더 디렉터리를 안 건드림.
- 회귀 — 전체 셸 테스트·스파이크·양 트리 타입체크·build:app. spike-cwd의 settingSources 단언은 새 기준으로 갱신.

## 5. 미결정

- cockpit 벤더 엔진 코드(claude.ts/codex.ts/deepseek.ts 등)의 물리적 삭제 시점. 도달 불가 확인 후 별도 정리 커밋.
- 기존 `.claude` origin 행의 일괄 실체화 마이그레이션(지금은 명시 가져오기 시 자연 승격만).
- SDK 네이티브 **서브에이전트** 로드(`~/.claude/agents/*.md`)를 끄는 공식 옵션이 없다. `agents` 옵션은 우리 것을 더할 뿐 남의 것을 빼지 않는다 — §6의 잔여 노출 항목을 본다.

## 6. 구현 상태 (2026-08-03)

§2.1~§2.5를 구현했다. 정본(`ref-docs/specs/`) 개정은 §3 마지막 항목대로 승격 시점으로 미룬다.

### 무엇이 달라졌는가

- **가져오기가 파일을 옮긴다(§2.1).** 명시적 가져오기(`mode:'import'`)만 벤더 트리를 읽고, 읽은 아티팩트를 naby 홈의 같은 상대 경로로 복사한 뒤 그 경로를 `provenance.origin`으로 기록한다. 스킬은 `SKILL.md` 한 장이 아니라 **디렉터리 통째로** 복사한다(references·scripts를 두고 오면 스킬이 없는 파일을 가리킨다). 벤더 경로는 `provenance.importedFrom`에 감사용으로만 남고, 아무 코드도 그것을 되읽지 않는다. 이 필드는 payload JSON에 실어 컬럼도 마이그레이션도 늘리지 않았다.
- **덮어쓰지 않고, 실패하면 행을 만들지 않는다(§2.1).** 대상이 이미 있으면 충돌로 건너뛰고 요약에 보고한다(naby 홈은 사용자 것이고, 가져오기는 그것을 고쳐 쓸 권한이 아니다). 복사가 실패하면 그 항목만 건너뛴다 — **파일 없는 DB 행은 만들지 않는다.** 요약에 `copied` 수를 새로 싣고 UI가 그 줄을 보여준다("포인터인지 사본인지"가 이번 변경의 전부이므로).
- **스캔은 naby 홈뿐이다(§2.2).** `resolveBaseDirs`는 naby 베이스만 돌려준다. 벤더 베이스는 `resolveVendorBases`라는 **별도 함수**가 답하고, 그것을 부르는 곳은 임포터의 `mode:'import'` 한 곳뿐이다. 목록 스캔 함수 이름도 `scanClaudeForScope` → `scanNabyHome`으로 바꿨다 — 이름이 동작보다 한 릴리스 오래 살아남은 것이 아무도 알아채지 못한 이유였다.
- **엔진은 무조건 격리다(§2.3).** `settingSources: []`가 상시 적용된다(`isolated` 플래그는 삭제했고, reflection 판사도 같은 줄로 격리된다). 여기에 `skills: []`(SDK가 문서화한 "이 목록에 든 스킬만 로드" 형식의 빈 목록)와 `disallowedTools`에 `Skill`·`SlashCommand` 추가를 얹었다. spike-cwd의 단언은 반전했고, **경험적 증거**를 하나 더 심었다(C3: 프로젝트에 심은 훅이 아예 실행되지 않는다 — 이전에는 `system/hook_started` 이벤트가 나왔다).
- **예약 작업은 naby 고정이다(§2.4).** 디스패처가 레지스트리 조회를 버리고 `nabySpec`을 직접 import한다 — 조회할 이름이 없으니 디스크의 낡은 `engine` 필드가 백엔드를 고를 수 없다. 벤더 엔진을 **명시한** 작업은 조용히 바꿔 실행하지 않고 거부한다(사용자가 고른 것과 다른 것을 말없이 쓰는 편이 더 나쁘다). 엔진 필드가 없거나 옛 피커가 쓴 `claude`/`claude2`인 작업은 그대로 naby로 실행한다.
  - 같이 고친 것: 재개 대상 확인이 `~/.claude/projects/<cwd>/<id>.jsonl`을 stat 하고 있었다. naby 세션에는 **없는 파일**이라 예약 실행마다 "복구"랍시고 새 세션을 파고 이어가야 할 대화를 버렸다. 이제 스토어에 묻는다.
- **잔재를 지웠다(§2.5).** `/api/claude-stats` 라우트와 구현, 그리고 아무도 부르지 않던 클라이언트 래퍼 `loadClaudeStats`를 삭제했다(죽은 코드라도 벤더 디렉터리를 읽는 코드는 벤더 디렉터리를 읽는 코드다). 세션 클린업 스윕은 이미 벤더 디렉터리를 건드리지 않았으므로 주석을 규칙으로 다시 썼다 — 타이머로 파일을 지우는 유일한 경로라 벤더 경로가 끼어들면 안 된다. i18n(en/ko)은 "계속 스캔한다"는 약속을 지우고 가져오기 버튼을 "…에서 naby로 복사해 가져오기"로 바꿨다.
- **묘비는 하위호환 장치로 축소했다(§2.6).** 코드는 유지하되 존재 이유를 다시 썼다: 이제 tier 1(파일째 삭제)이 정상 경로이고, 묘비가 필요한 경우는 셋이다 — §2.1 이전에 가져온 행(벤더 origin), 세트 임포트(파일 없음), 봉쇄 검사가 unlink를 거부한 경우.

### 검증

- 셸 테스트 **1070개 통과**(66 파일). 기준선 1029개에서 +41 — 실체화 복사(디렉터리·평면 파일·팩 중첩·충돌 건너뜀·복사 실패 시 행 없음·`origin`=naby·`importedFrom` 기록), 스캔 격리(`.claude`에 심은 파일이 몇 번을 돌려도 안 보이고, 명시 가져오기 뒤에야 naby 경로로 등장), 예약 작업 고정(레거시 허용·벤더 거부·스토어 재개), 도달 불가·삭제 확인(소스 단언)이다.
- 스파이크 — harness 17/17, export 11/11, import 11/11, skill 10/10, autonomy 22/22, 02 5/5, reflection 51/51, checkin 12/12, **cwd 9/9**(기준선은 6/7이었다 — A4가 이미 낡아 실패 중이었고, 이번에 A2 반전·A5·C3을 더해 전부 통과한다).
- 타입체크 — 런타임 트리 클린, 셸은 기준선과 같은 4건(이번 변경과 무관한 기존 테스트 파일 3개). `npm run build:app` 성공.

### 남은 노출 (정직하게)

- **SDK 네이티브 서브에이전트.** `~/.claude/agents/*.md`의 로드를 끄는 문서화된 옵션이 없다. 다만 위임된 서브에이전트의 모든 도구 호출도 그 턴의 PreToolUse 게이트를 지나므로 정책을 넘지는 못한다.
- **`skills: []`는 컨텍스트 필터다.** SDK 문서가 "샌드박스가 아니다 — 파일은 디스크에 남고 Read/Bash로 닿는다"고 못 박는다. 모델이 스스로 경로를 읽는 것까지 막지는 않는다(그 읽기는 게이트를 지난다).
- **자격증명과 엔진 내부 저장은 그대로다.** §1의 예외이며 이번 작업의 대상이 아니었다.
