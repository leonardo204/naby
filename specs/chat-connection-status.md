# 채팅 연결 상태 — 입력창 아래에 Atlassian과 Skill Hub를 늘 보여 준다

채팅 탭의 입력창 바로 아래에 얇은 줄을 두고 **Atlassian**과 **Skill Hub**를 점 하나와 이름으로 보여 준다. 설정 화면을 열지 않아도 Atlassian 로그인이 살아 있는지, 조직 하네스가 도는지 알 수 있게 하려는 것이다.

## 1. 결정 사항 (사용자 결정, 2026-10-08)

| 항목 | 결정 |
|---|---|
| 필수로 취급 | 조직 하네스는 필수로 취급해 상태 줄에 늘 표시하고, 연결이 안 되면 빨강으로 알린다 |
| 표시만 한다 | 사용을 막지 않는다. 키가 없으면 naby는 조직 하네스 없이 돈다(org-harness-sync §4.3). 끄는 스위치도 그대로다(§4.8). 프롬프트를 막는 것은 org-harness-sync §4.6의 Atlassian 규칙뿐이다 |
| 색 | 초록은 연결됨, 노랑은 저절로 끝나는 진행 중 상태, 빨강은 연결 안 됨이다. 회색은 쓰지 않는다 |

## 2. 어디에 보이나

데스크톱 채팅 탭마다 입력창 아래에 늘 보인다. 두 항목도 늘 둘 다 보인다. 감추는 때는 첫 상태를 받기 전 한순간(로컬 요청 한 번)뿐이다.

두 곳에는 두지 않는다.

- 선택 팝업(선택한 글에 대해 묻는 작은 창). 한 번 묻고 버리는 창이다. 조직 하네스 새 버전을 알리는 "갱신 팝업"(org-harness-sync §3.1)과는 다른 것이다. 갱신 팝업은 맨 위 창에 뜨고, 이 줄과 따로 전달된다(§5).
- 모바일 화면(`/m`). 그 화면에는 설정 창이 없고, 브라우저 로그인이 돌아오는 주소가 데스크톱의 `127.0.0.1`이라 휴대폰에서는 로그인이 끝나지 않는다.

## 3. 색과 마우스를 올렸을 때의 문장

표는 위에서부터 먼저 맞는 줄을 쓴다. 문장은 설정 화면의 조직 하네스 카드와 같은 문장이다. 마지막 줄에는 누르면 무엇을 하는지 적는다(§4).

빨강은 "연결이 안 됐다"는 뜻일 뿐이다. 빨강이어도 naby가 막히지는 않는다. 막히는지는 org-harness-sync §4.6이 정하고, 그때는 문장이 그렇다고 말한다.

### 3.1 Atlassian

| 상태 | 색 | 마우스를 올리면 |
|---|---|---|
| 연결됨 | 초록 | "브라우저 로그인으로 연결되어 있습니다." |
| 브라우저 로그인을 기다리는 중 | 노랑(깜빡임) | "브라우저를 기다리는 중…" |
| 유예 중(org-harness-sync §4.6) | 빨강 | "로그인하지 않았습니다." "N일 안에 로그인해 주세요. 그 뒤로는 로그인할 때까지 새 대화가 막힙니다." |
| 차단 중(유예가 끝남) | 빨강 | "로그인하지 않았습니다." "로그인할 때까지 새 대화가 막힙니다. 이미 열려 있는 대화는 그대로 쓸 수 있습니다." |
| 로그인한 적 없음 | 빨강 | "로그인하지 않았습니다." "조직 하네스를 쓰려면 이 로그인이 필요합니다." |
| 만료 | 빨강 | "로그인이 만료되었습니다. 다시 로그인해 주세요." |
| 이전 API 토큰 행(org-harness-sync §4.4) | 빨강 | "아직 이전 API 토큰 연결을 쓰고 있습니다. 한 번 로그인하면 API 토큰은 지워집니다." |
| 직접 만든 `atlassian` 서버만 있음 | 빨강 | "직접 만든 atlassian 서버가 있습니다. 조직 하네스에는 브라우저 로그인이 필요하고, 로그인하면 이 서버를 바꿉니다." |

유예는 차단을 늦출 뿐이고 색을 바꾸지 않는다. 유예 날수와 차단 문장은 Atlassian 차단이 실제로 걸리는 상태에서만 나온다. 조직 하네스가 켜져 있고, 패키지가 설치돼 있고, `HARNESS_GATE=0`이 아닐 때다(org-harness-sync §3.6). 그 밖에는 "조직 하네스를 쓰려면 이 로그인이 필요합니다."를 쓴다. 마지막 로그인이 실패했으면 "Atlassian 로그인 실패: (이유)"를 한 줄 더한다.

### 3.2 Skill Hub

| 상태 | 색 | 마우스를 올리면 |
|---|---|---|
| 키 없음(org-harness-sync §4.3) | 빨강 | "꺼짐 — Skill Hub 키가 없습니다." "누르면 설정 → 연결의 Skill Hub 키 입력칸을 엽니다." |
| 사용자가 끔(org-harness-sync §4.8, 설정 토글) | 빨강 | "꺼짐 — 직접 껐습니다." |
| 환경 변수로 끔(`NABY_ORG_HARNESS=0`, §4.8) | 빨강 | "꺼짐 — 환경 변수 NABY_ORG_HARNESS=0으로 꺼져 있습니다." |
| 키가 거부됨(401, org-harness-sync §3.6) | 빨강 | "Skill Hub가 키를 거부했습니다. 설정 → 연결에서 키를 다시 넣어 주세요." "누르면 설정 → 연결의 Skill Hub 키 입력칸을 엽니다." |
| 키를 넣었고 아직 확인하지 않음 | 노랑(깜빡임) | "Skill Hub 키를 아직 확인하지 않았습니다." |
| 키 확인됨, 첫 패키지를 받는 중 | 노랑(깜빡임) | "조직 하네스를 받는 중…" |
| 키 확인됨, 아직 받으러 가지 않음 | 노랑(깜빡임) | "아직 받지 않았습니다. 사내망에 연결되면 받습니다." |
| 키 확인됨, 확인은 했는데 패키지가 없음(사내망 밖, 체크섬 불일치 등) | 빨강 | "아직 받지 않았습니다. 사내망에 연결되면 받습니다." "마지막 확인 (시각) — (결과)" |
| 키 확인됨, 켜짐, 패키지 설치됨 | 초록 | "켜짐 — 모든 세션에서 조직 스킬을 씁니다." "버전 (버전)" "마지막 확인 (시각) — (결과)" |

끈 상태가 키 거부보다 먼저다. 둘 다 빨강이라 색은 같고, 문장만 "꺼짐"을 먼저 말한다.

"키를 넣었고 아직 확인하지 않음"은 확인 요청이 실패해도 그대로다. 사내망 밖에서는 답을 받지 못해 아무것도 기록하지 않으므로 노랑으로 남는다. 다음 확인(앱 시작, 6시간 확인, "지금 확인")이 다시 묻고, 답을 받으면 풀린다(org-harness-sync §3.6).

"받는 중"은 서버가 지금 확인을 돌리고 있는지(`syncing`)로 안다. 시작 확인, 6시간 확인, "지금 확인" 중 하나가 돌고 있으면 참이다. 패키지가 이미 설치된 상태에서 다시 확인하는 동안은 초록 그대로다.

## 4. 누르면

| 항목 | 상태 | 누르면 |
|---|---|---|
| Atlassian | 빨강 전부 | 설정 카드와 같은 브라우저 로그인을 바로 시작한다. 이전 API 토큰 행과 직접 만든 서버도 같다. 로그인이 끝나면 그 행을 OAuth 행으로 바꾼다(org-harness-sync §4.4) |
| Atlassian | 연결됨, 로그인을 기다리는 중 | 설정 → 하네스를 연다 |
| Skill Hub | 키 없음, 키 거부됨 | 설정 → 연결을 열고 Skill Hub 키 입력칸으로 스크롤해 커서를 둔다. 키 입력칸은 연결 칸의 System MCP 목록에 있는 Skill Hub 항목이다(settings-ia-reorg) |
| Skill Hub | 그 밖 전부 | 설정 → 하네스를 연다. 조직 하네스 카드에 켜고 끄는 토글, "지금 확인", 버전과 마지막 확인이 있다 |

키를 거부당한 상태에서 사용자가 하네스를 꺼 두었어도 연결 칸으로 간다. 키를 고쳐야 다시 켤 수 있기 때문이다. 각 경우의 마지막 줄은 누르면 어디가 열리는지 그대로 말한다.

로그인 요청 코드(`atlassian.login`을 보내고 인증 주소를 여는 부분)는 설정 카드의 로그인 버튼과 같이 쓴다. 상태 줄에서 시작한 로그인은 끝났을 때 성공이나 실패를 짧은 알림으로 알린다. 설정 카드에서 시작한 로그인은 카드가 알린다.

설정 창은 맨 위 창(작업 공간)에 있고 상태 줄은 프로젝트 탭(iframe) 안에 있다. 그래서 상태 줄은 `OpenSettings` 주제에 칸(`section`)을 실어 보내고, 작업 공간이 그 칸을 연다(settings-ia-reorg). 키 입력칸으로 갈 때는 `focus: "system-mcp:skill-hub"`도 싣는다. 설정 창은 `data-settings-anchor`가 같은 항목을 화면 가운데로 스크롤하고 첫 입력칸(없으면 첫 버튼)에 커서를 둔다. 연결 칸의 목록은 비동기로 불러오므로, 항목이 아직 없으면 요청을 기억해 두었다가 그 항목이 화면에 붙을 때 항목이 직접 받아 간다. 설정 창에는 타이머를 두지 않는다. 받아 가지 않은 요청은 설정 창을 닫으면 버린다.

## 5. 읽는 방법

**`status.connections`.** 상태 줄은 이 동작 하나로 읽는다. `POST /api/naby`에 `{"action": "status.connections"}`를 보내면 아래를 받는다. 상태 단어, 버전, 시각만 담는다. 키, 토큰, 주소는 담지 않는다. 서버는 `current` 표시와 설정 몇 개만 읽고, 행 목록이나 스킬 본문, `hooks.json`은 읽지 않는다.

```
connections: {
  atlassian: {
    status: "connected" | "relogin" | "none",
    row: "none" | "legacy" | "oauth" | "other",
    loginPending: boolean,
    lastLoginError?: string,
    required: boolean,        // §3.1의 차단이 실제로 걸리는 상태
    blocking: boolean,        // required이고 지금 새 대화를 막는 중
    graceDaysLeft?: number    // required이고 유예 중
  },
  skillHub: {
    configured: boolean,      // 키가 있다
    on: boolean,
    offReason?: "no-skill-hub" | "env-off" | "user-off" | "unauthorized",
    auth: "ok" | "unauthorized" | "unknown",
    version?: string,         // 설치된 패키지
    lastSync?: { at: number, outcome: string },
    syncing: boolean          // 지금 확인이 돈다
  }
}
```

갱신 팝업은 이 응답에 싣지 않는다. 팝업은 맨 위 창이 `/ws/global-state` 알림으로 받고(org-harness-sync §3.1), 상태 줄은 팝업을 그리지 않는다. 팝업 닫기(`orgHarness.ackUpdate`)는 `{ok, acked}`만 돌려준다.

**언제 읽나.** 프로젝트 탭 하나(iframe 하나)에 읽기 모듈이 하나 있다. 그 탭의 채팅 탭이 몇 개든 요청은 하나다. 구독하는 채팅 탭 수를 세어 첫 탭이 열릴 때 시작하고 마지막 탭이 닫히면 멈춘다. 마지막 상태는 남겨 두어, 탭을 다시 열면 바로 그린다.

- 처음 열 때
- 창으로 돌아올 때(focus)
- 60초마다
- 로그인을 기다리거나 확인이 도는 동안에는 2초마다
- 다른 창이 `ConnectionsChanged`를 알릴 때. 설정 카드의 로그인·"지금 확인"·켜고 끄기, 연결 화면의 키 저장·삭제가 이 주제를 맨 위 창과 모든 프로젝트 탭에 보낸다

이미 나가 있는 요청이 있으면 새로 보내지 않고 그 결과를 같이 받는다. 요청이 실패하면 마지막 상태를 그대로 둔다. 연결이 잠깐 끊긴 것이 연결 상태가 바뀌었다는 뜻은 아니다.

## 6. 점과 색 변수

점은 공용 `StatusDot`(shared-ui)이다. 작업 목록(`RunningJobsIndicator`)이 따로 갖고 있던 점을 옮겨 두 곳이 같이 쓴다. 상태 줄에서는 8px, 목록에서는 6px이다.

| 이름 | 색 변수 | 쓰는 곳 |
|---|---|---|
| success | `--success`(초록 9단계) | 연결됨, 작업 성공 |
| warning | `--warning`(노랑 9단계) | 진행 중, 작업 결과 모름 |
| danger | `--destructive` | 연결 안 됨, 작업 실패 |
| active | `--brand` | 도는 작업(깜빡임) |
| neutral | `--muted-foreground` 반투명 | 상태 줄에서는 쓰지 않는다 |

`--success`와 `--warning`은 이 문서에서 새로 정의했다. 밝은 테마와 어두운 테마 모두에 같은 9단계를 쓴다. 9단계는 두 테마에서 채움용 단계라 어느 배경에서도 점이 같게 보인다.

## 7. 구현 상태

2026-10-08에 넣었다. 셸의 `ConnectionStatusBar.tsx`, `connectionStatus.ts`(읽기 모듈), `connectionStatusView.ts`(색·문장·누름 결정), 서버의 `readConnectionsStatus`(`lib/orgHarness.ts`)다.

확인한 것.

- §3의 모든 행이 색 표 테스트에 한 줄씩 있다. 어떤 상태도 회색이 되지 않는다는 것, 숨김 규칙이 없다는 것도 테스트한다.
- 읽기 모듈: 탭 열 개가 요청 하나만 보내고, 마지막 탭이 닫히면 타이머와 듣기를 거두며, 겹친 요청은 하나로 합친다. focus, 60초, `ConnectionsChanged`, 로그인·확인 중 2초 읽기도 확인한다.
- 서버: 키·토큰·주소와 갱신 알림이 응답에 없다. 확인이 도는 동안 `syncing`이 참이다. 로그인 실패 이유가 응답에 실린다.
- 화면: prod 빌드 서버를 임시 홈, 임의의 빈 포트, 임시 Electron 프로필로 띄워 밝은·어두운 테마에서 찍었다. 키가 없으면 둘 다 빨강, 키만 넣고 확인 전이면 Skill Hub가 노랑, 패키지가 설치되면 Skill Hub가 초록이다. 세 경우 모두 Atlassian은 로그인 전이라 빨강이다.
