# 설정 정보 구조 재편

## 1. 문제

설정이 자랐다. 기능이 하나 늘 때마다 가장 가까운 탭에 얹혔고, 그 결과가 지금이다.

- **프로바이더 탭 하나에** 엔진 선택 + API 키 아코디언 5개 + System MCP 프리셋 2개 + 무한 MCP 서버 목록이 있다.
- **나비 탭의 성장 패널은** 펼치면 35~60줄이고 무한 목록이 두 개다(작업 유형별, 최근 결정). 읽기 전용 현황판인데 설정 사이에 끼어 있다.
- **기억 부분은** 콜드스타트 카드·개수·대기 제안·브라우저 버튼·토글 2개·문체 지문·일괄 삭제, 여덟 덩어리가 쌓여 있고, M13이 추가한 구분(전역 스타일은 수동 승인 전용, 대체 알림)이 드러나지 않는다.
- **텔레그램은** 연결 설정인데 나비 탭에 있다.

## 2. 조사 근거 (2026-08-04, 세 갈래)

- **설정과 대시보드를 섞지 않는다.** 읽기 전용 현황은 설정이 아니다. ChatGPT·Claude 모두 "AI가 배운 것"을 전용 서브페이지로 분리한다(Manage memories 모델). 설정에는 사용자가 바꾸는 것만 남긴다.
- **그룹은 의도(무엇을 하러 왔나) 기준, 한 그룹 4~5개 이하**(Microsoft Fluent), 라벨은 목적지를 예측하게(NN/g information scent), **깊이는 2단계까지**(NN/g progressive disclosure).
- **배지는 "사용자 결정이 필요한 것"에만** 달고, 0이면 숨긴다. 대기함은 사용자의 속도로 훑고 비울 수 있어야 한다.
- **구조는 정보다**(Anthropic frontend-design 스킬 원문). 구분선·박스·배지는 내용에 대한 사실을 담을 때만 존재한다. 대담함은 화면당 한 곳. 계층은 박스가 아니라 타이포그래피로. — 이 원칙들은 기존 `settingsLayout.test.ts` 불변식(섹션은 평면, 카드 금지, 한 문장 규칙)과 같은 방향이므로 불변식을 유지·확장한다.

## 3. 설계

### 3.1 내비게이션 재그룹 (7 → 8, 의도 기준)

| # | 탭 | 담는 것 | 이동 내역 |
|---|---|---|---|
| 1 | 일반 | 테마 + 언어 | 두 탭을 하나로 합침 |
| 2 | AI 프로바이더 | 엔진 선택 + API 키 | MCP 전부를 내보냄 |
| 3 | 연결 | System MCP + 일반 MCP + 텔레그램 | 프로바이더와 나비에서 이사 |
| 4 | 나비 | 에이전트 목록·위임 설정·가져오기/내보내기 + 성장 요약 한 줄 | 성장 상세는 리포트 오버레이로 |
| 5 | 기억 (배지) | 결정 대기함 + 학습 방식 + 스타일 + 브라우저 진입 | 나비 탭에서 독립 |
| 6 | 하네스 | 현행 (하네스 + 커맨드) | 변화 없음 |
| 7 | 권한 | 현행 | 변화 없음 |
| 8 | 정보 | 현행 (버전 + 업데이트 + dev) | 변화 없음 |

라벨에 "고급"·"기타" 같은 냄새 없는 이름은 쓰지 않는다.

### 3.2 성장 리포트 오버레이 (대시보드 분리)

에이전트 행 안의 성장 패널을 **리포트 오버레이**로 옮긴다(기억 브라우저와 같은 층, `z-[100]`). 행에는 세 가지만 남는다 — 단계 글리프 + 게이지 한 줄, 후퇴/성장 사유 한 줄, 버튼 두 개("성장 리포트", "빠른 성장 세션"). 축 상세, 작업 유형별 분해, 최근 결정 목록, 학습 현황, 면책 문구들은 전부 리포트로 간다. 리포트는 읽기 전용이므로 설정 불변식(평면 섹션)과 충돌하지 않는 자기 레이아웃을 갖는다.

### 3.3 기억 탭 — 결정 대기함이 먼저

위에서부터 이 순서다. 사용자 결정이 필요한 것 → 상태 한 줄 → 컨트롤 → 참조.

1. **결정 대기함** — 세 묶음. (a) 기억 제안(현행 최근 3건), (b) 스타일 제안 — `style/global/*`에는 "승인 필요" 배지(자동 확정이 금지된 유일한 항목이라는 사실을 배지가 담는다), (c) **대체 알림** — 최근 대체된 확정 기억 N건, "X → Y로 대체됨 · 되돌리기". 모두 비면 대기함 블록 자체가 사라진다.
2. **요약 한 줄** — 범위별 개수 + "마지막 회고 N시간 전". 자동 학습이 돌고 있다는 사실이 보인다.
3. **학습 방식** — 학습 토글 + 확증 자동 승격 토글을 한 묶음으로. 힌트가 네 경로(대화 중 제안=수동 / 확증 승격=자동 / 회고 4연산=자동·대체는 확정 조건부 / 스타일=유형별 자동·전역 수동)를 한 문장씩 설명한다.
4. **스타일** — 문체 지문(읽기 전용) + 확정된 `style/*` 항목으로 브라우저를 여는 딥링크.
5. **참조** — 브라우저 버튼, 일괄 삭제는 `SettingsDetails` 뒤로.

콜드스타트 카드(P15-07)는 유지하되 빠른 성장 세션과의 관계를 문구로 잇는다 — 카드가 남은 질문을 다 쓰면 "더 배우게 하려면 빠른 성장 세션"을 안내한다.

**배지** — 기억 탭 내비 항목에 대기 결정 수(제안 + 스타일 + 최근 대체 미확인)를 단다. 0이면 숨긴다. 배지 하나의 의미는 하나 — "당신의 결정을 기다리는 것"이다.

### 3.4 프로바이더/연결 분할

- 프로바이더 = 엔진 선택 + API 키. 온보딩 위저드는 그대로 둔다(설정 밖).
- 연결 = System MCP 프리셋 + 일반 MCP 목록 + 텔레그램. 컴포넌트는 그대로 옮긴다 — 동작 변경 없음.

### 3.5 필요한 API

- `memory.recentSupersessions` — 최근 대체 목록(옛 값·새 값·시각·되돌리기 대상 id). 개수만 있던 것을 목록으로.
- `memory.pendingCount` — 배지용 집계(제안 + 스타일 대기 + 미확인 대체). 기존 summary 액션 확장으로 충분하면 새 액션을 만들지 않는다.

## 4. 거절한 대안

- **설정 검색 추가** — VS Code·Apple은 검색을 좋은 그룹의 보완으로 쓴다. 8탭 규모에서는 그룹만으로 훑을 수 있으므로 넣지 않는다(항목이 더 자라면 재검토).
- **성장 패널 삭제·축약** — 정보 자체는 신뢰 지표의 투명성 요건이다(숫자와 단어가 같은 말을 해야 한다). 자리만 옮긴다.
- **3단계 내비게이션** — NN/g 기준 2단계 초과는 사용성이 떨어진다. 탭 → 오버레이(브라우저/리포트)까지가 끝이다.
- **탭 순서에 기억을 나비보다 앞에** — 정체성(나비)이 먼저, 그 산출물(기억)이 다음이 정보 냄새에 맞다.

## 6. 구현 상태

### ✅ IA-1 — 내비 재그룹 (2026-08-04)

`NAV_SECTIONS`가 8행이 된다 — 일반(테마+언어) · AI 프로바이더 · 연결 · 나비 · 기억(배지) · 하네스 · 권한 · 정보. 컴포넌트는 그대로 옮긴다. `NabyProviderSettings`에서 `<NabyMcpServers/>` 호출만 걷어내 연결 탭이 같은 컴포넌트를 마운트하고, 온보딩 위저드가 쓰는 `SystemMcpForm`·`SecurityBanner`는 손대지 않는다. 텔레그램은 나비 탭에서 연결 탭으로 간다.

- `settingsLayout.test.ts`의 `EXPECTED`를 갱신한다: `general:2 · provider:1 · connections:2 · agents:1 · memory:1 · harness:2 · permissions:1 · about:2`. 모든 변경이 **이동**이라 섹션 총합은 늘지 않는다(테마1+언어1+프로바이더1+나비3 = 일반2+프로바이더1+연결2+나비1+기억1).
- 타일 그리드 `grid grid-cols-3 gap-2 max-w-md`는 여전히 정확히 2개다(둘 다 일반 탭 안).
- `contentPane()`의 시작 지점을 `{section === 'general'`로 옮긴다.

### ✅ IA-2 — 성장 리포트 오버레이 (2026-08-04)

`GrowthReportModal.tsx`를 새로 만든다(`z-[100]`, ESC·배경 클릭 닫기, 자체 스크롤). 축 표, 암묵/훈련 축, 2차 지표, 작업 유형별, 최근 결정, 학습 블록, `howItMoves`와 그 `SettingsDetails`가 내용 그대로 옮겨간다. 에이전트 행에는 단계 사다리와 게이지(알 단계는 "N개 남음" 한 줄), 사유 한 줄(`border-l-2` 강조 유지), 버튼 두 개만 남는다. 기록은 `GrowthPanel`이 한 번만 읽어 리포트에 넘기므로 같은 원장을 두 번 묻지 않는다. 접기 버튼("Growth")은 사라진다 — 세 줄짜리 요약을 클릭 뒤에 숨길 이유가 없다.

- `settingsLayout.test.ts`에 리포트 불변식을 추가한다: 스택 층·닫기 경로·행에 남은 것과 옮겨간 것·열고 닫는 상태 배선. `growth-learning` 규칙은 약해지지 않고 **리포트 파일로 따라간다**.
- `growthCopy.test.ts`의 `SOURCES`에 리포트를 넣어 옮겨간 문구도 계속 두 로케일에서 검사한다. 카피 키는 그대로다.

### ✅ IA-3 — 결정 대기함 · 대체 알림 · 배지 (2026-08-04)

- **API** — `summarizeMemory`가 `recentSupersessions`(최근 5건, 옛 키·옛 값·새 값·시각·되돌리기 id), `pendingStyleProposals`(`isGlobal` 표시), `pendingCount`(제안+스타일+대체 알림), `lastReflectionAt`을 함께 답한다. 스타일 제안은 일반 제안 목록에서 빠져 자기 묶음으로 간다. 판정은 런타임의 `isStyleMemoryKey`·`isGlobalStyleMemoryKey`를 그대로 쓴다. 요청은 여전히 하나다.
- **런타임** — `ScopedMemoryQuery.keyPrefix` 하나만 늘린다(두 드라이버 모두). `search`는 키·값 부분일치라 `style/`을 언급한 기억까지 잡으므로 딥링크에는 쓸 수 없다. SQLite 쪽은 `GLOB`으로 앵커링해 `LIKE`의 A–Z 대소문자 무시와 `_` 와일드카드 문제를 피한다.
- **기억 탭** — 대기함(3묶음, 비면 블록 자체가 없음) → 요약 한 줄 + 마지막 회고 → 학습 방식(토글 2개 + 네 경로 한 문장씩) → 스타일(지문 + `style/*` 딥링크) → 참조(`SettingsDetails` 안에 일괄 삭제, 브라우저 버튼은 밖). 콜드스타트 카드는 남고, 빠른 성장 세션을 가리키는 한 문장이 붙는다.
- **배지** — 기억 내비 행에만 달리고 0이면 숨는다. 설정을 열 때 한 번 읽고, 그 뒤로는 패널이 자기 `pendingCount`를 콜백으로 돌려준다 — 폴링 경로를 새로 만들지 않는다.

### ✅ IA-3a — 배지가 스스로를 설명한다 (2026-08-04, 사용자 보고 후속)

배지는 숫자만 달고 나갔고, 사용자가 처음 물은 것이 **"'1'은 무슨 의미죠?"**였다. 명사 없는 숫자는 알림이 아니라 수수께끼다. 두 겹으로 고친다.

- **말해 준다** — `memoryReview.pendingBadgeTitle`이 `{{count}}`를 받아 `title`과 `aria-label` **양쪽**에 같은 문장으로 붙는다. 한 키에서 나오므로 툴팁과 스크린리더가 다른 말을 할 수 없다.
- **숫자가 겹친다(이쪽이 본체다)** — 대기함 제목이 `memoryReview.summaryPendingCount`로 바뀌어 **배지와 같은 `pendingCount`**를 싣는다. 목록 길이가 아니라 집계에서 읽는다 — 목록은 화면 크기 때문에 잘려 있어서, 배지가 12인데 제목이 3이면 맨숫자보다 나쁘다. 툴팁은 숫자를 설명하고, 두 화면에서 같은 숫자가 보이는 것이 그 설명을 믿게 만든다. 대기함이 비면 제목도 그대로 사라진다(기존 동작).

### ✅ IA-3b — 설정 한국어를 ~합니다체로 통일 (2026-08-04, 사용자 보고 후속)

사용자 보고: *"위에는 ~합니다 하다가 밑은 ~한다로 바뀜. 다른 설정 모두 ~합니다로 일관."* 기억 탭만 평서형으로 흘렀다.

원인은 규칙을 잘못 적용한 것이다. CLAUDE.md의 "~한다 평서형"은 **스펙 트리**(`specs/`, `ref-docs/specs/`) 규약인데 UI 문자열에도 적용됐다. 스펙은 계속 ~한다로 쓰고, **UI 카피는 ~합니다체**로 되돌린다. 2인칭도 같은 규약이다 — 이 제품의 한국어는 나/내로 말하고 당신을 쓰지 않는다.

`ko.json` 전수 검사로 평서형이 남은 문장은 정확히 `memoryReview.*` 24개와 `bootstrap.fastGrowth` 하나였고, 전부 바꿨다. `memoryBrowser.test.ts`의 옛 검사는 `/다\.$/`라 "쓴다."와 "씁니다."를 똑같이 통과시켜 이 드리프트를 잡지 못했다 — 어미(`니다`)를 보게 고치고, 두 키 표본이 아니라 **파일 전체**를 훑도록 넓혔다.

### ✅ IA-3c — 배지를 뗀다 (2026-08-04, 사용자 보고 후속)

IA-3a의 툴팁으로도 배지는 읽히지 않았다. 사용자는 기억 행의 "1"을 다시 물었고, 이번에는 이유가 하나 더 있었다 — **`title` 툴팁이 Electron에서 뜨지 않는다.** 숫자를 설명하는 유일한 표면이 이 앱이 실제로 도는 플랫폼에서 닿지 않는 곳에 있었다. 사용자가 요청한 대로 배지를 뗀다.

- **뗀 것** — `SettingsModal`의 배지 마크업, `title`/`aria-label` 배선, 배지만 먹이던 `pending` 상태와 요약 읽기, 그리고 두 로케일의 `memoryReview.pendingBadgeTitle` 키. 아무도 안 읽는 숫자를 위해 설정을 열 때마다 요청을 하나 더 보내지 않는다.
- **남긴 것** — 숫자 자체는 살아 있다. 기억 탭의 대기함 제목(`memoryReview.summaryPendingCount`, "확인할 것 {{count}}건")이 이제 **유일한 표면**이고, 원래부터 이쪽이 본체였다(IA-3a). 명사·목록·행동이 한 화면에 있으므로 툴팁이 필요 없다. `summarizeMemory`의 `pendingCount`와 패널의 요약 읽기는 그대로다.
- **검사** — `settingsLayout.test.ts`의 배지 불변식 묶음을 **삭제가 아니라 교체**한다. 배지가 다시 생기는 것(마크업·testid·`pending > 0` 조건·툴팁 키·모달의 자체 읽기)과 대기함 제목이 조용히 사라지는 것, 양쪽 모두 실패로 잡는다. 죽은 단언은 남기지 않는다.

**여기서 배운 것 하나.** 툴팁으로 설명을 붙이는 수리는 데스크톱 셸에서 검증되지 않는다. jsdom에도 소스 단언에도 "이 title이 실제로 뜨는가"는 보이지 않으므로, 다음부터 설명이 필요한 UI는 상시 노출 문구로 만든다 — 빠른 성장 버튼이 §3.3a에서 이미 같은 결론에 도달했다.
