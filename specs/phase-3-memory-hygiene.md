# Phase 3 P3-M10 — 기억 위생과 주권

> 상태: 설계 확정(2026-08-03). 한 줄 요약: 오래 안 쓰인 기억은 뒤로 물러나고(감쇠), 사용자는 기억을 직접 고치고 끄고 잠글 수 있으며(주권), 늘어난 기억은 전용 브라우저에서 다룬다(UI).

## 1. 근거

- **감쇠는 기능이다** — 연구(FSFM·FadeMem·Oblivion)는 망각을 청소가 아니라 신호대잡음 개선으로 본다. 낡은 고관련 사실이 에이전트를 "자신 있게 틀리게" 만든다. Anthropic 공식 문서도 장기 미접근 기억의 주기 정리를 명시한다.
- **주권은 3사 공통 기준선이다** — ChatGPT·Claude·Gemini 모두 항목 열람/삭제 + 전체 끄기 + 비학습 모드를 제공한다. naby는 열람/확인/삭제만 있고 편집·끄기·임시 모드가 없다.
- **UI는 무한 스크롤로 자랄 구조다**(사용자 지적) — 설정 섹션 안 인라인 목록이라 기억이 늘수록 설정 전체가 늘어난다. 주권 컨트롤(편집·검색)을 담을 전용 화면이 어차피 필요하다.

## 2. 감쇠 (G5)

### 2.1 접근 기록

- `memory_items`에 `last_injected_at`(epoch ms, NULL 허용) 컬럼을 추가한다(스키마 v9→v10). **주입 선택이 곧 접근이다** — `retrieveForInjection`이 고른 항목의 id를 턴 시작 시 배치로 찍는다(이미 주입 로그 계약이 있으므로 그 지점에 한 줄).
- 확인(confirm)·편집도 접근으로 찍는다(사람이 봤다는 신호).

### 2.2 감쇠 규칙 (결정론, 모델 호출 없음)

- 주입 랭킹에서 **신선도 페널티**: `last_injected_at`(없으면 `updatedAt`)이 `MEMORY_STALE_MS`(기본 30일)보다 오래면 관련도 동점 비교에서 뒤로 물러난다. 관련도 자체를 깎지 않는다 — 질의와 강하게 맞는 낡은 기억은 여전히 이긴다(관련도 > 신선도). M8c의 "동점은 기존 순서" 규칙에 신선도 단계를 하나 끼우는 가산 변경이다.
- `MEMORY_DECAY_REVIEW_MS`(기본 90일) 초과 미접근 confirmed 항목은 회고 스윕 끝의 통합 단계가 **검토 큐로 표시**한다(`status`는 그대로, 새 플래그가 아니라 `last_injected_at` 기준 파생 — 저장 상태를 늘리지 않는다). 브라우저의 "오래됨" 필터가 이것을 보여주고, 사용자가 지우거나 "계속 유지"(접근 갱신)를 고른다. **자동 삭제는 하지 않는다** — 삭제는 언제나 사람이 한다.

## 3. 주권 컨트롤 (G6)

- **항목 편집** — 브라우저에서 value를 직접 수정한다. 편집은 `provenance.source`를 `user`로 승격하고(사용자가 직접 말한 것과 동급이 된다) 확증 관측을 리셋한다(값이 바뀌었으므로 — M8b 규칙 그대로).
- **학습 끄기** — 설정 `memory.learningEnabled`(기본 켬). 끄면 `naby_remember` 도구·학습 지침·회고의 기억 제안이 모두 빠진다(주입은 유지 — 이미 배운 것은 계속 쓴다. "새로 배우지 마"이지 "잊어라"가 아니다).
- **임시 세션(비학습)** — 세션 단위 토글. 켜진 세션에서는 기억 캡처·회고 제안·확증 관측이 생기지 않고, 회고 스윕이 그 세션을 건너뛴다. 세션 행에 `no_learn` 플래그(v10에 동승). 탭 UI에 작은 표시.

## 4. 기억 브라우저 (UI 재구조)

- 설정>에이전트의 기억 섹션은 **요약 카드로 축소**한다: 스코프별 확정/대기 수 + 최근 `proposed` 3건(확인/삭제 인라인) + "전체 보기" 버튼.
- "전체 보기"가 **전용 전체 높이 모달**(설정 모달과 같은 계층, 그 위)을 연다: 검색(키/값 부분 일치), 필터(스코프·타입·상태·"오래됨"), 페이지네이션(50개 단위, 스토어에 limit/offset 읽기 추가 — 가산), 항목 행에서 확인/편집/삭제/출처 보기.
- 목록 API는 페이지 파라미터를 받는다(기존 호출은 무변경 기본값).

## 5. 검증 계획

- 스파이크 — v10 마이그레이션(양 드라이버), 주입 시 접근 기록, 신선도 동점 강등(관련도 우선 불변), 90일 파생 필터, 편집의 user 승격+확증 리셋, no_learn 세션에서 캡처·회고·관측 부재, learningEnabled 끔 상태의 도구·지침 부재(spike:learn 확장).
- 셸 — 요약 카드·브라우저(검색/필터/페이지) 액션, 임시 세션 토글 배선, 회귀 전체.
- 미검증 — 감쇠 상수(30/90일)의 적정성(실사용 조정), 브라우저 시각 렌더.

## 6. 미결정

- 감쇠 상수 기본값(30일 신선도·90일 검토)의 조정. 실사용 분포를 보고 정한다.
- 오래됨 검토를 회고 텔레그램 리포트에 실을지(지금은 브라우저 필터만).
- 세션 no_learn과 성장 원장(eval_events)의 관계 — 1차는 원장 기록도 함께 끈다(관측 없는 세션). 신뢰 지표 표본이 줄어드는 대가를 §5에서 계측하지 않는다.

## 7. 구현 상태

구현 완료(0.2.0). §2–§4를 모두 반영했고 §5의 검증 계획을 스파이크와 셸 테스트로 실행했다.

### 7.1 스키마 v10

`SCHEMA_VERSION`을 9에서 10으로 올리고 **컬럼 두 개만** 더한다. 테이블은 늘리지 않는다.

- `memory_items.last_injected_at` (INTEGER, NULL 허용) — 마지막 사용 시각이다. NULL은 "쓰인 적 없음"을 뜻한다.
- `sessions.no_learn` (INTEGER, DEFAULT 0) — 임시 세션 플래그다.

두 컬럼 모두 **버전이 아니라 컬럼 존재 여부로 게이트한다.** `ALTER TABLE ADD COLUMN`에는 `IF NOT EXISTS`가 없어서 두 번 실행하면 던진다. 버전으로 막으면 마이그레이션이 한 번이라도 중간에 끊긴 DB는 이후 모든 열기가 실패한다. 컬럼으로 막으면 스스로 복구한다.

`memory_items_by_access` 인덱스는 DDL이 아니라 `migrate()` 안에서 만든다. DDL은 하나의 배치로 실행되는데, 업그레이드 중인 DB에서는 컬럼이 생기기 전에 DDL이 먼저 돌아 인덱스 생성이 던지고 그 뒤 문장이 전부 날아간다.

**백필은 하지 않는다.** 기존 행의 사용 이력은 애초에 기록된 적이 없다. 없는 이력을 지어내는 대신 `memoryLastAccessAt`이 `updatedAt`으로 되돌아간다 — 그래서 업그레이드 당일에 사용자의 기억 전체가 오래된 것으로 바뀌지 않는다.

### 7.2 감쇠 (§2)

- **접근 기록** — `runTurn`의 주입 지점에서 `markMemoriesInjected`를 한 줄 호출한다(`src/runtime/session.ts`). **선택이 곧 접근**이라는 규칙이 코드베이스에서 이 한 곳에만 있다. 주입할 것이 없는 턴은 스토어에 아무것도 쓰지 않는다 — 계약 §5의 no-op 불변식을 프롬프트뿐 아니라 쓰기까지 확장한다. 확인(`confirmMemory`)과 편집(`updateMemoryValue`)도 같은 컬럼을 찍는다.
- **신선도 단계** — `rankCandidates`의 비교 사슬이 관련도 → **신선도** → 스코프 → 타입 → 최신순이 된다(`src/runtime/memory-inject.ts`). 신선도는 **두 번째**이지 첫 번째가 아니다. 오래됐지만 질의에 맞는 기억은 여전히 이긴다. 연속 감쇠 곡선이 아니라 **불리언 단계**로 둔 이유는, 곡선이면 누적된 나이가 어딘가에서 관련도 차이를 이길 수 있고 그 "어딘가"는 아무도 검증할 수 없기 때문이다. 단계는 구조적으로 그럴 수 없다.
- **검토 큐** — `listStaleConfirmedMemory(before)`가 스코프를 가로질러 확정·미사용 행을 읽는다. 저장 상태를 늘리지 않고 매번 `COALESCE(last_injected_at, updated_at)`으로 **파생한다.** 회고 스윕의 통합 단계가 개수를 세어 `staleForReview`로 보고하고 로그를 남긴다. **아무것도 지우지 않는다.**

### 7.3 주권 컨트롤 (§3)

세 가지가 하나의 술어 `canCaptureMemory({learningEnabled, sessionNoLearn})`로 모인다(`src/runtime/memory-hygiene.ts`). 판정을 한 곳에 두는 이유는 도구는 있는데 지침이 없거나 그 반대인 상태 — 스킬 주입이 이미 거부하는 "조용한 반쪽 실행" — 를 구조적으로 막기 위해서다.

- **항목 편집** — `updateMemoryValue(id, value)`가 값을 쓰고, `provenance.source`를 `user`로 올리고, **값이 실질적으로 바뀐 경우에만** 확증 관측을 지운다. 이 판단은 M8b의 `sameMemoryValue`를 그대로 쓴다(공백만 고친 것은 같은 주장이다). `status`는 건드리지 않는다 — 제안의 문구를 다듬는 것은 그 제안에 동의한 것이 아니다.
- **학습 끄기** — 설정 `memory.learningEnabled`(기본 켬). 끄면 `naby_remember`가 **도구 목록에서 사라지고**(거부가 아니라 부재다 — 보이는데 항상 실패하는 도구는 앱이 고장 난 것처럼 읽힌다), 학습 지침이 빠지고, 회고의 기억 제안이 멈춘다. 회고의 **교정은 계속 돈다.** 교정은 사용자에 대한 지속적 사실이 아니라 에이전트가 틀렸다는 통보이고, 이것까지 끄면 신뢰 지표가 눈을 잃는다.
- **임시 세션** — 탭 컨텍스트 메뉴의 "학습 제외"가 `sessions.no_learn`을 켠다. 그 세션은 기억 도구·학습 지침·체크인 도구·성장 관측을 모두 잃고, 회고 스윕이 **전사를 읽기도 전에 건너뛴다.** 커서를 전진시키지 않으므로 나중에 플래그를 해제하면 밀린 분량이 그대로 남아 있다. 스윕 상한도 소비하지 않는다.

**두 스위치 모두 주입은 건드리지 않는다.** "새로 배우지 마"는 "잊어라"가 아니다(§3). 이미 확정된 기억은 두 스위치가 다 꺼져 있어도 계속 턴을 만든다.

### 7.4 기억 브라우저 (§4)

- **요약 카드** — `NabyMemoryReview.tsx`가 스코프별 개수(확정/대기/미사용) + 최근 `proposed` 3건(인라인 확인·삭제) + "전체 보기" + 두 스위치 + 출처 기반 일괄 삭제로 줄었다. 기억이 얼마나 늘어도 **크기가 변하지 않는다** — §1이 지적한 문제가 바로 그것이었다.
- **전용 모달** — 새 `MemoryBrowserModal.tsx`가 설정 모달(`z-50`) 위, 컨텍스트 메뉴·토스트 층(`z-[200]`) 아래인 `z-[100]`에 뜬다. 검색(디바운스), 필터 칩(스코프·상태·타입·오래됨), 50개 페이지네이션, 행별 확인·편집(인라인 textarea)·계속 유지·삭제·출처 표시를 담는다.
- **필터는 전부 서버가 건다.** 페이지에 올라온 50행만 걸러 봐야 소용이 없고, "오래됨"은 클라이언트가 계산할 수 없는 파생값이다.
- **스토어 읽기는 가산이다.** `getScopedMemory`의 `opts`에 `type`/`search`/`staleBefore`/`limit`/`offset`을 더했다. 전부 선택이고, 전부 생략하면 Phase 1.5의 그 읽기 그대로다 — 기존 호출부는 한 곳도 바뀌지 않았다. 총 개수는 같은 술어를 쓰는 `countScopedMemory`가 답한다(목록과 총계가 서로 다른 조건을 볼 수 없게 한다).
- **검색은 ASCII만 대소문자를 접는다.** SQLite `LIKE`의 기본 동작이 A–Z까지이고 자바스크립트 `toLowerCase()`는 유니코드 전체다. 각자 자연스러운 철자를 쓰면 한 드라이버에서만 맞는 검색이 생긴다. 그래서 양쪽 다 `memoryMatchesSearch`의 규칙을 따른다. 검색어의 `%`·`_`는 이스케이프한다.

### 7.5 검증 결과

- **`npm run spike:hygiene`** (신규, 33/33) — v9→v10 무손실 마이그레이션(실제 파일), 재열기 no-op, 컬럼이 빠진 v10 DB의 자가 복구, 주입의 접근 기록과 빈 주입의 무기록, 확인·편집의 접근 기록, 편집의 user 승격과 확증 리셋(공백 변경은 보존), 세 갈래 stale 파생의 일치, 페이지네이션·검색·타입 필터의 양 드라이버 동일성, 무필터 읽기의 무변경, 두 스위치의 왕복과 주입 무영향.
- **`npm run spike:rank`** (13→17) — 신선도 단계가 관련도 동점을 가르고(최신순이 반대로 말했을 때에도), **오래된 관련 기억이 신선한 무관 기억을 여전히 이기며**, 균일하게 신선하거나 균일하게 오래된 집단은 M10 이전과 바이트 단위로 같은 순서를 낸다. 토큰 상한도 그대로다.
- **`npm run spike:learn`** (10→14) — `learningEnabled=false`가 도구와 지침을 함께 없애고 아무것도 쓰지 않으면서 확정 기억은 계속 주입한다. 임시 세션은 `naby_remember`와 `naby_checkin`을 둘 다 잃고 원장 행을 남기지 않으며, 플래그는 다음 턴으로 새지 않는다.
- **`npm run spike:reflection`** (49→61) — 임시 세션은 판정에 올라가지도 커서가 움직이지도 않고, 플래그를 해제하면 밀린 분량이 그대로 돌아온다. 학습 끔 상태에서 교정은 돌고 제안은 0이며 "거부됨"으로 집계되지 않는다. stale 검토는 세고 보고할 뿐 아무것도 바꾸지 않는다.
- **셸 테스트 1163 → 1273** (69파일, 전부 통과). 신규: `memoryBrowser.test.ts`(74) — 순수 `buildMemoryQuery`의 칩→파라미터 사상, z-index 적층, 서버측 필터링, 카드가 목록을 렌더하지 않음, 탭 토글 배선, 양 로케일 문구. 확장: `memory.test.ts`(38), `naby.test.ts`(45), `reflection.test.ts`(56).
- **타입체크** 두 트리 모두 기준선 유지(루트 29 / 셸 4, 모두 기존 항목). **`npm run build:app` 성공.**

### 7.6 이번 작업에서 고친 것

회귀 검증 중에 드러난 실제 결함 하나를 함께 고쳤다. 스윕 맨 앞에서 학습 설정을 읽는 코드가 스토어가 던지는 경우를 막지 않아, "스윕은 절대 던지지 않는다"는 이 파일의 가장 오래된 약속을 깼다. 이제 감싸고, **읽기 실패는 "학습하지 않음"으로 떨어진다** — `readLearningEnabled`의 기본값(켬)과 반대 방향인데, 둘은 다른 질문에 답하기 때문이다. 그 함수는 *값이* 비었을 때를 정하고, 여기는 *스토어를 물어볼 수 없었던* 경우다. 사용자가 학습을 껐는지 모르는 상태에서 지속적 기억을 쓰는 것은 주권 스위치가 해서는 안 되는 유일한 실수다. 잃는 것도 없다 — 커서가 전진하지 않은 세션은 다음 스윕에서 그대로 읽힌다.

### 7.7 미검증으로 남은 것

- **감쇠 상수(30일·90일)의 적정성.** §6이 미결정으로 둔 그대로다. 실사용 분포를 보고 정한다. 틀려도 대가가 작도록 설계했다 — 30일은 동점 순서만, 90일은 필터 하나만 움직인다.
- **브라우저 모달의 시각 렌더.** jsdom에는 레이아웃 엔진이 없어서 소스 단언으로 대신했다(설정 레이아웃 테스트와 같은 방식이다). 실제 그려지는 모습은 사람이 봐야 한다.
- **대용량 기억에서의 페이지네이션 성능.** 인덱스는 넣었지만 수만 행 규모로 측정하지 않았다.
