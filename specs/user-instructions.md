# 모든 세션에 적용할 지침

## 1. 왜 필요한가

사용자는 세션마다 같은 말을 반복한다. "한국어로 답해 줘", "명령은 실행 전에 보여 줘" 같은 규칙이다. 지금까지는 이를 기억에 맡겼지만 두 가지가 맞지 않는다.

- 기억은 관련도로 골라 넣는다. 첫 턴에 반드시 들어간다는 보장이 없다.
- 기억은 단기·장기 단계를 오가고, 기억 작업 세션이 합치거나 고쳐 쓸 수 있다([단기·장기·고정 기억](memory-tiers.md)). 규칙은 사용자 말고는 아무도 바꾸면 안 된다.

`~/.claude/CLAUDE.md`도 쓸 수 없다. naby는 Agent SDK를 `settingSources: []`로 돌리고(engine-env.ts), ai-sdk 엔진은 그런 파일을 읽지 않는다. 그래서 설정값 하나로 둔다. 모든 엔진에 같은 길로 들어간다.

## 2. 저장

- 설정 키 `instructions.global`에 문자열 하나로 저장한다. 스키마는 바꾸지 않는다.
- 저장할 때 앞뒤 공백을 지우고 줄바꿈을 `\n`으로 맞춘다. 비어 있으면 "지침 없음"이다.
- 상한은 8,000자다(`USER_INSTRUCTIONS_MAX_CHARS`). 매 턴 붙는 글이라 매 턴 비용이 든다. 넘으면 **잘라 저장하지 않고 거절한다.** 잘린 규칙이 저장된 것처럼 보이면 안 되기 때문이다. 거절하면 기존 값을 그대로 둔다.
- 런타임 모듈은 `src/runtime/user-instructions.ts`다. 읽기 `readUserInstructions`, 쓰기 `writeUserInstructions`, 블록 생성 `userInstructionsBlock`.

## 3. 턴에 넣는 방식

- 셸 엔진 어댑터(`engines/naby.ts`)가 **매 턴 새로 읽는다.** 설정에서 저장하면 어느 프로젝트든 다음 메시지부터 적용된다.
- 시스템 프롬프트 블록 목록의 **맨 끝**, 스타일 줄 뒤에 둔다. 사용자가 직접 적은 규칙이 나비가 학습한 말투와 기본값을 이긴다.
- 블록 머리에 두 가지를 적는다. 사용자가 설정에서 적은 것이라는 점, 그리고 안전 규칙·권한 게이트·꺼 둔 스위치를 풀지 못한다는 점이다. 권한은 게이트가 코드에서 막으므로 실제로 풀리지 않는다. 모델이 "왜 아직 묻는지"를 설명하게 하려고 적는다.
- 기본 페르소나와 전문 에이전트 턴 모두에 넣는다. 둘 다 같은 사용자를 위해 일한다. 라운드의 나비 발언도 같은 시스템 프롬프트에서 시작하므로 함께 받는다.
- 다른 엔진에서 도는 참가자 에이전트, 백그라운드 기억 작업, 요약 호출에는 넣지 않는다. 참가자는 자기 지시문을 가진 별개 인물이고, 기억 작업은 사용자에게 답하는 턴이 아니다.

## 4. API와 설정 화면

- `instructions.get` → `{ instructions, instructionsMaxChars }`.
- `instructions.set { text }` → 저장한 값을 돌려준다. 문자열이 아니거나 상한을 넘으면 `ok: false`.
- 설정 → 나비 탭 맨 위에 "모든 세션에 적용할 지침" 섹션을 둔다. 입력 칸, 글자 수, 비우기, 저장 버튼이 있다. 상한을 넘으면 글자 수가 빨갛게 바뀌고 저장 버튼이 꺼진다. 저장하지 않은 변경이 있으면 표시한다.

## 5. 검증

- `shell/.../api/userInstructionsApi.test.ts`: 저장·정규화·읽기, 상한 초과 거절과 기존 값 유지, 문자열 아님 거절, 빈 값으로 비우기, 블록 문구, 엔진이 매 턴 읽고 맨 끝에 두는지(소스 검사).
- `settingsLayout.test.ts`: 나비 탭 섹션 수 2.

## 6. 남은 일

- 프로젝트별 지침(프로젝트 폴더의 파일이나 프로젝트 설정)은 이 문서 범위 밖이다. 필요해지면 같은 블록 옆에 프로젝트 블록을 두는 방식으로 넓힌다.
